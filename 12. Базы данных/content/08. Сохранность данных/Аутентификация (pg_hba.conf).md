# Аутентификация (pg_hba.conf)
> [!abstract] Четыре понятия безопасности [01:41:34](https://www.youtube.com/watch?v=ocmHxM52CLo&t=6094s)
> - **[[Аутентификация и сессии|Аутентификация]]** — *кто ты*. "Я Иванов" — и доказал это паролем
> - **[[Аутентификация и сессии|Авторизация]]** — *что тебе можно*. Иванову разрешены такие-то действия
> - **Контроль доступа** — *что видно и изменяемо* в данных
> - **Привилегии** — конкретные объектные и глобальные [[Роли и привилегии\|права]]

Аутентификацию — то, **как** клиент доказывает, кто он, — задаёт файл **pg_hba.conf** (host-based authentication)

## Строка правила
Правила читаются сверху вниз, срабатывает первое подходящее [01:43:20](https://www.youtube.com/watch?v=ocmHxM52CLo&t=6200s)
```
# тип    база      пользователь   адрес/маска     метод
local    all       all                            peer
host     movielens app            10.0.0.0/24     md5
```
- **тип** — `local` ([[Порты и сокеты#Сокет [1 11 49](https //www.youtube.com/watch?v=HxGsA6Ps-T8&t=4309s)|сокет]]), `host` ([[Заголовок TCP и установление соединения|TCP]]), `hostssl` / `hostnossl` (с шифрованием и без);
- **база**, **пользователь**, **адрес/маска** — к кому правило применяется;
- **метод** — как проверять, плюс опции

## Методы аутентификации [01:46:16](https://www.youtube.com/watch?v=ocmHxM52CLo&t=6376s)
| Метод | Как проверяет |
|---|---|
| **trust** | пускает безусловно — без пароля |
| **reject** | безусловный отказ |
| **md5**, **password** | по паролю (md5 — хешированный, password — открытым текстом) |
| **peer** | по имени пользователя операционной системы |
| **gss**, **sspi** | единый вход (Kerberos, Windows-домен) |
| **ldap**, **radius** | проверку делегируют внешнему сервису |

> [!note] Сервер либо проверяет сам, либо делегирует
> С `trust`/`md5`/`peer` PostgreSQL аутентифицирует **самостоятельно**; с `ldap`/`radius`/`gss` — отдаёт проверку **наружу**, на внешний сервис

> [!example]- Единый вход (SSO) [01:49:43](https://www.youtube.com/watch?v=ocmHxM52CLo&t=6583s)
> При **SSO** пользователь логинится один раз на доверенном сервисе, а тот выдаёт другим системам подтверждение "это правда он" — повторно вводить пароль не нужно. Характерный пример — вход через корпоративный домен (Kerberos): база доверяет билету, выданному доменом, и пароль у неё не спрашивает

> [!tip] pg_ident.conf — мост между пользователями [[Операционная система|ОС]] и базы
> При входе по имени системного пользователя (`peer`, `gss`) **pg_ident.conf** сопоставляет системного пользователя имени роли в базе: например, ОС-пользователь `deploy` ходит в базу как роль `app`
