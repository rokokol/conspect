# Роли и привилегии
В PostgreSQL и пользователи, и группы — это **роли**. Разница одна: **роль с правом `LOGIN` — пользователь, без него — группа** [01:58:04](https://www.youtube.com/watch?v=ocmHxM52CLo&t=7084s)

```sql
CREATE ROLE app WITH LOGIN PASSWORD 'secret';   -- пользователь
CREATE ROLE readers;                            -- группа (NOLOGIN по умолчанию)
DROP ROLE app;
SELECT rolname FROM pg_roles;                    -- список ролей
```

## Параметры роли
> [!abstract] Что роли можно по умолчанию
> Каждый флаг имеет отрицание (`NOSUPERUSER`, `NOCREATEDB`, …):
> - **SUPERUSER** — обходит все проверки прав; по умолчанию есть только у роли `postgres`
> - **CREATEDB** / **CREATEROLE** — право создавать базы / другие роли (по умолчанию запрещено)
> - **LOGIN** — может подключаться; новая роль по умолчанию **не может** залогиниться
> - **INHERIT** — автоматически получает права групп, в которые входит
> - **REPLICATION** — может подключаться как [[Назначение и схемы репликации\|реплика]]
> - **CONNECTION LIMIT** — потолок одновременных подключений для этой роли

## Наследование прав
> [!note] INHERIT против SET ROLE [02:01:00](https://www.youtube.com/watch?v=ocmHxM52CLo&t=7260s)
> Войдя в группу, роль либо **наследует** её права автоматически (`INHERIT`), либо нет (`NOINHERIT`) — и тогда переключается в них руками:
> ```sql
> GRANT admin TO joe;   -- joe — член группы admin
> SET ROLE admin;       -- joe временно действует с правами admin
> RESET ROLE;           -- вернуться к себе
> ```
> С `NOINHERIT` роль `joe` по умолчанию пользуется только **своими** правами и явно переключается в `admin`, когда они нужны — права группы не "протекают" в обычную работу

## Раздача прав на объекты [02:03:50](https://www.youtube.com/watch?v=ocmHxM52CLo&t=7430s)
> [!important] Политика по умолчанию: что явно не разрешено — запрещено
> Доступ выдают командой `GRANT` (действие на ресурс кому):
> ```sql
> GRANT SELECT, UPDATE ON films TO admin;        -- права на таблицу
> GRANT SELECT (title) ON films TO readers;       -- права на отдельный столбец
> GRANT CREATE ON DATABASE mydb TO admin;         -- глобальное право
> GRANT SELECT ON films TO PUBLIC;                -- всем, кто авторизован
> ```
> Минимум прав — принцип, который аукнется в [[SQL-инъекции\|инъекциях]]: чем меньше может пользователь приложения, тем меньше натворит атакующий через его соединение
