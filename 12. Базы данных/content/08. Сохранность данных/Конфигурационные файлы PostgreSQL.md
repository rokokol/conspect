# Конфигурационные файлы PostgreSQL
Поведение сервера задаётся тремя файлами [38:15](https://www.youtube.com/watch?v=ocmHxM52CLo&t=2295s)

| Файл | За что отвечает |
|---|---|
| **postgresql.conf** | основные параметры сервера: память, журналирование, сеть |
| **pg_hba.conf** | кто и как может подключиться — правила [[Аутентификация (pg_hba.conf)\|аутентификации]] |
| **pg_ident.conf** | сопоставление пользователей [[Операционная система\|ОС]] пользователям базы |

## Структура через include_dir
> [!tip] Раскладывать настройки по conf.d, а не править один большой файл
> В `postgresql.conf` оставляют строку
> ```
> include_dir = 'conf.d'
> ```
> и каждую группу параметров кладут отдельным файлом в каталог `conf.d`. Так конфиг проще читать, держать в системе контроля версий и раскатывать: один файл — одна тема, без слияния правок в общую простыню

## Сетевые подключения
```
listen_addresses = '*'     -- с каких адресов принимать соединения ('*' = со всех)
max_connections = 100      -- предел одновременных подключений
```
> [!warning] `max_connections` упирается в память
> Каждое подключение тратит свою долю [[Настройка памяти PostgreSQL\|оперативной памяти]] (буферы сортировок и хешей). Поэтому потолок соединений выставляют не "с запасом побольше", а исходя из того, сколько памяти сервер реально может отдать под запросы — иначе при наплыве клиентов база уйдёт в своп
