# SQL-инъекции
**[[Определение данных (DDL)|SQL]]-инъекция** — атака, при которой данные от пользователя, склеенные со строкой запроса, меняют сам запрос. Лечится одним правилом: **никогда не подставлять пользовательский ввод конкатенацией** [02:04:38](https://www.youtube.com/watch?v=ocmHxM52CLo&t=7478s)
![[SQL-инъекция.png]]

## Корень проблемы: конкатенация вместо плейсхолдеров
> [!danger] Параметры передают отдельно от текста запроса
> Правильно — оставить в запросе **плейсхолдер**, а значение передать параметром; сервер сам экранирует его и не даст вмешаться в синтаксис:
> ```sql
> SELECT * FROM users WHERE login = $1   -- $1 передаётся отдельно
> ```
> Лениво и опасно — вклеить значение прямо в строку:
> ```python
> "SELECT * FROM users WHERE login = '" + login + "'"   # так нельзя никогда
> ```
> Конкатенация плоха **дважды**: ломается кеш планов (каждый запрос уникален и [[Оптимизатор запросов\|планируется заново]]) и открывает дорогу инъекции

## Как живёт инъекция
> [!example] Обход проверки пароля
> Запрос авторизации:
> ```sql
> SELECT * FROM users WHERE login = 'Admin' AND pass = '...'
> ```
> Подставив в логин `Admin' --`, атакующий закрывает кавычку и **комментирует** хвостом `--` всё остальное:
> ```sql
> SELECT * FROM users WHERE login = 'Admin' --' AND pass = '...'
> ```
> Проверка пароля исчезла — вход выполнен под `Admin`

> [!example]- Разведка через UNION и хитрость с ORDER BY [02:09:58](https://www.youtube.com/watch?v=ocmHxM52CLo&t=7798s)
> `UNION` подклеивает **свой** результат к чужому запросу, но требует совпадения числа столбцов. Чтобы его узнать, не перебирают `UNION`-ом — берут `ORDER BY N`: сортировка по номеру несуществующего столбца даёт ошибку, и **делением пополам** число полей находят за пару попыток:
> ```sql
> ' ORDER BY 4 --      -- есть 4-й столбец → ок, иначе ошибка
> ' UNION SELECT table_name, NULL FROM information_schema.tables --
> ```
> Дальше через `information_schema` вытягивают список таблиц и колонок — всё, до чего дотягивается текущий пользователь

> [!warning]- Эскалация: файлы, DoS, команды [[Операционная система|ОС]] [02:11:13](https://www.youtube.com/watch?v=ocmHxM52CLo&t=7873s)
> - **Чужие данные** — под привилегированной ролью читают [[Физические резервные копии (pg_basebackup и снапшоты)\|файлы кластера]] напрямую (PostgreSQL по умолчанию не пускает за пределы своего каталога — и то спасает);
> - **[[SYN flood и защита соединения|Отказ в обслуживании]]** — `pg_sleep()` в запросе: при лимите в 100 соединений сотня "вечных" запросов выедает весь пул, база жива, но никто не подключается;
> - **Команды ОС** — если язык (**PHP** — PHP: Hypertext Preprocessor, + mysqli) позволяет несколько выражений через `;`, или через `COPY ... FROM PROGRAM`, читают `/etc/passwd` и выполняют любую shell-команду **с правами процесса сервера**. Тогда сервер скомпрометирован целиком

## Защита
> [!success] Параметры, минимум прав, изоляция
> - **параметризованные запросы** (prepared statements) — всегда; никакой конкатенации пользовательского ввода;
> - **минимальные [[Роли и привилегии\|права]]** у пользователя приложения — только чтение, если приложению нужно лишь читать; никаких суперюзеров;
> - **изоляция** — сервер под отдельным пользователем ОС, при возможности под SELinux, чтобы при пробое он не дотянулся за пределы своего каталога
