# Триггеры
**Триггер** — функция, которую [[Реляционная модель данных|СУБД]] вызывает **автоматически** при изменении данных в таблице (`INSERT`/`UPDATE`/`DELETE`/`TRUNCATE`). Это императивная альтернатива декларативным [[Целостность и ограничения|ограничениям целостности]]: то, что нельзя выразить `CHECK`/`FOREIGN KEY`, навешивают триггером

```sql
CREATE TRIGGER emp_audit
  AFTER INSERT OR UPDATE OR DELETE ON emp
  FOR EACH ROW EXECUTE PROCEDURE process_emp_audit();
```

## Когда и на что срабатывает [1:21:47](https://www.youtube.com/watch?v=XkS3937Xn8M&t=4907s)
Триггер задаётся тремя осями: **момент** × **событие** × **гранулярность**

> [!abstract] Момент срабатывания
> - **`BEFORE`** — до операции: можно проверить или **подменить** записываемую строку, отменить операцию;
> - **`AFTER`** — после операции: строка уже записана, удобно для аудита и каскадных действий;
> - **`INSTEAD OF`** — вместо операции: главным образом чтобы делать [[Представления (VIEW)|представления]] обновляемыми

> [!abstract] Гранулярность
> - **`FOR EACH ROW`** — вызывается на **каждую** затронутую строку: удалили 100 строк — триггер сработал 100 раз;
> - **`FOR EACH STATEMENT`** — **один раз** на всю команду, независимо от числа строк

## Доступ к данным строки
Внутри триггерной функции доступны специальные переменные:

| Переменная | Что содержит |
|---|---|
| `NEW` | новая строка (для `INSERT`/`UPDATE`) |
| `OLD` | старая строка (для `UPDATE`/`DELETE`) |
| `TG_OP` | вид операции: `INSERT` / `UPDATE` / `DELETE` |
| `TG_TABLE_NAME`, `TG_NAME` | имя таблицы и самого триггера |

> [!example] Аудит изменений таблицы
> Один триггер `AFTER` логирует все правки в журнальную таблицу, различая операцию по `TG_OP`:
> ```sql
> CREATE OR REPLACE FUNCTION process_emp_audit()
>   RETURNS TRIGGER AS $$
> BEGIN
>   IF (TG_OP = 'DELETE') THEN
>     INSERT INTO emp_audit SELECT 'D', now(), user, OLD.*;
>     RETURN OLD;
>   ELSIF (TG_OP = 'UPDATE') THEN
>     INSERT INTO emp_audit SELECT 'U', now(), user, NEW.*;
>     RETURN NEW;
>   ELSIF (TG_OP = 'INSERT') THEN
>     INSERT INTO emp_audit SELECT 'I', now(), user, NEW.*;
>     RETURN NEW;
>   END IF;
>   RETURN NULL;
> END;
> $$ LANGUAGE plpgsql;
> ```

## За и против
Триггеры держат целостность и бизнес-логику прямо в [[Реляционная модель данных|БД]] и удобны для аудита — но платят неявностью:

> [!warning] Цена триггеров
> - **сложность отладки** — выполнение **неявное**, по коду приложения не видно, что правка строки запустила цепочку действий;
> - **производительность** — каждая операция тянет за собой лишнюю работу;
> - **взаимодействие триггеров** — один триггер меняет таблицу, на которой висит другой, и поведение становится трудно предсказуемым
