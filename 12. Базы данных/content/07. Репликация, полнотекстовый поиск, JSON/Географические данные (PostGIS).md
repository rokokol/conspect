# Географические данные (PostGIS)
Хранить координаты в обычных столбцах и фильтровать по ним неудобно: выборка идёт по нескольким полям, а географические координаты плохо приспособлены для расчётов — расстояние по ним вручную не посчитать. **PostGIS** — штатное расширение для геоданных с правильными типами, функциями и индексами

## Подключение [1:21:02](https://www.youtube.com/watch?v=HYg6O_YaFEk&t=4862s)
PostGIS ставится отдельно (в составе дистрибутива PostgreSQL он обычно есть) и подключается к базе:
```sql
CREATE EXTENSION postgis;
CREATE EXTENSION postgis_topology;
```

## Расстояние и системы координат [1:21:45](https://www.youtube.com/watch?v=HYg6O_YaFEk&t=4905s)
> [!warning] Без системы координат `ST_Distance` врёт
> Координаты без указания системы трактуются как точки на **декартовой плоскости**, и расстояние выходит бессмысленным — это просто длина вектора между парами "широта, долгота":
> ```sql
> SELECT ST_Distance(
>     ST_GeomFromText('POINT(37.6726 55.7448)'),   -- Москва
>     ST_GeomFromText('POINT(30.3715 59.9401)'));  -- Петербург
> -- 8.42…  ← число ни в чём, длина вектора на плоскости
> ```

> [!success] С системой координат — расстояние в метрах
> Указываем идентификатор системы (`SRID=4326`) и считаем по географии — получаем настоящие метры:
> ```sql
> SELECT ST_Distance(
>     ST_GeogFromText('SRID=4326;POINT(37.6726 55.7448)'),
>     ST_GeogFromText('SRID=4326;POINT(30.3715 59.9401)'));
> -- 636751…  ← ≈ 636 км между центрами Москвы и Петербурга
> ```
> Третий аргумент `ST_Distance` задаёт расчёт по сфероиду (по умолчанию) или по прямой — на прямой результат чуть меньше

> [!note]- SRID — идентификатор системы координат [1:25:13](https://www.youtube.com/watch?v=HYg6O_YaFEk&t=5113s)
> Систем координат в PostGIS множество (`SELECT * FROM spatial_ref_sys;`), но чаще нужна одна из двух — они задают разные **сфероиды** (модель Земли):
>
> | SRID | Система | Известна как |
> |---|---|---|
> | 4326 | WGS-84 | [[GPS]] |
> | 4740 | ПЗ-90 (параметры Земли 1990) | ГЛОНАСС |
>
> Размеры Земли в них почти совпадают, отличается в основном положение центра — метров на 150

## Геопоиск с индексом [1:27:04](https://www.youtube.com/watch?v=HYg6O_YaFEk&t=5224s)
![[Поиск по радиусу PostGIS.png]]

> [!example] Все аэропорты в радиусе 100 км от Москвы
> Без индекса запрос идёт полным перебором с тяжёлыми вычислениями на каждой строке. Спасает [[Специализированные индексы (GiST, GIN, битовый)|GiST-индекс]] — он умеет работать с перекрывающимися областями и пространственными типами:
> ```sql
> CREATE INDEX idx_airports ON airports USING GIST (
>     Geography(ST_SetSRID(ST_Point(longitude, latitude), 4326)));
>
> SELECT * FROM airports WHERE ST_DWithin(
>     Geography(ST_SetSRID(ST_Point(longitude, latitude), 4326)),
>     ST_GeogFromText('SRID=4326;POINT(37.6726 55.7448)'),
>     100 * 1000);   -- радиус в метрах
> ```

> [!note] Что умеет геопоиск PostGIS
> Вхождение точки в многоугольник, поиск по радиусу, вычисление расстояний и многое другое — полноценный пространственный движок поверх PostgreSQL
