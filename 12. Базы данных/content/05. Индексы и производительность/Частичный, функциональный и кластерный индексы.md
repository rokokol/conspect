# Частичный, функциональный и кластерный индексы
Это не отдельные типы, а **способы построить** [[Индекс B-tree|обычный индекс]]: частичный — по части строк, функциональный — по выражению, кластерный — задаёт физический порядок таблицы. У первых двух одна и та же ловушка: условие/выражение приходится точно повторять в запросе, иначе индекс не используется

## Частичный индекс [19:00](https://www.youtube.com/watch?v=4Tgvd6NPufs&t=1140s)
**Частичный индекс** держит в себе только строки, удовлетворяющие условию `WHERE`:

```sql
CREATE INDEX idx_subjects_avatar ON subjects (avatar_id)
    WHERE avatar_id IS NOT NULL;
```

Если у большинства строк значение `NULL`, индексировать их незачем. В примере лектора индекс был **вдвое больше таблицы**, а после условия `IS NOT NULL` суммарный объём индексов сократился **втрое**

> [!warning] Условие надо таскать за собой
> Чтобы частичный индекс применился, его условие должно стоять и в запросе. Запросы вида "выбрать предметы, где `avatar_id IS NULL`" такой индекс не ускорит, зато все остальные работают так, будто он построен по всей таблице[^notnull]

[^notnull]: Для `NOT NULL` по полям внешнего ключа, по которым идёт `JOIN`, PostgreSQL научился выводить условие сам (примерно с версии 9.3–9.4), так что такой частичный индекс можно создавать безопасно. Заодно помни: в PostgreSQL [[Определение данных (DDL)|внешний ключ не создаёт индекс автоматически]] (в отличие от MySQL)

## Функциональный индекс [20:41](https://www.youtube.com/watch?v=4Tgvd6NPufs&t=1241s)
**Функциональный индекс** строится не по значению поля, а по $f(\text{поле})$. Классика — регистронезависимый поиск:

```sql
CREATE INDEX idx_movies_title_lower ON movies (LOWER(title));
```

> [!warning] Выражение в запросе должно совпадать с индексом
> Индекс по `LOWER(title)` использует только запрос с тем же выражением:
> - `WHERE LOWER(title) = 'алиса в стране чудес'` → индекс работает;
> - `WHERE title = 'Алиса в стране чудес'` → индекс **не** работает
>
> Если же построить индекс по голому `title`, всё поменяется местами. Подробнее про регистронезависимый поиск — [[Регистронезависимый поиск]]

## Кластерный индекс [22:45](https://www.youtube.com/watch?v=4Tgvd6NPufs&t=1365s)
По умолчанию строки таблицы лежат в том порядке, в каком их записали. **Кластеризация** принудительно упорядочивает их по выбранному индексу:

```sql
CLUSTER movies USING idx_movies_title;
```

> [!info] Зачем это нужно
> Чтение по индексу — это последовательный проход по индексу, но за каждой строкой идёт прыжок в таблицу: [[Стоимость операций|случайное чтение]], дорогое на [[Стоимость операций|HDD]]. Если данные физически упорядочены по тому же индексу, чтение строк тоже становится последовательным, и индекс работает быстрее

> [!warning] Кластеризация одноразовая
> `CLUSTER` упорядочивает таблицу **один раз**. Дальше строки добавляются, удаляются и меняются — порядок не поддерживается, надо периодически повторять `CLUSTER`. Кластерный порядок у таблицы только **один**
