# Индекс B-tree
**B-tree** (сбалансированное дерево) — индекс по умолчанию, который покрывает ~90% случаев. Хранит значения в упорядоченном дереве: спуск от корня к листу даёт поиск по равенству, рекурсивный обход — по порядку, а соседние листья сцеплены, что даёт дешёвый поиск по диапазону

![[Индекс B-tree.png]]

## Что умеет [04:00](https://www.youtube.com/watch?v=4Tgvd6NPufs&t=240s)
Возьмём составной индекс по `(last_name, first_name, birth_date)`:

> [!check] Запросы, которые ускоряет B-tree
> - **полное совпадение** — найти строку по всему ключу: спускаемся по дереву, выбирая нужную ветвь;
> - **левый префикс** — поиск по `last_name` или по `(last_name, first_name)`: префикс ключа задаёт поддерево;
> - **диапазон** — `birth_date BETWEEN …`: упорядоченность даёт читать листья подряд;
> - **сортировка и обход по порядку** — рекурсивный обход дерева выдаёт значения уже отсортированными

## Ограничение составного ключа [05:11](https://www.youtube.com/watch?v=4Tgvd6NPufs&t=311s)
> [!warning] Без левой части ключа индекс не работает
> Столбцы в составном индексе **нельзя пропускать**. Для `(last_name, first_name, birth_date)`:
> - знаем `last_name` + `birth_date` (пропущен `first_name`) → индекс поможет только по `last_name`, до `birth_date` он не доберётся;
> - знаем только `first_name` (нет левого `last_name`) → индекс бесполезен
>
> Порядок столбцов в индексе — это иерархия: каждый следующий уточняет предыдущий, и перепрыгнуть через звено нельзя

Поэтому при `WHERE first_name = 'Алиса'` без `last_name` дерево, упорядоченное по фамилии, ничем не помогает — придётся читать таблицу целиком ([[Стоимость операций|последовательное чтение]]) либо строить отдельный индекс по `first_name`
