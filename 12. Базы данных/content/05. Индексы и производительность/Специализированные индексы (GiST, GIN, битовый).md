# Специализированные индексы (GiST, GIN, битовый)
Кроме B-tree и хеша есть индексы под особые задачи: **GiST** — для перекрывающихся областей, **GIN** — для полей с множеством значений, **битовый** — для объединения условий. Первые два создаются явно, битовый — скрытый и строится [[Реляционная модель данных|СУБД]] на лету

## GiST [12:25](https://www.youtube.com/watch?v=4Tgvd6NPufs&t=745s)
**GiST** (Generalized Search Tree) индексирует значения, которые могут **перекрываться** между собой. По одной координате [[Индекс B-tree|дерево]] построить легко, но точку ещё можно, а полигон или прямоугольник — уже нет. GiST строит особый подвид дерева, где перекрывающиеся области ищутся быстро

> [!example] Где применяется
> - **пространственные данные** (R-Tree) — точки, области, геометрия на карте;
> - **любой тип данных**, для которого определён набор из нескольких методов — можно завести свой тип и индексировать его через GiST (подключается расширением)

## GIN [13:43](https://www.youtube.com/watch?v=4Tgvd6NPufs&t=823s)
**GIN** (Generalized Inverted Index) — инвертированный индекс: вместо "в строке такие значения" хранит обратное — **какой ключ в каких строках встречается**

> [!example] Где применяется
> Когда внутри одного поля **несколько значений**:
> - полнотекстовый поиск (слово → список документов);
> - массивы;
> - поля типа [[Слабоструктурированные данные и JSON|JSON]]

## Битовый индекс [14:57](https://www.youtube.com/watch?v=4Tgvd6NPufs&t=897s)
**Битовый индекс** хранит для условия "да/нет" большую битовую строку: один бит на строку таблицы. Условие `пол = 'М'` — это маска из нулей и единиц, и несколько условий пересекаются простыми **битовыми операциями**

![[Битовый индекс.png]]

> [!info] Скрытый индекс, его строит СУБД
> Вручную битовый индекс создать нельзя. PostgreSQL строит его **на лету**, когда нет одного индекса сразу под все условия: берёт разные индексы, по каждому строит битовую маску, пересекает их и получает список кортежей для чтения (в плане запроса — [[EXPLAIN — план выполнения запроса|Bitmap Index Scan / Bitmap Heap Scan]])

> [!warning]- Сложность — соответствие id ↔ номер бита
> "Какой бит какой строке" — нетривиально: идентификаторы идут с **дырами**, бывают не числовыми (строковый первичный ключ). Поэтому битовый индекс хорош именно как временная структура для объединения условий, а не как постоянный индекс
