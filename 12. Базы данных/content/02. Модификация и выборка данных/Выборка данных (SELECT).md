# Выборка данных (SELECT)
`SELECT` — главная команда [[Определение данных (DDL)|DML]] (вместе с `INSERT`/`UPDATE`/`DELETE`). Это [[Реляционная алгебра|реляционная алгебра]] в синтаксисе [[Определение данных (DDL)|SQL]]: каждая часть запроса отвечает своей операции над отношениями

## Анатомия запроса [1:16:21](https://www.youtube.com/watch?v=dGwkG2VyDTY&t=4581s)
| Часть                                                   | Что делает                                                |
| ------------------------------------------------------- | --------------------------------------------------------- |
| [[Подзапросы и обобщённые табличные выражения\|`WITH`]] | именованные подзапросы (в т.ч. рекурсивные)               |
| `SELECT [ALL\|DISTINCT]`                                | список выражений или `*`; `DISTINCT` убирает дубли        |
| `FROM`                                                  | источник строк                                            |
| `WHERE`                                                 | фильтр строк                                              |
| `GROUP BY`                                              | группировка для агрегатов                                 |
| `HAVING`                                                | фильтр уже *сгруппированного* результата                  |
| `UNION`/`INTERSECT`/`EXCEPT`                            | [[Реляционная алгебра\|теоретико-множественные операции]] |
| `ORDER BY`                                              | сортировка                                                |
| `LIMIT`/`OFFSET`                                        | срез результата (постраничность)                          |
| `FOR UPDATE`                                            | взять блокировку на строки под будущее изменение          |

## FROM — откуда берём строки [1:20:10](https://www.youtube.com/watch?v=dGwkG2VyDTY&t=4810s)
В `FROM` идут постоянные таблицы, [[Определение данных (DDL)|временные таблицы]] и представления (`VIEW`).

> [!warning] INSERT/UPDATE/DELETE в FROM нельзя [1:20:46](https://www.youtube.com/watch?v=dGwkG2VyDTY&t=4846s)
> Эти команды умеют возвращать строки (`INSERT` — добавленные, `UPDATE` — после правки, `DELETE` — удалённые), но в `FROM` их вставить нельзя. Вероятная причина — безопасность: при SQL-инъекции в `FROM` нельзя было бы дописать деструктивное действие. Внутри `WITH` — можно

## WHERE — фильтр строк [1:21:24](https://www.youtube.com/watch?v=dGwkG2VyDTY&t=4884s)
Сравнения (`a = b`, `a <> b`, `a < b`, `a > b`), логика `AND`/`OR`/`NOT` и:
- **`a BETWEEN x AND y`** — интервал, включающий **обе** границы (`a BETWEEN 2 AND 4` → 2, 3, 4)
- **`a IN (…)`** — принадлежность множеству
- **`a LIKE маска`** — сравнение по маске: `_` — любой **один** символ, `%` — любая последовательность символов

> [!tip] Оптимизатор понимает сравнения, но не арифметику [1:22:55](https://www.youtube.com/watch?v=dGwkG2VyDTY&t=4975s)
> Условие `a < b` [[Оптимизатор запросов|оптимизатор]] может выполнить через [[Индекс B-tree|индекс]] — он знает, что такое "меньше". А `a + b < c` для него магия: `a + b` придётся вычислять для каждой строки, индекс уже не применишь

## DISTINCT и дубли
`SELECT DISTINCT` схлопывает одинаковые кортежи — это [[Реляционная алгебра|проекция]] в чистом виде. Две строки из одних `NULL` тоже считаются дублем и схлопываются.

> [!important] UNION по умолчанию убирает дубли — пишите UNION ALL [1:17:45](https://www.youtube.com/watch?v=dGwkG2VyDTY&t=4665s)
> `UNION` по умолчанию работает как `DISTINCT` (теряет дубликаты) — единственная команда с таким поведением, остальные дубли сохраняют. Дедупликация **не бесплатна** (требует ресурсов), поэтому, когда дубли не мешают, явно пишут `UNION ALL`

> [!info]- DISTINCT ON — учитывать поле, но не выводить [1:24:30](https://www.youtube.com/watch?v=dGwkG2VyDTY&t=5070s)
> `DISTINCT ON (поля)` позволяет искать дубли по одному набору полей, а в результат выводить другой. На практике пользы мало — обычно в поиске дублей участвуют ровно те поля, что и в выборке

## Группировка и агрегаты [1:31:05](https://www.youtube.com/watch?v=dGwkG2VyDTY&t=5465s)
`GROUP BY` собирает строки в группы по набору полей, а агрегатная функция считает значение **в рамках группы** (не по всей таблице): средний возраст *по отделу*, число сотрудников *каждого уровня*:
```sql
SELECT grade, department, COUNT(*)
FROM employees
GROUP BY grade, department
ORDER BY grade, department;
```

> [!warning] В SELECT — только сгруппированные поля и агрегаты [1:34:46](https://www.youtube.com/watch?v=dGwkG2VyDTY&t=5686s)
> Если есть хоть один агрегат, в списке выборки разрешены **только** поля из `GROUP BY` (иначе непонятно, какую из строк группы взять). Ловушка: **[[Тихие предупреждения вместо ошибок|MySQL этого не требует]]** и молча подставит произвольную строку группы — гарантий никаких

> [!note]- COUNT(*) и COUNT(поле) — разные операции [1:37:01](https://www.youtube.com/watch?v=dGwkG2VyDTY&t=5821s)
> - `COUNT(*)` — число строк в группе
> - `COUNT(поле)` — число строк, где `поле IS NOT NULL`
>
> То же с `AVG(age)` и подобными: в расчёт идут только строки с не-`NULL` значением. Выглядят похоже, считают разное

> [!note]- Тонкости агрегатов: DISTINCT, ORDER BY, FILTER [1:35:48](https://www.youtube.com/watch?v=dGwkG2VyDTY&t=5748s)
> Внутри агрегата можно задать `ALL`/`DISTINCT`, порядок `ORDER BY` (важен, например, для конкатенации имён по алфавиту) и `FILTER (WHERE …)` — учитывать в агрегате не все строки группы

`HAVING` фильтрует уже **сгруппированный** результат (там, где `WHERE` фильтрует исходные строки).

> [!warning] GROUP BY не гарантирует порядок [1:33:46](https://www.youtube.com/watch?v=dGwkG2VyDTY&t=5626s)
> Группировка может *попутно* отсортировать вывод, но обещания нет — за фиксированный порядок отвечает только явный `ORDER BY`

## Условные выражения [1:29:48](https://www.youtube.com/watch?v=dGwkG2VyDTY&t=5388s)
Когда в выражении нужна развилка:

| Конструкция | Смысл |
|---|---|
| `CASE WHEN усл THEN знач … ELSE …` | цепочка `if-else`; срабатывает первое подошедшее условие |
| `NULLIF(a, b)` | `NULL`, если `a = b`, иначе `a` |
| `GREATEST(…)` / `LEAST(…)` | наибольшее / наименьшее из значений |

## Срез, сортировка, алиасы
- **`ORDER BY`** — сортировка результата
- **`LIMIT n` / `OFFSET k`** — взять `n` строк начиная с позиции `k` (постраничность); `FETCH` — синоним `LIMIT`
- **`FOR UPDATE`** — пометить, что строки будут меняться, и взять на них блокировку
- **Алиас столбца** [1:38:10](https://www.youtube.com/watch?v=dGwkG2VyDTY&t=5890s) — без явного `AS` имя столбца результата берётся из поля (`SELECT id`) или собирается из выражения; для сложных выражений человеческое имя удобнее задать самому
