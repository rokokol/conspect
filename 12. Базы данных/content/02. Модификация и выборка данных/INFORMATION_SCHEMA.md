# INFORMATION_SCHEMA
После кучи [[Определение данных (DDL)|CREATE и ALTER TABLE]] узнать, какая структура у базы *сейчас*, позволяет **`INFORMATION_SCHEMA`** — системная схема, в которой текущая структура базы лежит **в виде обычных таблиц**, доступных через [[Выборка данных (SELECT)|SELECT]]

> [!note] Схема — это namespace для таблиц [1:09:31](https://www.youtube.com/watch?v=dGwkG2VyDTY&t=4171s)
> **Схема** в [[Реляционная модель данных|СУБД]] — пространство имён для таблиц; их может быть несколько. По умолчанию работают в `public`, а среди системных — `information_schema`, где описаны все таблицы, столбцы, типы, триггеры, представления и последовательности базы

## Ключевые таблицы [1:10:12](https://www.youtube.com/watch?v=dGwkG2VyDTY&t=4212s)
| Таблица | Что внутри |
|---|---|
| `tables` | каталог (текущая база), схема-namespace, имя и тип таблицы, действия при коммите для временных |
| `columns` | таблица и имя колонки, её позиция, `DEFAULT`, nullable, тип, данные по ссылкам и уникальности |

## Зачем читать метаданные [1:12:00](https://www.youtube.com/watch?v=dGwkG2VyDTY&t=4320s)
- **Инструменты с [[Пользовательский интерфейс|GUI]]** — список таблиц, колонок и автодополнение берут структуру именно отсюда
- **Проверка миграций** — сравнить базу, поднятую [[Версионирование схемы БД|инкрементными патчами]], с эталонной "последней версией": совпадают ли структуры
- **Проверка совместимости из кода** — ORM (Object-Relational Mapping; например, Hibernate) сверяет, подходит ли схема под типы, объявленные программистом, ещё до работы с данными
