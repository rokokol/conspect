# COLLATION и регистронезависимое сравнение
> [!success] У MySQL регистронезависимое сравнение встроено в collation [01:11:21](https://www.youtube.com/watch?v=mkI2q6twyc0&t=4281s)
> **Collation** (правило сравнения и сортировки строк) можно задать прямо на столбце. Суффикс `_ci` (case-insensitive) делает сравнение нечувствительным к регистру без всяких функций:
> ```sql
> name VARCHAR(100) COLLATE utf8_general_ci   -- 'Маша' = 'маша'
> ```

## Чего не хватает PostgreSQL
> [!warning] В PostgreSQL то же делают окольно
> У PostgreSQL collation наследуется от **локали [[Операционная система|ОС]]** и регистронезависимого сравнения из коробки не даёт. Тот же эффект приходится получать иначе (разобрано в [[Регистронезависимый поиск]] из f03):
> - [[Регистронезависимый поиск|функциональный индекс]] по `LOWER(name)` и сравнение `LOWER(...) = LOWER(...)`;
> - тип `citext` из расширения;
> - явный `COLLATE` с ICU-провайдером (ICU — International Components for Unicode).
>
> Единственный надёжный способ перенести между серверами и саму сортировку, и регистронезависимость — задавать collation **явно**, а не полагаться на локаль машины

> [!note]- libslave — забирать изменения MySQL из C++ [01:50:45](https://www.youtube.com/watch?v=mkI2q6twyc0&t=6645s)
> C++-библиотека `libslave` притворяется репликой и читает поток изменений MySQL напрямую — линкуется только с клиентом `libmysqlclient`. Полезна, чтобы внешняя система ловила правки таблиц на лету (кэши, поисковые индексы), не опрашивая базу
