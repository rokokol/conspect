# Отступления MySQL от стандарта SQL
"В MySQL втягивают много фич, и часть из них реализована странновато" — несколько таких расхождений со стандартом [01:08:14](https://www.youtube.com/watch?v=mkI2q6twyc0&t=4094s)

## UPDATE считает присваивания слева направо [02:06:10](https://www.youtube.com/watch?v=mkI2q6twyc0&t=7570s)
> [!danger] Поменять местами `a` и `b` одним `UPDATE` не выйдет
> Стандарт SQL92 требует вычислять **все** правые части от **старой** строки, поэтому swap работает:
> ```sql
> UPDATE foo SET a = b, b = a;   -- по стандарту: значения меняются местами
> ```
> MySQL же применяет присваивания **по порядку**, и второе видит уже изменённое `a`:
> ```text
> a = b   → a стало равно старому b
> b = a   → b стало равно НОВОМУ a (= старому b)
> итог: оба столбца = старое b, обмена не произошло
> ```

## Имена таблиц зависят от файловой системы [01:04:54](https://www.youtube.com/watch?v=mkI2q6twyc0&t=3894s)
> [!warning] `lower_case_table_names` ломает переносимость
> MySQL кладёт каждую таблицу в файл, поэтому чувствительность имён к регистру наследует от [[Операционная система|ОС]]: на Linux `Orders` и `orders` — **разные** таблицы, на Windows по умолчанию приводятся к нижнему регистру и совпадают. База, перенесённая Linux↔Windows, внезапно перестаёт находить таблицы
>
> Параметр `lower_case_table_names` управляет приведением, а практический вывод лектора прост: **не использовать большие буквы в именах таблиц** (и не держать боевую базу под Windows)

## Многотабличный DELETE [02:07:52](https://www.youtube.com/watch?v=mkI2q6twyc0&t=7672s)
> [!example] `DELETE … JOIN` чистит по связи
> Стандартный способ удалить строки по другой таблице — через подзапрос:
> ```sql
> DELETE FROM t1 WHERE t1.id IN (SELECT t2.id FROM t2);
> ```
> MySQL даёт компактный многотабличный синтаксис с соединением (в PostgreSQL ту же роль играет [[Модификация данных (DML)|`DELETE … USING`]]):
> ```sql
> DELETE t1 FROM t1 JOIN t2 ON t1.id = t2.id;
> ```
