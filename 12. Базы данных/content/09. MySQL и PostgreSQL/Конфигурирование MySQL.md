# Конфигурирование MySQL
Базовые параметры, которые трогают при локальной настройке. Кэш в MySQL **свой у каждого движка** — у MyISAM и InnoDB он настраивается порознь, в отличие от единого [[Настройка памяти PostgreSQL|`shared_buffers`]] PostgreSQL

## Кэш MyISAM
> [!info] `key_buffer_size` кэширует только индексы [01:30:30](https://www.youtube.com/watch?v=mkI2q6twyc0&t=5430s)
> MyISAM держит в своём буфере **только индексы** (данные кэширует [[Операционная система|ОС]]). Под буфер отдают 25–50% памяти, выделенной MyISAM; можно завести несколько именованных буферов и прибить горячие таблицы к своему:
> ```sql
> SET GLOBAL key_buffer_1.key_buffer_size = 1G;
> CACHE INDEX t1, t2 IN key_buffer_1;
> LOAD INDEX INTO CACHE t1, t2;     -- прогреть кэш заранее
> ```

> [!warning]- `delay_key_write` — скорость ценой риска
> Откладывает сброс изменённых индексных блоков на диск (`OFF` / `ON` / `ALL`). Ускоряет запись, но при сбое сервера индекс MyISAM остаётся несогласованным и требует ремонта

## Кэш InnoDB
> [!success] `innodb_buffer_pool_size` — главный параметр, ~80% [[Характеристики ЗУ и типы ПЗУ|RAM]]
> InnoDB кэширует в пуле **всё**: индексы, данные, буфер вставки, блокировки, внутренние структуры. На выделенном сервере под него отдают около 80% физической памяти. Состояние пула можно сохранять между перезапусками, чтобы не прогревать кэш заново:
> ```sql
> SET GLOBAL innodb_buffer_pool_dump_at_shutdown = ON;
> ```

## Журнал InnoDB
> [!abstract] Размер журнала и момент сброса
> - `innodb_log_file_size` — размер [[Журнал транзакций (WAL)|журнала транзакций]]; берут с запасом на 10–60 минут работы сервера под нагрузкой, чтобы журнал не переключался слишком часто;
> - `innodb_flush_log_at_trx_commit` — компромисс [[Надёжность данных (durability)|надёжность против скорости]]:
>
> | Значение | Когда журнал идёт на диск | Риск |
> |---|---|---|
> | `1` | при каждом коммите | ничего не теряется (по умолчанию) |
> | `2` | пишется в файл, сброс раз в секунду | при крахе ОС теряется ~1 с |
> | `0` | сброс раз в секунду | при крахе процесса теряется ~1 с |
>
> Аналог `synchronous_commit` PostgreSQL: ослабляя гарантию, выменивают скорость на потерю последних транзакций при сбое
