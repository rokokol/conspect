# AUTO_INCREMENT в MySQL
> [!info] У MySQL нет общего объекта-последовательности [00:50:48](https://www.youtube.com/watch?v=mkI2q6twyc0&t=3048s)
> Автоинкремент — не отдельная сущность, а **свойство столбца**, и счётчик живёт **внутри каждого хранилища** своей реализацией. Отдельного объекта `SEQUENCE`, как в PostgreSQL, нет — отсюда два неудобства ниже

## Значение нельзя узнать заранее
В отличие от [[Модификация данных (DML)|`INSERT … RETURNING`]] PostgreSQL, в MySQL **до вставки** новый идентификатор не получить: сначала вставляешь строку, потом отдельным вызовом (`LAST_INSERT_ID()`) спрашиваешь, какой номер выдали. Это ломает пакетную вставку, когда нужно знать `id` ещё до записи

## Идентификаторы переиспользуются [00:53:04](https://www.youtube.com/watch?v=mkI2q6twyc0&t=3184s)
> [!warning] После перезапуска счётчик может откатиться
> InnoDB исторически держал счётчик автоинкремента **в памяти** и при старте восстанавливал его как `MAX(id) + 1` по таблице. Если удалить последние строки и перезапустить сервер — счётчик "забывает" о выданных номерах и начинает раздавать **те же идентификаторы заново**:
> ```text
> id 1,2,3,4,5 → удалили 4,5 → рестарт → следующий INSERT снова получит id 4
> ```
> Опасно, если на этот `id` где-то ссылались по значению (внешние системы, кэши, логи) — старые ссылки внезапно указывают на новую строку
