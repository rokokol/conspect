# Изменение схемы в MySQL
Два следствия [[Архитектура MySQL и движки хранения#Цена подключаемости дублирование метаданных|дублирования метаданных]] между ядром и хранилищем: **[[Определение данных (DDL)|DDL]] не транзакционен** и **`ALTER TABLE` пересобирает таблицу целиком**

## DDL сам завершает транзакцию [00:15:23](https://www.youtube.com/watch?v=mkI2q6twyc0&t=923s)
> [!danger] Любой `ALTER TABLE` авто-коммитит открытую транзакцию
> Метаданные надо синхронно поправить и в ядре, и в хранилище, а откатить это движок не умеет. Поэтому MySQL перед DDL **молча фиксирует** текущую транзакцию:
> ```sql
> BEGIN;
> INSERT INTO orders ...;        -- ещё не зафиксировано
> ALTER TABLE orders ADD note TEXT;  -- здесь происходит скрытый COMMIT
> ROLLBACK;                      -- откатывать уже нечего
> ```
> Скрипт миграции, рассчитанный на атомарность "всё или ничего", в MySQL разваливается: половина шагов уже зафиксирована. Сравните с [[Изменение схемы без простоя|PostgreSQL]], где `ALTER` внутри транзакции честно откатывается

## ALTER пересобирает таблицу целиком [00:17:25](https://www.youtube.com/watch?v=mkI2q6twyc0&t=1045s)
> [!warning] Даже мелкая правка копирует всю таблицу
> Снять ограничение, удалить столбец, добавить `NULL`-столбец — InnoDB на старых версиях делает это так: создаёт новую таблицу с нужной структурой и **переливает в неё все строки**. На большой таблице это часы блокировки и двойной объём на диске
>
> С MySQL 5.7.4 часть операций умеет идти без копирования — флагом `ALGORITHM=INPLACE`:
> ```sql
> ALTER TABLE films ADD INDEX idx_title (title), ALGORITHM=INPLACE;
> ```
> Большинство других [[Реляционная модель данных|СУБД]] такие изменения делают **правкой одних метаданных** (мгновенно): добавить столбец — это запись в системный каталог, а не перелив данных
