# Потоковая выборка результата (ResultSet)
> [!danger] По умолчанию весь результат запроса MySQL грузит в память клиента [00:21:46](https://www.youtube.com/watch?v=mkI2q6twyc0&t=1306s)
> Драйвер забирает с сервера **всю** выборку разом и складывает в оперативку приложения. На `SELECT` из таблицы в десятки миллионов строк это кладёт процесс по нехватке памяти ещё до того, как обработана первая строка

## Потоковый режим
Чтобы строки шли по одной по мере чтения курсора, [[Модификация данных (DML)|JDBC]]-драйвер MySQL переводят в потоковый режим особым значением размера выборки:
```java
Statement stmt = conn.createStatement(
    ResultSet.TYPE_FORWARD_ONLY,   // только вперёд
    ResultSet.CONCUR_READ_ONLY);   // только чтение
stmt.setFetchSize(Integer.MIN_VALUE);  // магическое значение → стриминг
```
`Integer.MIN_VALUE` здесь — не размер пачки, а **флаг-переключатель**: драйвер начинает отдавать строки потоком вместо одной большой загрузки. Расплата — соединение занято до конца чтения, по нему нельзя слать другие запросы

> [!note]- В PostgreSQL то же делают курсором
> У PostgreSQL потоковую выборку включает не магическое число, а серверный курсор (`DECLARE … CURSOR` или `setFetchSize` с обычным положительным размером при выключенном автокоммите) — драйвер подтягивает строки пачками сам
