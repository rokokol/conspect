# Семантическая разметка
$$\boxed{\text{тег выбирается по смыслу содержимого, а не по внешнему виду}}$$
Внешний вид — целиком забота [[Каскад и селекторы|CSS]]: любой тег можно оформить как угодно. Смысл же читают машины: поисковик решает, что попадёт в выдачу, режим чтения — что оставить от страницы, скринридер — как [[Доступность|озвучить]], твой будущий [[Obsidian API|парсер]] — что где лежит

## Скелет страницы

| Тег | Роль | Сколько на странице |
|---|---|---|
| `<header>` | шапка: логотип, название, навигация | у страницы и у секций |
| `<nav>` | блок навигационных ссылок | сколько нужно |
| `<main>` | основное содержимое | **ровно один** |
| `<article>` | самодостаточный кусок: пост, новость, карточка товара | сколько нужно |
| `<section>` | тематический раздел с заголовком | сколько нужно |
| `<aside>` | побочное: сайдбар, "по теме", сноска-врезка | сколько нужно |
| `<footer>` | подвал: копирайт, контакты, карта сайта | у страницы и у секций |

`<div>` и `<span>` — контейнеры **без смысла**: legitimate для группировки под стили, но только когда смыслового тега нет. Страница из одних div — "div-суп" — работает, но нема для всех машин[^1]

[^1]: Промежуточная эпоха: до HTML5 (2008) смысловых тегов скелета не было, и весь веб был div-супом с классами `class="header"`, `class="nav"`. Авторы стандарта выбирали имена новых тегов, статистически проанализировав миллионы страниц — какие имена классов люди дают блокам

## Заголовки

`<h1>…<h6>` образуют иерархию: h1 — тема страницы (один), h2 — крупные разделы, h3 — подразделы. Уровень выбирается по **логике вложенности, не по размеру шрифта** — размер поправит CSS

> [!warning] Не перепрыгивать уровни
> h2 → h4 "потому что красивее" ломает оглавление для скринридеров и поисковиков. Дерево заголовков любой страницы видно в лабе `lab02-dissect-a-site` одной строкой в консоли

## Списки

| Тег | Что | Пример |
|---|---|---|
| `<ul>` + `<li>` | неупорядоченный | меню, теги, фичи |
| `<ol>` + `<li>` | упорядоченный (нумерация значима) | шаги рецепта, топ-10 |
| `<dl>` + `<dt>`/`<dd>` | пары "термин — описание" | глоссарий, ингредиенты, FAQ (frequently asked questions) |

Списки вкладываются: `<li>` может содержать свой `<ul>` — так размечают многоуровневые меню и оглавления

## Ссылки

**`<a href="…">`** — тот самый гипертекст, буква H в [[HTTP]] и [[HTML-документ и DOM-дерево|HTML]]

- `href="https://…"` — внешняя; `href="/notes/"` — относительная внутри сайта; `href="#id-элемента"` — якорь на этой странице (вспомни [[URL и адресация#Анатомия URL|фрагмент URL]])
- `target="_blank"` — новая вкладка; хорошим тоном добавляется `rel="noopener"`
- `download` — скачать вместо перехода; `href="mailto:…"`, `href="tel:…"` — не-HTTP схемы
- Текст ссылки — самодостаточный: "смотри отчёт", не "жми [сюда]" — скринридеры умеют читать список всех ссылок страницы подряд

## Текстовые роли

| Тег | Смысл (не внешний вид!) |
|---|---|
| `<strong>` / `<em>` | важность / смысловое ударение[^2] |
| `<code>`, `<pre>` | код инлайн / блок с сохранением пробелов |
| `<time datetime="2026-07-09">` | дата-время в машиночитаемом виде |
| `<abbr title="…">` | аббревиатура с расшифровкой |
| `<blockquote cite="…">`, `<q>` | цитата блочная / инлайн |
| `<mark>` | подсветка-выделение |
| `<small>` | мелкий шрифт по смыслу: дисклеймеры, копирайт |

[^2]: `<b>` и `<i>` живы, но означают "просто жирный/курсив без особой важности" (термин, название корабля). Разница слышна: скринридер меняет интонацию на `<em>`, но не на `<i>`
