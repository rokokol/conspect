# Доступность
**Доступность** (accessibility, **a11y**[^1]) — чтобы страницей могли пользоваться все: незрячие со скринридером, моторно-ограниченные с клавиатурой без мыши, слабовидящие с зумом 200%. Побочный эффект стараний — страница удобнее и здоровым: тем же капчам, поисковикам и твоим будущим [[Obsidian API|парсерам]]

[^1]: Нумероним: a + 11 букв + y. Той же породы i18n (internationalization) и k8s (kubernetes)

## Как машина читает страницу

Браузер строит из [[HTML-документ и DOM-дерево|DOM]] **дерево доступности**: у каждого элемента — роль (кнопка, ссылка, заголовок), имя (текст или подпись) и состояние (нажато, свёрнуто). Скринридер читает его, а не пиксели. Дерево видно в [[DevTools|DevTools]] → Accessibility

> [!important] Семантика = доступность бесплатно
> `<button>` из коробки: роль "кнопка", фокус с клавиатуры, срабатывание по Enter и пробелу. `<div onclick="…">` — просто текст: скринридер не объявит его кнопкой, Tab до него не дойдёт. Правильный тег из [[Семантическая разметка|семантики]] закрывает 90% доступности до всякой специальной работы

## Опорные точки

- **`alt` у картинок** — [[Медиа и таблицы#Картинки|правила там]]: содержание, а не имя файла; декоративным — пустой `alt=""`
- **[[Семантическая разметка#Заголовки|Заголовки]] без дыр** — скринридер-пользователи прыгают по ним как по оглавлению
- **[[Формы#Подписи и группировка|label у каждого поля]]** — поле без подписи озвучивается как "редактирование, пусто"
- **Текст ссылки самодостаточен** — список из десяти "подробнее" бесполезен
- **`lang` на `<html>`** — иначе русский текст читается английским синтезатором
- **Контраст** текста и фона ≥ 4.5:1 — проверяется пипеткой в DevTools (Inspector → цвет → contrast)

## Клавиатура и фокус

Значительная часть пользователей живёт без мыши: **Tab** — следующий интерактивный элемент, **Enter/пробел** — активировать. Проверка стоит ноль: отложи мышь и пройди свою страницу

- Порядок обхода = порядок в DOM — ещё один довод размечать по смыслу
- **Фокус должен быть виден**: убирать дефолтную обводку `outline` без замены — вредительство
- `tabindex="0"` вводит элемент в обход, `tabindex="-1"` выводит; положительные значения не использовать — ломают естественный порядок

## ARIA

**ARIA**-атрибуты (Accessible Rich Internet Applications: `role`, `aria-label`, `aria-expanded`, …) вручную задают роль и состояние в дереве доступности — для виджетов, которых в [[HTML-документ и DOM-дерево|HTML]] нет: табы, тосты, кастомные дропдауны

> [!warning] Первое правило ARIA — не использовать ARIA
> Если существует нативный тег — он лучше: `<button>` вместо `role="button"`. ARIA не добавляет поведения (фокус, клавиши — всё руками через [[Типы и коэрция|JS]]), а неправильная ARIA хуже её отсутствия: скринридер верит атрибутам, даже когда они врут. Реальные случаи: `aria-label` для кнопки-иконки без текста, `aria-expanded` на раскрывашке
