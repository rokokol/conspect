# Модули
**Модуль** — файл со своей областью видимости: наружу видно только то, что явно экспортировано. До 2015 в языке модулей *не было вообще* — код делили через глобальные переменные и [[Функции и замыкания#Функции высшего порядка|IIFE]]-обёртки, а зависимости соблюдали порядком `<script>`-тегов руками[^1]

[^1]: Вакуум заполняли самоделки: CommonJS (2009, для сервера), AMD/RequireJS (для браузера, с колбэками), UMD (Universal Module Definition; обёртка, совместимая со всеми сразу). Встретишь их следы в любой библиотеке: файлы `*.umd.js`, `*.cjs`, `*.mjs` — окаменелости этой геологии

## ESM

```js
// lib/math.js
export const PI = 3.14159;                  // именованный экспорт
export function area(r) { return PI * r * r; }
export default class Circle { }             // default — один на модуль

// main.js
import Circle, { area, PI as π } from "./lib/math.js";   // default + именованные + переименование
import * as math from "./lib/math.js";      // всё пространство под именем
export { area } from "./lib/math.js";       // реэкспорт — так собирают публичный API пакета
```

**ESM** (ECMAScript Modules) — статическая система: import/export только на верхнем уровне файла, пути — строковые литералы. Поэтому граф зависимостей известен *до выполнения* — на этом стоят автодополнение, tree shaking (выкидывание неиспользуемого кода [[Бандлеры|бандлером]]) и проверка опечаток в именах импортов

> [!tip] Именованный экспорт лучше default
> `import { area }` проверяется тулингом: опечатался — ошибка сразу. `import whatever from` — имя произвольное, единообразие по проекту держится только дисциплиной. Многие стайлгайды запрещают default целиком; исключения — когда файл и есть одна сущность (компонент, [[Анатомия плагина Obsidian|класс плагина]])

### Модуль исполняется один раз

Импорт — не копирование: все импортёры делят **один экземпляр** модуля (синглтон), код верхнего уровня выполняется при первом импорте. Импортированные привязки — живые ссылки на переменные модуля, и они read-only: изменить состояние модуля можно только через его функции

## В браузере

```html
<script type="module" src="main.js"></script>
```

`type="module"` включает: свой scope (не сорит в window), автоматический strict mode, отложенное выполнение (как `defer` — после парсинга [[HTML-документ и DOM-дерево|HTML]]), и `import` работает. Два ограничения: пути должны быть явными (`./utils.js`, с расширением), а по протоколу `file://` модули **не работают** — нужен локальный сервер (`npx serve`, `python -m http.server`) из-за [[Безопасность в браузере|правил same-origin]]

## CommonJS

```js
const fs = require("node:fs");        // импорт — обычный вызов функции
module.exports = { readConfig };      // экспорт — присваивание объекту
```

**CommonJS** (CJS) — модули Node.js с 2009; `require` — динамический (можно в if, с вычисляемым путём), поэтому статический анализ по нему слабее. Node сегодня понимает обе системы: `.mjs` — ESM, `.cjs` — CJS, а для `.js` решает поле `"type": "module"` в [[Node и npm|package.json]] — в нашем `web-course` оно стоит, поэтому все `.js` там ESM

> [!warning] Interop — источник самых кривых ошибок экосистемы
> ESM-файл может импортировать CJS-пакет (default-ом), но CJS не может `require` ESM (только динамическим `import()`). Ошибки `ERR_REQUIRE_ESM` и "default is not a function" — это оно. При выборе библиотек смотри, отдаёт ли пакет ESM-сборку; экосистема мигрирует уже десятилетие и закончит нескоро

> [!note] Динамический import()
> `const { heavy } = await import("./heavy.js")` — работает и в ESM, где угодно в коде: ленивые загрузки по клику, условные импорты. Возвращает промис — синтаксис из [[Промисы|модуля 05]]
