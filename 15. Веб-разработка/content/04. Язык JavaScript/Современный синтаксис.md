# Современный синтаксис
Сахар, появившийся в ES2015+ (ES6[^1]) — то, чем современный [[Типы и коэрция|JS]]-код отличается на глаз от кода 2010 года. Читать чужой [[Система типов TypeScript|TS]]/JS без этого невозможно: деструктуризация и spread — в каждой второй строке

[^1]: До 2015 стандарт ECMAScript выходил раз в годы и нумеровался (ES3 — 1999, ES5 — 2009); шестая версия шла 6 лет, вышла гигантской (классы, модули, промисы, стрелки, let — всё разом) и стала переломом эпохи. С тех пор релизы ежегодные и мелкие: ES2016, ES2017… Слово "ES6" осталось синонимом "современный JS"

## Шаблонные строки

```js
const msg = `Привет, ${user.name}! Тебе ${age >= 18 ? "можно" : "нельзя"}`;
const sql = `многострочность
из коробки`;
```

Бэктики: интерполяция `${выражение}` и многострочность. Продвинутый режим — **тегированные шаблоны** `tag\`строка ${x}\`` — функция получает куски строки и значения отдельно; так устроены CSS-in-JS и защита от [[Определение данных (DDL)|SQL]]-инъекций в некоторых библиотеках

## Деструктуризация

Распаковка структуры в переменные зеркальным паттерном:

```js
const { name, age = 18, address: { city } = {} } = user;   // объект: по именам + дефолт + вложенно
const [first, , third, ...tail] = list;                    // массив: по позициям, с пропуском
function draw({ x = 0, y = 0, color = "#000" } = {}) { }   // именованные параметры — главный кейс
draw({ y: 10, color: "red" });                             // порядок не важен, читается как проза
```

> [!tip] Именованные параметры — стандарт де-факто
> Функция с тремя и более параметрами в современном коде почти всегда принимает один объект и деструктурирует его в сигнатуре. `= {}` в конце позволяет вызвать вообще без аргументов. Это питоновские kwargs, собранные из подручных средств

> [!warning] Деструктуризация не глубже ссылок
> `const { a } = obj` — это ровно `const a = obj.a`: если `a` — объект, ты получил ссылку, не копию. И переименование пишется "наоборот": `{ name: localName }` — ключ слева, новая переменная справа

## Spread и rest

Один синтаксис `...`, две роли по контексту:

```js
// spread — РАЗвернуть итерируемое/объект
const merged = { ...defaults, ...options };   // слить объекты; правый побеждает
const copy = [...arr];                        // поверхностная копия массива
Math.max(...nums);                            // массив → аргументы

// rest — СОбрать остаток
const { id, ...rest } = row;                  // всё кроме id
function log(first, ...others) { }
```

Слияние `{ ...defaults, ...options }` — идиома конфигов с дефолтами; порядок важен: кто последний, тот и прав (ровно как в [[Каскад и селекторы|каскаде CSS]])

## Опциональные цепочки и нулевое слияние

```js
const city = user?.address?.city;        // undefined вместо TypeError, если по пути null/undefined
user?.greet?.();                         // вызвать, только если функция существует
const port = config.port ?? 3000;        // ?? — дефолт ТОЛЬКО при null/undefined
const port = config.port || 3000;        // || — дефолт при любом falsy: port: 0 будет затёрт!
```

**`?.`** (optional chaining) обрывает цепочку на `null`/`undefined`, **`??`** (nullish coalescing) — правильный оператор дефолтов: в отличие от `||` не съедает легальные `0`, `""` и `false`. Пара `?.` + `??` (2020) убила целый класс кода вида `x && x.y && x.y.z`

> [!note] Прочее, что встретится в чужом коде
> - `x ??= 10`, `x ||=`, `x &&=` — присваивание с условием
> - `2 ** 10` — степень
> - метки `label:` у циклов и `for…in` (обход ключей — почти всегда нужен `for…of` из [[Коллекции и итераторы]])
> - `void 0` — архаичный синоним undefined
> - запятая в конце списков `[1, 2, 3,]` — норма и рекомендована: git-диффы чище
