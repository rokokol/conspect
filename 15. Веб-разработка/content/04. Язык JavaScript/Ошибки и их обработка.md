# Ошибки и их обработка
```js
try {
  const data = JSON.parse(raw);        // бросает SyntaxError на кривом JSON
} catch (err) {
  console.error("не распарсили:", err.message);
} finally {
  spinner.hide();                      // выполнится в любом случае — уборка
}
```

`throw` раскручивает стек до ближайшего `catch`; не поймали — скрипт падает, браузер пишет Uncaught Error в консоль (страница при этом жива — умер только текущий [[Event loop|таск]]). `catch` без переменной — `catch { }` — легален, когда сама ошибка не нужна

## Объект Error

У любой ошибки три главных поля: `name` (класс), `message` (человеческий текст) и нестандартное, но вездесущее `stack` — многострочный снимок стека вызовов, лучший друг отладки. Встроенные классы: `SyntaxError`, `TypeError` (обращение к `undefined`, вызов не-функции — 90% ошибок новичка), `RangeError`, `ReferenceError`

> [!warning] throw кидает что угодно — но кидать нужно Error
> `throw "что-то пошло не так"` синтаксически легален, но у строки нет stack, а `catch` по всему коду ожидает Error-подобное. То же про промисы: `reject("текст")` — антипаттерн. Всегда `throw new Error("…")`. Поскольку прилететь может всё, в `catch (err)` [[Система типов TypeScript|TypeScript]] даёт err тип `unknown` — и это честно

## Свои классы ошибок

```js
class ValidationError extends Error {
  constructor(field, message) {
    super(message);
    this.name = "ValidationError";
    this.field = field;
  }
}

try { validate(form); }
catch (err) {
  if (err instanceof ValidationError) showField(err.field, err.message);
  else throw err;                      // чужое — пробросить дальше!
}
```

Свой класс = возможность ловить *выборочно* через `instanceof` и возить полезные данные (поле формы, [[HTTP|HTTP]]-статус). Правило хвоста: неопознанную ошибку **пробрасывай** — молча проглоченная чужая ошибка превращается в многочасовую отладку у того, кто выше[^1]

[^1]: Пустой `catch {}` — знаменитый "error swallowing", источник легенд о "самопочиняющихся" системах. В большом коде ищи такие места грепом `catch\s*(\([^)]*\))?\s*{\s*}` — почти всегда там закопан баг. Легитимное исключение — операция "не критично, если не вышло" (записать в отключённую аналитику), и тогда об этом пишут комментарий

## Стратегия

Не у каждого вызова, а на **границах**: обработчик события, HTTP-запрос, чтение файла, парсинг чужих данных — то есть там, где (а) ошибка ожидаема и (б) есть осмысленная реакция: показать пользователю, повторить, подставить дефолт. Всё остальное пусть летит наверх к общему обработчику — в браузере это `window.onerror` / `unhandledrejection` (сервисы мониторинга вроде Sentry живут именно на них)

> [!tip] Ошибка — часть [[Программный интерфейс приложения|API]] функции
> Проектируя функцию, реши: невалидный вход — это throw (нарушение контракта, баг вызывающего) или нормальный результат (`null`, `{ ok: false, reason }`)? Ожидаемые в норме отказы (не нашли запись, невалидная форма) чище возвращать значением; throw — для действительно исключительного. В [[Дизайн REST API|дизайне API]] эта же развилка станет выбором между 4xx-ответом и пустым 200
