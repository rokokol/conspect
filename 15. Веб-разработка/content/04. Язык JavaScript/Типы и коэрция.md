# Типы и коэрция
**JavaScript** (JS)[^1] — язык с динамической типизацией: тип живёт у *значения*, а не у переменной, и проверяется в рантайме. Значения делятся на семь **примитивов** (неизменяемые, копируются по значению) и **объекты** (всё остальное, копируются по ссылке)

[^1]: Brendan Eich написал первую версию языка за 10 дней в мае 1995 для Netscape. Рабочие имена — Mocha, затем LiveScript; «Java» в финальном имени — чистый маркетинг на хайпе Java, языки не родственники. Отсюда шутка: Java относится к JavaScript как ham к hamster. Стандарт языка называется **ECMAScript** (ECMA — European Computer Manufacturers Association, ассоциация стандартизации; с 1994 года Ecma International), потому что имя JavaScript было торговой маркой Sun

## Семь примитивов

| Тип | Значения | Замечания |
|---|---|---|
| `number` | все числа | один тип для целых и дробных — [[IEEE]] 754 double, тот же `double` из C++ |
| `bigint` | `123n` | целые произвольной длины, с `number` не смешиваются |
| `string` | `"…"`, `'…'`, `` `…` `` | неизменяемы; UTF-16 |
| `boolean` | `true` / `false` | |
| `undefined` | `undefined` | "значения не назначали": необъявленное свойство, функция без return |
| `null` | `null` | "пусто намеренно": ставится руками |
| `symbol` | `Symbol("id")` | уникальные ключи свойств; редкий, но им устроены [[Коллекции и итераторы|итераторы]] |

> [!warning] typeof врёт дважды
> `typeof null === "object"` — баг первой реализации 1995 года, зафиксированный навечно ради обратной совместимости[^2]. И `typeof function(){} === "function"`, хотя функция — объект. Проверка на null — только `x === null`

[^2]: В первой реализации значения хранились с тегом типа в младших битах; у объектов тег был `000`, а null был машинным нулевым указателем — те же нулевые биты. Предложение починить (`typeof null === "null"`) дошло до комитета в 2006 и было отклонено: слишком много кода в вебе уже опиралось на баг. Девиз эволюции JS — "don't break the web"

### Число с сюрпризами

```js
0.1 + 0.2 === 0.3        // false! 0.30000000000000004 — двоичная плавучка (IEEE 754),
                         // как и в C++/Python; сравнивай через Math.abs(a-b) < Number.EPSILON
NaN === NaN              // false — NaN не равен ничему, даже себе; ловится Number.isNaN()
Number.MAX_SAFE_INTEGER  // 2^53 - 1: дальше целые теряют точность — для больших id есть bigint и строки
```

## Коэрция

**Коэрция** (coercion) — автоматическое приведение операндов к нужному типу. Три мишени: к строке, к числу, к булеву

| Контекст | Правило | Примеры |
|---|---|---|
| `+` при строке | всё в строку | `1 + "2"` → `"12"`; `"" + x` — старый трюк "в строку" |
| прочая арифметика | всё в число | `"6" * "2"` → `12`; `+x` — трюк "в число" |
| `if`, `!`, `&&`, `\|\|` | к булеву | см. falsy ниже |

> [!important] Восемь falsy-значений — выучить, остальное truthy
> `false`, `0`, `-0`, `0n`, `""`, `null`, `undefined`, `NaN`. Всё прочее истинно, включая `"0"`, `"false"`, `[]` и `{}` — пустой массив в if пройдёт! Проверка "массив не пуст" — `arr.length > 0`, а не `if (arr)`

### Знаменитые перлы

```js
[] + []       // "" — массивы к строкам ("" и ""), конкатенация
[] + {}       // "[object Object]"
"11" - 1      // 10 (минус — всегда числовой)
"11" + 1      // "111" (плюс при строке — конкатенация)
null + 1      // 1 (null → 0)
undefined + 1 // NaN (undefined → NaN)
```

Каждая строчка следует из таблицы выше — "странности" JS детерминированы, просто правил больше, чем хочется[^3]

[^3]: Классика жанра — доклад "Wat" Гэри Бернхардта (2012, 4 минуты): destroyallsoftware.com/talks/wat. Смеяться, потом объяснить каждый пример — хорошее упражнение из практики модуля

## Равенство

> [!important] Всегда === и !==
> `==` (нестрогое) перед сравнением применяет коэрцию по замысловатой таблице: `0 == ""`, `"0" == 0`, но `"" != "0"` — нетранзитивно! `===` сравнивает без приведений: другой тип — сразу false. Единственное общепринятое исключение: `x == null` — компактная проверка "null или undefined" сразу

Объекты сравниваются **по ссылке**: `{a: 1} === {a: 1}` — false, это разные объекты. Глубокого равенства в языке нет — либо сравнение по полям, либо структурное клонирование/сериализация

## Явное преобразование

```js
Number("42")        // 42; Number("42px") — NaN
parseInt("42px")    // 42 — парсит, пока может; parseInt(x, 10) — основание указывай
String(123)         // "123"
Boolean(x)          // или !!x — идиома "в булев"
JSON.parse / JSON.stringify   // строка ↔ структура данных
```

> [!tip] Проверка типа на практике
> `typeof x === "string"` — для примитивов; `Array.isArray(x)` — для массивов (typeof массива — "object"); `x instanceof Map` — для экземпляров классов; `x == null` — "нет значения". Этот зоопарк — цена динамической типизации, и половина мотивации [[f07. TypeScript — MOC|TypeScript]], где проверки уезжают в компилятор
