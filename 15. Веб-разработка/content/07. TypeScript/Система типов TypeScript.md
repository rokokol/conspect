# Система типов TypeScript
**TypeScript** (TS) — JavaScript + статические типы: компилятор `tsc` проверяет код и **стирает** типы, оставляя чистый [[Типы и коэрция|JS]][^1]. В рантайме типов не существует — это исключительно инструмент времени разработки: автодополнение, проверка контрактов, безопасный рефакторинг. Любой валидный JS — уже валидный TS, поэтому мигрировать можно файл за файлом

[^1]: Автор — Anders Hejlsberg (Microsoft, 2012), до того создавший Turbo Pascal и C#. Изначально TS встретили скепсисом ("Microsoft опять хочет свой веб" — свежа была память о попытках вроде VBScript), но открытая разработка и решение *не отклоняться* от стандарта JS переубедили индустрию: сегодня TS — язык по умолчанию для нового кода, а комитет TC39 обсуждает нативные аннотации типов в самом JS

## Аннотации и вывод

```ts
let title: string = "…";        // аннотация…
let count = 0;                  // …но чаще НЕ нужна: тип выведен (number)
function area(r: number): number { return Math.PI * r ** 2; }
const ids: number[] = [];       // пустые массивы и параметры — аннотируй,
                                // остальное компилятор выводит сам
```

**Вывод типов** (inference) — TS понимает типы из значений; хороший стиль — минимально необходимые аннотации: обязательно на параметрах функций (их вывести не из чего), на публичных [[Программный интерфейс приложения|API]] — по вкусу, локально — почти никогда

## Описание объектов

```ts
interface Card {
  id: number;
  front: string;
  back: string;
  tags?: string[];              // ? — необязательное (string[] | undefined)
  readonly createdAt: number;   // менять нельзя
}

type CardId = Card["id"];       // достать тип поля
type Grade = "again" | "good" | "easy";     // union литералов — «enum здорового человека»
```

`interface` и `type` в 95% случаев взаимозаменяемы (interface расширяется повторным объявлением и `extends`, type умеет union и вычисления). Договорённость проекта важнее выбора; частый стиль — interface для объектов-сущностей, type для остального

## Union

```ts
type Result = number | null;
function find(q: string): Card | undefined { … }
let status: "idle" | "loading" | "error" = "idle";
status = "loadnig";             // ← ошибка компиляции: опечатки больше не живут до рантайма
```

**Union** `A | B` — значение одного из типов. Литеральные union-ы заменяют enum-ы и константы: автодополнение подсказывает варианты, switch проверяется на полноту. Работать со значением union-типа можно только после [[Сужение типов|сужения]]

## Структурная типизация

```ts
interface Point { x: number; y: number }
function dist(p: Point) { … }
dist({ x: 1, y: 2 });               // ок — никто не «реализовывал» Point
dist(window.scrollPos);             // тоже ок, если по форме совпало
```

Совместимость по **форме**, не по имени (в C++/Java — наоборот, номинативно): любой объект с нужными полями подходит. Это осознанный выбор под природу JS, где данные приходят из [[Слабоструктурированные данные и JSON|JSON]] и литералов. Следствие-ловушка: два разных по смыслу типа с одинаковой формой (`UserId = number`, `CardId = number`) взаимозаменяемы — на границах, где это опасно, применяют трюк branded types (`number & { __brand: "UserId" }`)

> [!note] Лишние поля в литералах всё же ловятся
> `dist({ x: 1, y: 2, z: 3 })` — ошибка "excess property": для *свежего литерала* TS включает проверку лишних полей, спасая от опечаток в необязательных свойствах. Тот же объект через переменную пройдёт — структурная совместимость

## any против unknown

| | `any` | `unknown` |
|---|---|---|
| Что значит | "выключи проверку" | "не знаю, что это" |
| Можно делать | всё (и молча упасть в рантайме) | ничего, пока не [[Сужение типов|сузишь]] |
| Заражает | да — распространяется по коду | нет |

`any` — дыра в системе типов, легитимная только на время миграции легаси; линтер её запрещает. `unknown` — честный тип для данных извне: `JSON.parse`, `catch (err)`, ответы [[fetch]] — сначала проверь, потом пользуйся. Пара к ним `never` — тип "не бывает": функция, которая всегда бросает, пустая ветка после полного switch — пригодится для проверки исчерпанности

> [!tip] Строгость — только полная
> В [[tsconfig и файлы деклараций|tsconfig]] всегда `"strict": true`. Без него TS молчит про null/undefined (`strictNullChecks`) и неявные any — то есть не ловит ровно те баги, ради которых его ставили. Строгость на старте бесплатна; включать её в живом проекте потом — недели
