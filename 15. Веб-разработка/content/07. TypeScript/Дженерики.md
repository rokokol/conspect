# Дженерики
**Дженерик** (generic) — тип-параметр: функция или структура, работающая с *каким-то* типом T, сохраняя связь между входом и выходом. Родня шаблонов C++[^1], но без метапрограммирования — чистая параметризация

[^1]: В отличие от C++, где каждый инстанс шаблона порождает свой машинный код (и километры ошибок инстанцирования), дженерики [[Система типов TypeScript|TS]] — только проверка: после [[Система типов TypeScript|стирания типов]] остаётся одна-единственная [[Типы и коэрция|JS]]-функция. Поэтому по дженерику нельзя ветвиться в рантайме — `if (T === string)` не существует

```ts
function first<T>(arr: T[]): T | undefined { return arr[0]; }

first([1, 2, 3]);        // T выведен: number — аргументы подставлять не надо
first(["a", "b"]);       // T = string
first<Card>([]);         // явно — когда вывести не из чего
```

Без дженерика пришлось бы выбирать: `first(arr: any[]): any` (потеряли тип — автодополнение мертво) или копипаста на каждый тип. Дженерик хранит **связь**: что вошло, то и вышло

## Дженерик-структуры

```ts
interface ApiResponse<T> {
  ok: boolean;
  data: T;
}
type CardsResponse = ApiResponse<Card[]>;

class Store<T> {
  private items: T[] = [];
  add(item: T) { … }
}

const wait = <T,>(ms: number, value: T): Promise<T> => …   // знакомые Promise<T>, Map<K, V> —
                                                           // те же дженерики стандартной библиотеки
```

## Ограничения

```ts
function longest<T extends { length: number }>(a: T, b: T): T {
  return a.length >= b.length ? a : b;
}
longest("абв", "гд");        // строки имеют length — ок
longest(10, 20);             // ошибка: у number нет length
```

`T extends X` — "любой T, совместимый с X": внутри функции доступны гарантированные поля, снаружи сохраняется точный тип. Читается как "T не уже, чем X"

### keyof

```ts
function pluck<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}
pluck(card, "front");     // string — тип поля вычислен
pluck(card, "frnt");      // ошибка компиляции: нет такого ключа
```

`keyof T` — union строковых ключей типа (`"id" | "front" | "back"`), `T[K]` — тип значения по ключу. Связка `K extends keyof T` — типобезопасный доступ по имени поля; на ней держатся все "магические" [[Программный интерфейс приложения|API]] вроде `workspace.on(name, cb)` в [[Obsidian API]], где тип колбэка зависит от строки-события

> [!tip] Когда дженерик НЕ нужен
> Если T используется в сигнатуре **один раз** — связь ничего не связывает: `function log<T>(x: T): void` честнее записать `log(x: unknown)`. Дженерик оправдан, когда тип встречается минимум дважды (вход↔выход, два аргумента, вход↔поле класса). Перегруженные дженериками сигнатуры — популярный способ выпендриться, с которым сам TS-гайд просит бороться

## Дефолты и практичные мелочи

```ts
interface EventMap { [name: string]: unknown }
class Emitter<M extends EventMap = EventMap> { … }   // дефолт параметра

const cache = new Map<string, Card>();   // выводу неоткуда взять типы пустой мапы — задаём руками
```

Чтение чужих сигнатур с `<...>` в хедерах библиотек — навык важнее написания своих: в реальном коде дженерики чаще *потребляют* (Promise, Map, Array.map уже параметризованы), чем изобретают
