# Каркас сайта на Vite
Финальный веб-проект курса: интерфейс флеш-карточек на [[Бандлеры|Vite]], ходящий в [[Сервер на Hono и SQLite|наш API]]. [[Бандлеры#Два поколения инструментов|Устройство Vite]] известно из модуля 08 — теперь он рабочий инструмент от `create` до `dist`

## Скелет

```bash
npm create vite@latest deck-web -- --template vanilla-ts
cd deck-web && npm install && npm run dev     # :5173, HMR
```

```
deck-web/
├── index.html          ← точка входа (не в public!)
├── src/
│   ├── main.ts         ← корень графа модулей
│   ├── api.ts          ← клиент API: fetch-обёртки одного стиля
│   ├── ui.ts           ← рендер DOM
│   └── style.css       ← import "./style.css" из main — часть графа
├── public/             ← статика как есть (favicon, robots.txt) → корень dist
└── vite.config.ts
```

Непривычное после статических страниц: `index.html` — не просто файл, а **манифест сборки**. Vite стартует с него, идёт по `<script type="module" src>` и `<link>`, строит [[Модули|граф модулей]] и в проде подставляет хэшированные имена. Всё, до чего есть `import`, проходит конвейер (хэш, оптимизация); всё из `public/` копируется дословно и хэша не получает — потому туда кладут лишь то, что обязано сохранить имя

## import.meta.env

Принцип [[Node как рантайм#process|"конфиг в окружении"]] для клиента: переменные из `.env`-файлов доступны в коде под префиксом `VITE_`

```ts
const API = import.meta.env.VITE_API_URL ?? "/api";
if (import.meta.env.DEV) console.log("dev-режим");   // DEV/PROD — булевы флаги сборки
```

Файлы читаются по **режиму**: `.env` — всегда, `.env.development` — в dev, `.env.production` — при сборке. Так адрес API, ключи аналитики и прочие различия dev/прод живут в файлах, а не в `if`-ах по коду

> [!warning] Всё в бандле клиента — публично
> `import.meta.env.VITE_*` встраивается в собранный [[Типы и коэрция|JS]] текстом — виден любому в DevTools. Префикс `VITE_` — намеренный барьер: переменные без него в бандл не попадают, чтобы серверный секрет из общего `.env` не утёк случайно. Правило абсолютно: секрет (ключ базы, токен) в клиентском коде не живёт никогда — только на [[Сервер на Hono и SQLite|сервере]]. "Спрятать" ключ в минифицированном JS — самообман[^1]

[^1]: Охота на утечки — целая индустрия: боты круглосуточно сканируют публичные бандлы и GitHub на паттерны `sk_live_…`, `AKIA…`; украденный облачный ключ за ночь намайнит криптовалюты на тысячи долларов на твоей карте. GitHub и крупные провайдеры договорились о **secret scanning** — найденный в публичном коммите ключ отзывается автоматически, часто быстрее, чем автор заметит пуш. Надёжнее их всех барьер простой: секрету на клиенте взяться неоткуда

## Прокси в dev

Фронт на :5173, API на :3000 — [[CORS на практике|разные origin]]. Вместо настройки [[CORS на практике|CORS]] проще научить dev-сервер притворяться, будто API — часть сайта:

```ts
// vite.config.ts
export default defineConfig({
  server: {
    proxy: { "/api": { target: "http://localhost:3000", rewrite: (p) => p.replace(/^\/api/, "") } },
  },
});
```

Клиент ходит в `/api/cards` — свой origin, preflight не возникает, cookies работают. В проде ту же роль играет реверс-прокси; клиентский код не меняется от localhost до продакшна — он всегда ходит в `/api`

## Сборка

```bash
npm run build     # → dist/: index.html + assets/main-<хэш>.js — чистая статика
npm run preview   # посмотреть собранное локально (не dev-сервер!)
```

Хэш в имени файла — ключ к [[Кэширование и сеть глубже#Паттерн вечного кэша|вечному кэшу]]: содержимое поменялось → имя поменялось. Ленивая загрузка достаётся почти бесплатно: динамический `import("./stats.ts")` Vite вырезает в отдельный чанк, который скачается при первом вызове — стартовый бандл не тащит редко используемые экраны

`dist/` не нуждается в Node: [[HTML-документ и DOM-дерево|HTML]], JS, [[Каскад и селекторы|CSS]], картинки — раздать их умеет любой файловый сервер, что и делает [[Деплой сайта|следующий шаг]] почти бесплатным

> [!tip] preview ≠ dev
> `npm run preview` отдаёт собранный `dist/` — единственный честный способ увидеть прод локально: без [[Бандлеры|HMR]], с минификацией, с реальными путями и чанками. Баги класса "на dev работало" (забытый ассет, кривой base-путь, порядок загрузки чанков) ловятся именно здесь; прогон `build && preview` перед деплоем — дешёвая страховка от стыдных откатов
