# Переходы и анимации
Движение в [[Каскад и селекторы|CSS]] двух сортов: **transition** — плавный переезд между двумя состояниями (было → стало, триггерит смена стиля), **animation** — самостоятельный сценарий по ключевым кадрам, которому триггер не нужен

## Transition

```css
.button {
  background: steelblue;
  transition: background 0.2s ease, transform 0.2s ease;
}
.button:hover { background: navy; transform: translateY(-2px); }
```

Transition вешается на *исходное* состояние (иначе обратный ход будет мгновенным) и перечисляет: что анимировать, сколько, по какой кривой, с какой задержкой. `transition: all` работает, но ловит и то, что анимировать не хотелось (например, скачок `width` при смене контента) — перечисляй свойства явно

> [!warning] Анимируется только то, у чего есть промежуточные значения
> Числа, цвета, transform — да; `display: none` → `block` — нет (нет середины между "нет" и "есть"). Классическое появление элемента — пара `opacity` + `visibility`, или современные `@starting-style` и `transition-behavior: allow-discrete`, разрешающие анимировать и дискретные свойства

## Transform

```css
transform: translate(-50%, 10px) rotate(3deg) scale(1.05);
```

Сдвиг, поворот, масштаб, перекос — *визуальное* преобразование: элемент рисуется в другом месте, но его место в раскладке не меняется, соседи не двигаются. Порядок функций важен (поворот после сдвига ≠ сдвиг после поворота); точка опоры — `transform-origin`

> [!important] Почему анимируют только transform и opacity
> Изменение `width`, `margin`, `top` заставляет браузер пересчитать раскладку всей страницы на каждый кадр (60 раз в секунду) — [[Как браузер превращает ответ в пиксели|layout → paint → composite]] целиком. `transform` и `opacity` применяются на последнем шаге, композиторе, зачастую силами видеокарты ([[Графический процессор|GPU]]), минуя layout и paint
>
> Отсюда правило: двигать — `translate`, а не `left`; сворачивать — `scale`, а не `height`. Подробнее в [[f09. Браузер изнутри — MOC|модуле 09]]

## Animation и keyframes

```css
@keyframes pulse {
  0%   { transform: scale(1); }
  50%  { transform: scale(1.08); }
  100% { transform: scale(1); }
}
.badge { animation: pulse 1.2s ease-in-out infinite; }
```

**`@keyframes`** — раскадровка в процентах длительности; `animation` — какая раскадровка, сколько длится, сколько раз (`infinite`), в какую сторону (`alternate` — туда-обратно), что остаётся после конца (`fill-mode: forwards` — замри в финальном кадре)

### Тайминг-функции

| Функция | Характер |
|---|---|
| `linear` | равномерно — хорош только для вращения спиннера |
| `ease` (дефолт) | быстрый старт, мягкий финиш |
| `ease-out` | быстро → плавно; **дефолт для появления [[Пользовательский интерфейс\|UI]]** — интерфейс кажется отзывчивым |
| `ease-in` | плавно → быстро; для исчезновений |
| `cubic-bezier(…)` | своя кривая; с выходом за [0,1] даёт пружину-overshoot |
| `steps(n)` | дискретные скачки — покадровая смена спрайтов, "печатающийся" текст[^1] |

[^1]: `steps()` — потомок покадровой мультипликации: спрайт-лист персонажа двигают `background-position` шагами, ровно как плёнку в кинопроекторе. Так анимированы персонажи в старых браузерных играх и стикеры-эмодзи

> [!tip] Быстрее, чем кажется нужным
> Рабочие длительности UI — 150–250ms на ховеры и 200–400ms на появления панелей. 500ms+ ощущается как тормоз уже на третьем повторении. Дизайнерская эвристика: сделай красиво, потом ускорь в полтора раза

### Уважение к prefers-reduced-motion

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation-duration: 0.01ms !important; transition-duration: 0.01ms !important; }
}
```

У части людей анимации вызывают укачивание вплоть до мигрени — системная настройка "уменьшить движение" транслируется в этот media query, и декоративное движение надо гасить. Редкий легитимный кейс `!important` из [[Каскад и селекторы#Каскад|каскада]]

> [!note] Scroll-driven animations — новинка 2024
> `animation-timeline: scroll()` привязывает прогресс анимации не ко времени, а к прокрутке — прогресс-бары чтения и parallax-эффекты теперь возможны без [[Типы и коэрция|JS]]. Поддержка ещё выравнивается, прогрессивное улучшение обязательно
