# Поток и позиционирование
**Нормальный поток** (normal flow) — дефолтная раскладка без единой строчки [[Каскад и селекторы|CSS]]: блочные элементы стопкой сверху вниз во всю ширину, строчные — текут внутри строк слева направо с переносами. Всё остальное позиционирование — способы элемент из потока *вынуть* или внутри него *сдвинуть*

## display

| Значение | Поведение |
|---|---|
| `block` | своя строка, вся доступная ширина, честные width/height (`<div>`, `<p>`, `<section>`) |
| `inline` | течёт в тексте; **width/height и вертикальные margin игнорируются** (`<a>`, `<span>`, `<strong>`) |
| `inline-block` | течёт в тексте, но размеры и отступы работают — гибрид |
| `none` | элемента нет: не рисуется, места не занимает, из [[Доступность|дерева доступности]] удалён (сравни с `visibility: hidden` — место занимает, но невидим) |
| `flex` / `grid` | элемент остаётся блочным снаружи, а *детей* раскладывает по правилам [[Flexbox и Grid]] |

> [!tip] display — это два слова
> Современная запись — `display: block flex`: первое слово — как элемент ведёт себя *снаружи* (в потоке родителя), второе — как раскладывает *внутри*. Привычные односложные значения — сокращения (`flex` = `block flex`, `inline-block` = `inline flow-root`). Эта оптика сразу отвечает на вечный вопрос "почему flex-контейнер не встал в строку" — снаружи он block

## position

| Значение | Из потока? | Относительно чего |
|---|---|---|
| `static` | — (дефолт) | смещения `top/right/bottom/left` игнорируются |
| `relative` | нет — место сохраняется | сдвиг от собственного места; соседи не замечают |
| `absolute` | **да** | ближайший *позиционированный* предок |
| `fixed` | да | окно браузера — не скроллится |
| `sticky` | нет | скроллится как обычно, пока не упрётся в заданный порог (`top: 0`) — дальше прилипает |

> [!important] Пара relative + absolute — главный паттерн позиционирования
> `absolute` привязывается к ближайшему предку с `position` ≠ `static`. Поэтому бейдж в углу карточки — это `position: relative` на карточке (без смещений — только чтобы стать точкой отсчёта) и `position: absolute; top: 8px; right: 8px` на бейдже. Забыл relative на родителе — бейдж улетел к началу страницы

> [!warning] Смещать элементы лучше через transform
> `top/left` у relative-элемента и `transform: translate(…)` дают одинаковую картинку, но по-разному считаются: transform не трогает раскладку и уходит на композитор ([[Как браузер превращает ответ в пиксели]]), поэтому анимируется без пересчёта страницы. Правило: статичное позиционирование — position, любое движение — transform ([[Переходы и анимации]])

### z-index и контексты наложения

Кто выше при перекрытии, задаёт `z-index` — но работает он только на позиционированных (и flex/grid) элементах и только *внутри своего контекста наложения*. **Контекст наложения** (stacking context) — изолированная группа слоёв: элемент с `z-index: 9999` внутри контекста с `z-index: 1` никогда не перекроет соседний контекст с `z-index: 2` — сравниваются родители, не дети

> [!warning] Контекст наложения создаётся десятком неожиданных свойств
> Не только `position` + `z-index`, но и `opacity < 1`, `transform`, `filter`, `will-change`. Классический баг: добавил карточке `opacity: 0.95` — и её выпадающее меню стало прятаться под соседей. Отладка "почему z-index не работает" — это всегда поиск, какой предок нечаянно стал контекстом[^1]

[^1]: Отсюда мем про `z-index: 999999` в легаси-коде: числа растут, а проблема не в числах. В DevTools (Firefox) панель Layout показывает создался ли на элементе stacking context

## float

`float: left/right` вынимает элемент из потока и прижимает к краю, а текст обтекает его — так журнальная картинка обтекается текстом. Это *единственное* законное применение float сегодня. Но с 1998 по ~2015 float-ами строили **все** многоколоночные раскладки — другого инструмента не было[^2]

`clear: both` запрещает элементу обтекать предыдущие float-ы; родитель одних только float-ов схлопывается в нулевую высоту (они же вне потока) — лечится `display: flow-root` на родителе (современно) или классическим хаком clearfix (псевдоэлемент с clear)

[^2]: Эпоху float-вёрстки открыл сайт [CSS Zen Garden](https://csszengarden.com/) (2003): один и тот же [[HTML-документ и DOM-дерево|HTML]], сотни радикально разных дизайнов чистым CSS — манифест "таблицы для данных, а не для раскладки". Если встретишь `.clearfix` в чужом коде — это археологический слой той эпохи

## Центрирование

Век назад "отцентрируй div по вертикали" был мемом-собеседованием, сегодня — одна строка:

```css
.parent { display: grid; place-items: center; }   /* или flex + justify-content/align-items */
```

Доисторические способы, которые ещё встречаются в легаси: `margin: 0 auto` (только горизонталь, блоку с шириной — работает и сейчас, это нормально), `position: absolute; top: 50%; transform: translateY(-50%)`, вёрстка `display: table-cell; vertical-align: middle`
