# Box model
**Box model** (блочная модель) — каждый элемент страницы для браузера прямоугольная коробка из четырёх слоёв: содержимое → padding → border → margin. Вся геометрия [[Каскад и селекторы|CSS]] — управление этими слоями

![[box-model.png]]

## Четыре слоя

| Слой | Свойство | Что это | Красится фоном? |
|---|---|---|---|
| содержимое | `width` / `height` | текст, картинка, дети | да |
| **padding** | `padding` | внутренний отступ — воздух между содержимым и рамкой | да |
| **border** | `border` | рамка: `border: 1px solid #ccc` | сама себя |
| **margin** | `margin` | внешний отступ — расстояние до соседей | нет, всегда прозрачен |

Шорткаты по часовой стрелке сверху: `margin: 10px 20px` (верт | гориз), `margin: 1px 2px 3px 4px` (top right bottom left); отдельные стороны — `padding-left`, `margin-block` / `margin-inline` (логические оси: вдоль текста и поперёк)

## box-sizing

По умолчанию (`box-sizing: content-box`) `width` задаёт ширину *только содержимого*, а padding и border растут наружу: `width: 300px + padding 20px×2 + border 2px×2` = коробка 344px. Это исторический дефолт, с ним вёрстка сеток превращается в арифметику[^1]

> [!important] Универсальный резет — первая строка любого style.css
> ```css
> *, *::before, *::after { box-sizing: border-box; }
> ```
> **`border-box`**: `width` = полная ширина коробки (содержимое + padding + border), задал 300px — получил 300px. Так думает человек, так работали старые IE (Internet Explorer), и это единственный дефолт, который сегодня меняют не глядя

[^1]: В первой войне браузеров IE считал width как border-box вопреки спецификации, Netscape — по ней. "IE box model bug" лет десять был главной головной болью верстальщиков — а в итоге индустрия признала, что "баг" был удобнее стандарта, и вернула его себе опцией `box-sizing`

## Схлопывание margin

Вертикальные margin соседних блоков **схлопываются** (margin collapse): между абзацем с `margin-bottom: 20px` и следующим с `margin-top: 10px` будет 20px, а не 30 — берётся максимум. Схлопывается и margin первого ребёнка с margin родителя — классический сюрприз "отступ у ребёнка, а уехал весь родитель"

> [!warning] Когда схлопывание выключается
> Горизонтальные margin не схлопываются никогда. Вертикальные перестают, если между боксами есть "прокладка": padding или border родителя, либо родитель — flex/grid-контейнер ([[Flexbox и Grid]] этой болезни не имеют вовсе)

## Единицы измерения

| Единица | Что такое | Куда |
|---|---|---|
| `px` | CSS-пиксель[^2] | границы, тени, мелкая геометрия |
| `rem` | кратно `font-size` корня (по умолчанию 16px) | **размеры шрифтов, отступы** — уважает настройку крупного шрифта у пользователя |
| `em` | кратно font-size *текущего* элемента | отступы, привязанные к размеру текста рядом (padding кнопки) |
| `%` | доля от родителя | ширины колонок |
| `vw` / `vh` | 1% ширины/высоты окна (viewport width/height) | полноэкранные секции, hero-блоки |
| `ch` | ширина символа "0" текущего шрифта | ширина текстовой колонки: `max-width: 70ch` |

[^2]: CSS-пиксель ≠ физический пиксель экрана: это угловая единица (примерно 1/96 дюйма на расстоянии вытянутой руки). На retina-экранах в одном CSS-пикселе 2–3 физических — коэффициент виден в [[Типы и коэрция|JS]] как `devicePixelRatio`

> [!tip] Правило большого пальца
> Шрифты и вертикальный ритм — `rem`; ширины — `%`/`ch`/flex; рамки — `px`. Жёсткие `height` в пикселях почти всегда зло: контент длиннее ожидаемого — и он вылезает. Задавай `min-height`, а высоту отдай контенту

## Переполнение

Когда содержимое не влезает в заданные размеры, поведением управляет `overflow` (`-x`/`-y` по осям): `visible` (дефолт — вылезает наружу), `hidden` (обрезать), `scroll` (всегда полосы прокрутки), `auto` (полосы при необходимости). Значение кроме `visible` заодно отключает схлопывание margin внутрь — бокс становится изолированным

`min-width` / `max-width` / `min-height` / `max-height` ставят пределы: классика адаптивной картинки — `img { max-width: 100%; height: auto; }` — не вылезай за родителя, пропорции сохраняй
