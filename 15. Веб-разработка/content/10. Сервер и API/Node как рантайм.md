# Node как рантайм
В [[Node и npm|модуле 08]] Node запускал инструменты; здесь он — сервер. Устройство: движок **V8** исполняет [[Типы и коэрция|JS]], библиотека **libuv** (C) даёт [[Event loop|event loop]] и неблокирующий доступ к системе — файлы, сеть, таймеры[^1]. Ставка архитектуры: один поток + весь ввод-вывод асинхронный, поэтому десять тысяч одновременных соединений — это десять тысяч ожидающих колбэков, а не десять тысяч потоков [[Операционная система|ОС]]

[^1]: Node (Райан Дал, 2009) родился из раздражения: Apache держал по потоку на соединение и падал на C10k — десяти тысячах одновременных клиентов. Спустя десять лет Дал прочитал доклад "10 things I regret about Node.js" (система модулей, node_modules, отсутствие безопасности по умолчанию) и написал Deno — попытку исправить всё сразу. libuv тем временем переросла Node: на ней стоят Julia, Neovim и десятки не-JS проектов

## Тот же язык, другие глобалы

| Есть везде | Только браузер | Только Node |
|---|---|---|
| `fetch`, `URL`, `console`, таймеры, промисы, `crypto`, `structuredClone` | `document`, `window`, [[HTML-документ и DOM-дерево\|DOM]], [[Хранение данных в браузере\|storage]] | `process`, `Buffer`, `node:*`-модули, `__dirname` (в [[Модули\|CJS]]) |

Код [[fetch|запросов из модуля 06]] переносится на сервер дословно — `fetch` встроен с Node 18. **Buffer** — сырые байты для файлов и сети: то, что в браузере `ArrayBuffer`, здесь повседневный тип (любой `fs.readFile` без кодировки возвращает его)

## Event loop с фазами

Браузерная модель "[[Event loop|стек → микротаски → таск]]" в Node уточняется: цикл идёт по **фазам** — timers (`setTimeout`) → poll (события I/O) → check (`setImmediate`) → close. Микротаски (промисы) выполняются между любыми переходами, как в браузере

```js
setTimeout(() => console.log("timeout"), 0);
setImmediate(() => console.log("immediate"));
process.nextTick(() => console.log("tick"));   // своя очередь ВЫШЕ микротасков
// tick → timeout/immediate (порядок этих двух вне I/O не гарантирован!)
```

Практический осадок: `setImmediate` — "после текущего I/O", `process.nextTick` — "прямо сейчас, до всего" (и потому им легко устроить голодание цикла — в новом коде предпочитают `queueMicrotask`). Остальное поведение — ровно как в браузере, интуиция из модуля 05 работает

## Стандартная библиотека

```js
import fs from "node:fs/promises";     // файлы; промисный вариант — всегда его
import path from "node:path";          // path.join(dir, "db.sqlite") — без ручных "/"
import crypto from "node:crypto";      // randomUUID(), scrypt, timingSafeEqual
import http from "node:http";          // голый HTTP-сервер; фреймворки — поверх

const text = await fs.readFile("data.json", "utf8");
await fs.writeFile("out.txt", text.toUpperCase());
```

Префикс `node:` явно отличает встроенное от npm-пакетов и закрывает тайпсквоттинг имён стандартной библиотеки. В обойме также `node:sqlite` ([[Сервер на Hono и SQLite|дальше по модулю]]), `node:test`, `node:util`, `node:worker_threads`

> [!note] Стримы — данные больше памяти
> Файл на 10 ГБ не читается в строку — он течёт кусками: `createReadStream(file).pipe(res)`. `pipe` при этом решает и **backpressure**: если получатель медленнее источника, чтение приостанавливается, память не растёт. Паттерн "источник → труба → сток" — самая старая часть Node; узнавать его важнее, чем писать руками

## process

```js
process.argv          // аргументы CLI: [node, script, ...твои]
process.env.PORT      // переменные окружения — главный канал конфигурации
process.exit(1)       // код выхода ≠ 0 — "упал" для шелла и CI
process.on("SIGTERM", shutdown)   // сигналы ОС — просьба завершиться
```

> [!important] Конфиг живёт в окружении
> Порт, путь к базе, секреты — не в коде, а в `process.env`: это пункт свода правил **twelve-factor app** (двенадцатифакторное приложение — манифест переносимого деплоя). Код одинаков везде, различается окружение: локально `PORT=3000 node server.js`, в [[Деплой в Docker|Docker]] — секция `environment`. Файл `.env` — локальное удобство (`node --env-file=.env`), лежит в `.gitignore`; секреты в git не попадают никогда

> [!warning] SIGTERM обязан обрабатываться
> Платформа останавливает сервис вежливо: сигнал **SIGTERM**, пауза, затем SIGKILL. Сервер без обработчика умирает посреди запросов; правильный финал — перестать принимать новые соединения, дождаться текущих, закрыть базу и `process.exit(0)`. Заготовка стоит три строки, а проверяется в [[Деплой в Docker|деплое]]: `docker stop` шлёт именно SIGTERM

## Однопоточность на сервере

В браузере заблокированный поток вешал вкладку одного пользователя; на сервере — всех сразу. Тяжёлое [[Центральный процессор|CPU]] (хэширование, парсинг гигантского [[Слабоструктурированные данные и JSON|JSON]]) душит все соединения разом:

- **worker_threads** — вынести счёт в отдельный поток (родня [[Параллельность, гонки и отмена|Web Workers]])
- **cluster / несколько процессов** — по процессу на ядро за балансировщиком; заодно переживание падений
- правило по умолчанию: Node-сервер должен быть **I/O-bound** — ждать сеть и диск он умеет бесконечно дёшево, считать — нет

> [!tip] REPL — серверная консоль DevTools
> Голый `node` — **REPL** (Read-Eval-Print Loop), интерактивная песочница: потрогать `fs`, `crypto.randomUUID()`, регэксп. `.editor` — многострочный режим, `_` — последний результат. А `node --watch server.js` перезапускает процесс при правках — dev-цикл без сторонних инструментов (nodemon больше не нужен)
