# ESLint и Prettier
**Линтер** (linter, от lint — "катышки на ткани") — статический анализатор: читает код не запуская и ищет подозрительные места[^1]. **ESLint** — линтер [[Типы и коэрция|JS]]/[[Система типов TypeScript|TS]], ловит *смысловые* проблемы; **Prettier** — форматтер, отвечает за *внешний вид*. Их не выбирают между собой — они пара с чётким разделением труда

[^1]: Слово ввёл Stephen Johnson (Bell Labs, 1978) — утилита `lint` для C выискивала то, что компилятор пропускал. JS-традицию начал JSLint Дугласа Крокфорда с легендарным дисклеймером в документации: "Warning: JSLint will hurt your feelings". Его недемократичность (правила не отключались) породила форк JSHint, а тот — ESLint (2013), где всё стало плагинами

| Инструмент | Вопрос к коду | Пример находки |
|---|---|---|
| Prettier | красиво ли записано | отступы, кавычки, длина строк |
| ESLint | не подозрительно ли | `==` вместо `===`, неиспользуемая переменная, `async` без `await` |
| [[tsconfig и файлы деклараций\|tsc]] | сходятся ли типы | `string` передан туда, где ждут `number` |
| [[Тестирование с vitest\|vitest]] | правильно ли работает | функция возвращает не то |

Каждый уровень ловит своё; спор "зачем линтер, если есть типы" не имеет смысла — `no-unused-vars` и `no-fallthrough` к типам отношения не имеют

## ESLint

Конфиг нового поколения (2022+) — **flat config**: обычный JS-файл `eslint.config.js`, экспортирующий массив; старый `.eslintrc.json` в туториалах — легаси

```js
// eslint.config.js
import js from "@eslint/js";
import tseslint from "typescript-eslint";

export default tseslint.config(
  js.configs.recommended,          // базовый набор правил для JS
  ...tseslint.configs.recommended, // + правила для TS
  {
    rules: {
      "no-console": "warn",              // off | warn | error
      "@typescript-eslint/no-explicit-any": "error",
    },
  },
);
```

Запуск: `npx eslint .`; часть правил чинится сама — `npx eslint . --fix`. Стартовать проще визардом `npm init @eslint/config`

> [!tip] Правила — это документированные грабли
> Страница каждого правила на eslint.org — мини-урок "почему так писать опасно" с примерами. Читать доки правил, на которые ругается линтер, — недооценённый способ учить язык: это конденсат чужих продакшн-ошибок. Особо познавательны `no-async-promise-executor`, `require-atomic-updates`, `no-prototype-builtins` — за каждым стоит [[Промисы|асинхронная]] или [[Объекты, прототипы и классы|прототипная]] история

## Prettier

Философия — **ноль споров**: опций сознательно почти нет, форматтер не подстраивается под вкус, а отменяет сам предмет вкуса[^2]. Работает радикально: парсит код в **AST** (Abstract Syntax Tree — абстрактное синтаксическое дерево) и *печатает заново* с нуля — твоё форматирование не "поправляется", оно полностью игнорируется

```bash
npx prettier --write .     # отформатировать всё
npx prettier --check .     # только проверить (для CI)
```

[^2]: Prettier (2017, James Long) реализует алгоритм из статьи Филипа Уодлера "A prettier printer" (1998) — отсюда имя. Идея алгоритма: документ описывается как дерево вариантов "в строку или в столбик", и принтер выбирает укладку под ширину. Поэтому Prettier сам решает, когда разбить цепочку вызовов по строкам — правило одно: влезает в `printWidth` — в строку, нет — в столбик

> [!note] Конфликт пары решён давно
> Стилистические правила ESLint (кавычки, точки с запятой) дрались бы с Prettier. Конфиг `eslint-config-prettier` просто выключает их все: стиль — Prettier, смысл — ESLint. В современных пресетах уже включён

## Куда встроить

| Момент | Как | Зачем |
|---|---|---|
| в редакторе | format on save + LSP-диагностика (LSP — Language Server Protocol) (в nixvim: conform.nvim + eslint) | ошибки видны при наборе |
| перед коммитом | git-хук `pre-commit` (husky + lint-staged — только изменённые файлы) | грязь не попадает в историю |
| в [[Непрерывная интеграция\|CI]] | `prettier --check && eslint .` | сеть безопасности, если хук обойдён |

> [!tip] Форматтер меняет то, как ты пишешь
> Побочный эффект автоформата: черновик можно писать вообще без оглядки на вид — одной строкой, с лишними скобками — сохранил, и код опрятен. Мысли о форме сгружены машине полностью; это заметно снижает трение письма. Ровно та же причина, по которой в Go форматтер `gofmt` встроили в язык с первого дня — и споров о стиле в Go-сообществе не существует как жанра
