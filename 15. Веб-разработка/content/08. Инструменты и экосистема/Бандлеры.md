# Бандлеры
**Бандлер** (bundler) — собирает граф [[Модули|модулей]] и зависимостей из node_modules в несколько оптимизированных файлов для браузера. Браузер умеет [[Модули|ESM]] и без сборки — но 500 модульных файлов = 500 запросов, `import "lodash"` без путей браузер не поймёт, [[Система типов TypeScript|TS]] не поймёт никто. Сборка решает всё разом

## Что делает сборка

| Операция | Что | Расшифровка |
|---|---|---|
| **резолв** | `import "hono"` → конкретный файл из node_modules | по полям package.json (`exports`) |
| **транспиляция** | TS → [[Типы и коэрция\|JS]], новый синтаксис → старый | типы просто вырезаются (без проверки!) |
| **бандлинг** | граф модулей → один-несколько чанков | + code splitting: ленивые куски отдельно |
| **tree shaking** | выкинуть неиспортированное | буквально "потрясти дерево, сухое осыпется"; работает благодаря статичности ESM |
| **минификация** | короткие имена, без пробелов | + sourcemap — карта "минифицированное → исходник" для [[Отладка|отладчика]] |

## Два поколения инструментов

**esbuild** — сборщик, написанный на Go: в 10–100 раз быстрее предшественников (webpack/Rollup эпохи JS-на-JS)[^1]. Идеален как "просто собери мне файл": один вызов, минимум конфигурации — ровно так собираются [[Сборка и публикация плагина|плагины Obsidian]]:

```bash
esbuild main.ts --bundle --outfile=main.js --format=cjs --external:obsidian
```

[^1]: Автор esbuild Evan Wallace (сооснователь и технический директор Figma) написал его отчасти как демонстрацию тезиса "наши инструменты медленные, потому что написаны на интерпретируемом языке, а не потому что задача сложная". Тезис доказан: индустрия массово переписывает тулинг на Go/Rust — esbuild, SWC (Speedy Web Compiler, Rust), Rolldown, Oxc; даже сам tsc переписывается на Go (проект Corsa, обещают ×10)

**Vite** (франц. "быстро", произносится "вит") — надстройка-фреймворк сборки: дефолты, dev-сервер, плагины. Хитрость архитектуры — **в dev не бандлит вообще**: отдаёт браузеру родные ESM-модули по одному (транспилируя на лету esbuild-ом), поэтому старт мгновенный при любом размере проекта; прод-сборка — Rollup-ом со всеми оптимизациями

```bash
npm create vite@latest my-site   # каркас проекта: vanilla-ts, react, …
npm run dev                      # dev-сервер на :5173 c HMR
npm run build                    # прод в dist/
```

> [!note] HMR — горячая замена модулей ^hmr
> **HMR** (Hot Module Replacement): сохранил файл — в браузер по WebSocket прилетает только изменённый модуль, страница не перезагружается, состояние живёт (заполненная форма не сбрасывается). Наш [[Каркас сайта на Vite|сайт в модуле 11]] поедет на Vite — там это почувствуется

## Когда что

| Задача | Инструмент |
|---|---|
| страница из пары файлов, упражнения курса | ничего — браузер сам |
| собрать библиотеку/плагин в один файл | esbuild |
| сайт/приложение с dev-циклом | Vite |
| легаси на работе | webpack (стандарт 2015–2022; медленный, но всемогущий — встретишь) |

> [!tip] Бандл — это артефакт, смотри на него
> `dist/` полезно открывать глазами: что реально уехало в браузер? Анализаторы (`rollup-plugin-visualizer`, esbuild `--metafile`) рисуют карту веса: типичное открытие — "moment.js притащил все локали на 300 КБ". Вопрос "сколько весит зависимость" — часть выбора пакета: bundlephobia.com отвечает до установки
