# Оцифровка курса агентами

Как выглядит заметка, решает стандарт заметок волта; здесь — как курс доходит до заметок: кто что делает, в каком порядке и что считается принятым

## Рабочая папка и инструменты

- Рабочая папка курса — `~/.cache/<курс>-digitization/` вне волта, путь передаётся инструментам через `DIGI_WORK`. В ней источники, расшифровки, карта, адаптированные брифы, файлы находок и `progress.md` со статусом каждого блока: статус переживает сжатие контекста только в файле
- Инструменты (Whisper, переслушивание окна, кадр доски, автосубтитры) и их окружение — `~/Projects/conspect/Scripts/digitization/README.md`. Команды здесь не пересказываются
- Scratch сессии и агентов — scratchpad сессии, не волт: obsidian-git коммитит всё, что легло в волт, за минуты
- Чтение PDF из `~/Projects/conspect/Книги/` — рендером страницы в картинку (`pdftoppm`, тулчейн — в справке стандарта заметок по графике); `pdftotext` портит индексы и формулы, и ошибку источника по нему не заявляют

## Конвейер

1. Подготовка источника — по его виду, ниже
2. Разметка или расшифровка агентами, параллельно по диапазонам
3. Сессия сводит разметку в карту тем: заметка, её тема, папка, блоки или страницы источника. Карту утверждает Хозяин
4. Первая волна — две заметки, они идут Хозяину на стиль. Его решения вписываются в бриф автора до следующей волны
5. Остальные волны — авторы параллельно; каждую партию проверяет верификатор сразу после неё, не в конце курса
6. Правки по находкам, затем opus-проход по diff правок (`briefs/diff-verify.md`)
7. Поиск дублей курса со всем волтом (`briefs/dedupe.md`); решения о владельце — Хозяину
8. Ссылки из других курсов, старые заметки в корзину, MOC, иконки, lint, песочницы
9. Леса удаляются по слову Хозяина; venv остаётся, если на нём работают `.sources/` курса

### Видео

- Аудио, видео и автосубтитры качаются, аудио транскрибирует Whisper, разметка лекций идёт по транскрипту
- Таймкоды — из транскрипта Whisper, а не из разметки по автосубтитрам: та сдвинута на 10–30 с
- Whisper теряет слова, и потеря выглядит как оговорка лектора. Каждую оговорку перед сноской подтверждают автосубтитрами и переслушиванием окна
- Разметка наследует ошибки лектора и путает атрибуцию ("лектор подтверждает"): её утверждения сверяют с транскриптом

### Запись без видео

Если видео не сохраняется, таймкодов в заметках нет совсем. Провенанс — страницы слайдов, схемы со слайдов — rect-вставкой PDF++, справочные таблицы переносятся целиком и сверяются с рендером слайда и первоисточником

### Рукописные сканы

- Сначала постраничная расшифровка в сырой markdown, потом карта и заметки по тексту. К скану возвращаются за рисунками и спорными местами. Один агент на все сканы копит картинки в контексте и сжигает лимит
- Копии для чтения — 1600 px по длинной стороне (`magick -auto-orient -resize 1600x1600`); на 1000 px теряются индексы
- Телефон не пишет EXIF-ориентацию. Лежачий кадр (`width > height`), прочитанный как есть, возвращается с выдуманными формулировками. Такие кадры выпрямляются из оригиналов до раздачи: направление — по дыркам скоросшивателя (слева у лицевой стороны листа, справа у оборотной) и заголовкам, результат проверяется монтажом миниатюр
- Расшифровка — sonnet-агентами по 4–6 страниц (`briefs/scan-transcribe.md`). Пробный батч сессия сверяет сама до запуска остальных

### Фото тетради с телефона

Кадры сортирует сессия по монтажу миниатюр 300 px (`magick montage`). Выпрямление и разрезку разворота на `pNNa`/`pNNb` делает сам агент расшифровки, пачками по 3 фото (`briefs/photo-transcribe.md`). Направление поворота агенты путают в обе стороны, поэтому каждый итоговый скан он открывает и проверяет глазами

### Пособие, блокноты, старые заметки

- Пособие лектора — источник курса: им заполняют пропуски тетради без пометки "не из лекции". Пособие тоже ошибается, и его ошибку заявляют только по рендеру страницы
- Старые заметки, которые Хозяин хочет переписать: авторы пишут вслепую по источнику, затем отдельный агент сверяет со старыми и переносит только верное и ценное, с пометкой по границе своего из `conspect` (`references/course-structure.md` → "Источники и картинки")
- Практика или проект Хозяина — не сырьё для курса: курс ссылается на них в месте механизма и не копирует факты

## Оркестровка

- В сессии одновременно не больше трёх агентов. Освободившееся место сразу занимает следующий блок
- Opus — один и занят верификацией математики, физики и рисунков; авторы и правщики — sonnet. Темп задаёт верификатор: пока он занят, свободные места отдаются авторам и правкам
- Находки верификатора пишутся в `briefs/fix-UN.md` рабочей папки, автору блока уходит SendMessage "прочитай файл": его контекст цел, и сессия не копирует находки дважды. Доработку получает тот же автор, а не новый агент
- Мелкие правки (ссылка, алиас, титул) сессия вносит сама, не занимая место
- Перед каждой партией правок записывается коммит-база — последний коммит до неё: по нему потом строится diff для верификатора
- Системная находка (тема рисунков, общий модуль, повторяющаяся ошибка авторов) чинится у источника — в ките или в брифе, — а не в каждой заметке
- Правило, которое сессия уточняет на ходу, сначала проверяет верификатор: правило, зависящее от формы записи, ломает заметки, написанные по нему

## Брифы

Шаблоны лежат в [references/briefs/](references/briefs/). Пути и имена в них — от курса, на котором они родились: бриф копируется в `briefs/` рабочей папки вместе с `common.md` и адаптируется под курс, а не берётся вслепую. Агент читает бриф по пути одним файлом

Каждый бриф начинается со ссылки на [references/briefs/common.md](references/briefs/common.md): правка файлов только Write/Edit, мутации на копии, scratch, лимит памяти, факты по источнику, отчёт текстом и список частых находок верификатора. Новый бриф без этой ссылки не раздаётся. Нарушение `common.md`, о котором агент сказал в отчёте, возвращается ему, а не принимается молча

## Приёмка

- "Принято" — только после полного прохода. Отчёт о приёмке называет покрытие: доля пересчитанных ответов, открыты ли рисунки в полный размер, прочитан ли текст целиком. Выборка, которая нашла ошибки, — довод за полный проход, а не приёмка
- Рисунки смотрят в полный размер; монтаж миниатюр годится только чтобы найти, что открыть
- Песочницу сессия открывает сама хотя бы в тёмной теме на 390 px: агент считает зелёный `check_page` осмотром, а тот не видит контраста
- Находку верификатора сессия проверяет сама до правки: верификатор тоже ошибается (принимает верный якорь за битый, "исправляет" верное)
- Где нужно суждение (рисунки, физика), проверяет другая модель, чем писала; механическую часть (ответы) — sonnet с python
- Диапазон партии для верификатора — `git log --since=<начало партии> -- <пути>` или `git diff --word-diff=plain <база> HEAD -- <пути>`, а не `git diff` рабочего дерева: obsidian-git коммитит по ходу
- Массовая правка генератором (ссылки, расшифровки аббревиатур) проверяется полностью, каждая ссылка — по смыслу, каждая расшифровка — по первоисточнику. Типовые дефекты: омоним вместо владельца, ссылка в чужую тему, выдуманная расшифровка, вторая ссылка на ту же цель в строке
- Перед массовыми правками снимается копия заметок. Если базы в git нет, пары "было/стало" восстанавливаются из журналов агентов: каждый вызов Edit хранит `old_string` и `new_string`. Отклонённый харнессом файл отчёта агента лежит целиком во входе его вызова Write

## Завершение

- Иконки курса пишет только принимающая сессия. Syncthing не сливает `data.json` плагина Iconic, побеждает последняя версия: перед массовой расстановкой Obsidian на других устройствах закрыт или синхронизация стоит, после — иконки сверяются со всеми `.md` курса и восстанавливаются из `data.json.backupN` и git
- Общий помощник рисунков импортируют скрипты разных тем: перед его правкой — grep по импортёрам, после — прогон всех и сверка PNG
