# Справка — база линтера и проверка рендера

## Принять одну проверку

`lint.py --accept <охват>` записывает в базу **все** находки охвата, любых проверок: настоящая находка рядом с ложной спрячется вместе с ней. Одна проверка принимается так:

```bash
python3 ~/Projects/conspect/.agents/skills/conspect/tools/lint.py --accept --only <код> "<файл1>" "<файл2>"
python3 ~/Projects/conspect/.agents/skills/conspect/tools/lint.py --vault ~/myWiki --accept --only <код> "<файл>"
```

Волтов два, а инструмент один, и по умолчанию он разбирает волт конспектов, в котором живёт сам. Заметки личного волта (дневник, ядра, Zettelkasten) берёт `--vault ~/myWiki`; без флага их приносит абсолютный путь мимо волта конспектов. База у двух волтов одна (`tools/baseline.json`), поэтому пути в ней записаны от корня того волта, к которому принадлежат; записи чужого волта прогон не трогает, в одном прогоне берутся заметки одного волта

Под `--only` и `--skip` принимаются только активные коды, записи остальных остаются. После записи прогон без `--accept` должен по-прежнему показать соседние находки

Список файлов для прогона: шелл агента — zsh, `mapfile` в нём нет, а пустой массив файлов молча расширяет прогон на весь волт. Читай список через `bash -c 'mapfile -t F < list; …'`. `grep` здесь — ugrep: шаблон вида `.{0,90}слово.{0,60}` по кириллице падает с `exceeds complexity limits`, контекст совпадения проще вырезать python-скриптом

## После переноса или переименования

База привязана к путям, поэтому после переноса заметок все их прежние находки выводятся как новые. Свои среди них видны только сверкой со старым коммитом:

1. `git worktree add --detach <scratchpad>/old <коммит до правок>`
2. Обёртка в scratchpad: `import lint; lint.VAULT = Path(argv[1]); lint.BASELINE = <несуществующий файл>; sys.argv = ["lint.py"] + argv[2:]; lint.main()`
3. Прогон `--all` по старым путям в копии и по новым в волте, счёт по классам (`^── code (N)`), сравнение `join`-ом. Выросший класс разбирается построчно `diff`
4. Свои находки исправляются, остальное — `--accept` по затронутым папкам, затем `git worktree remove --force`

В копии нет медиа, вложения вне git: `missing-attachment`, `iconic-dangling` и `alias-collision` с рисунками-`.md` из `00. Вложения` там врут

obsidian-git коммитит по ходу работы, поэтому `git diff HEAD` показывает только последний шаг. Переносы видны через временный индекс: `GIT_INDEX_FILE=<scratch>/idx git add -A`, затем `git diff --cached -M <коммит до правок>`

## Как Obsidian отрисует разметку

Склеились ли callout-ы, стал ли `[!type]` текстом — это проверяется без глаз пользователя. В запущенном Obsidian `app.plugins.plugins.dataview.api.renderValue(markdown, container, …)` прогоняет текст через тот же `MarkdownRenderer`, что режим чтения. Из `container` читается DOM: `.callout` (число, вложенность через `.callout .callout`, `data-callout`), `p`, `li` и `td` с литералом `[!`

Через `obsidian-cli eval` это два вызова: первый запускает рендер и кладёт контейнер в `window.__r`, второй читает и удаляет `window.__r`. Live Preview так не проверяется — его рендерит CodeMirror, а не `MarkdownRenderer`, и его смотрит пользователь
