# Справка — callout-блоки Obsidian

Главный инструмент структурирования заметок. Используются **активно**: по статистике на волте — ~91 `note`, ~76 `summary`, ~63 `tip`, далее `warning`, `success`, `quote`, `faq`, `danger`, `important`

## Какой тип для чего

Полный список типов, алиасов и цветов, а также базовый синтаксис (`> [!note] Заголовок`, `+`/`-`, вложенность через `> >`) — общий Obsidian-синтаксис, справка в скилле `obsidian-markdown` (`references/CALLOUTS.md`). Здесь — только назначение каждого типа в этом волте:

| Тип | Назначение | Где применять |
|---|---|---|
| `note` | определения, формулировки, нюансы | основной callout для учебных определений |
| `summary` | краткая выжимка, итог блока, формулировка теоремы через `boxed` | вывод раздела, формулировка теоремы |
| `info` | дополнительный контекст, замечание | побочное замечание |
| `todo` | список дел | в проектных заметках, дневнике |
| `tip` | следствие, лайфхак, мнемоника, мост | "это следствие из...", "обрати внимание", в дневнике — осознание |
| `success` | доказанная теорема, рабочий результат, **доказательство/вывод** | теорема об эквивалентности, готовый алгоритм, `[!success]- Доказательство` |
| `question` | упражнение или задача; вопрос, проверка понимания | `[!question]+ Упражнение` с решением внутри, риторические вопросы в дневнике, "а что если" |
| `warning` | предупреждение, типичные ошибки, оговорки об обозначениях | "будем использовать сокращения...", "не путать с..." |
| `failure` | неудача, контрпример | самокритика в дневнике, контрпример |
| `danger` | категорически запрещено | БЖД, медицина, инструкции — "Не вскрывать пузыри!" |
| `bug` | странность, контр-интуитивное поведение | мелкие "косяки" в дневнике |
| `example` | разобранный пример, иллюстрация концепции | "Кубик и крупье", "Пример: нормальное распределение", алгоритм решения |
| `quote` | прямая цитата | Сапольский, Лютер, лектор |
| `experiment` | опыт, демонстрация, случай из жизни, который лектор приводит по ходу теории | "Почему лёд плавает"; свой тип волта, цвет и иконку даёт сниппет `.obsidian/snippets/callouts.css` |

### Заголовок как сама мысль

Часто в учебных заметках весь смысл — в заголовке, тело отсутствует:

```markdown
> [!summary] $x_{6}\bar{x}_{7}x_{9}$ — элементарная дизъюнкция

> [!tip] У сопряжённых уравнений соответствующие собственные числа также сопряжены
```

**Не придумывается содержательное имя — выноси сам факт в заголовок как хайлайт.** Мета-обёртка ("Три синонима", "Замечание", "Важно") не несёт информации — её всё равно надо разворачивать в теле. Лучше поднять главную мысль первой строкой в заголовок, остальное — телом:

```markdown
❌ > [!tip] Три синонима
   > Для функции одной переменной **дифференцируемость**, **существование производной** и **существование дифференциала** — одно и то же
   > Для функций нескольких переменных это уже не так — дифференцируемость строго сильнее существования частных производных

✅ > [!tip] Для функции одной переменной **дифференцируемость**, **существование производной** и **существование дифференциала** — одно и то же
   > Для функций нескольких переменных это уже не так — дифференцируемость строго сильнее существования частных производных
```

**Без мета-ярлыка и кавычек-пугалок.** Заголовок называет суть напрямую: не "Рецепт", "Трюк", "Приём", "Ключ" как ярлык перед собственной фразой в кавычках. Выше мы поднимаем факт в заголовок, когда имени нет вовсе, здесь — снимаем обёртку с имени, которое есть:

```markdown
❌ > [!tip] Рецепт "Делим на старшую степень"
❌ > [!tip] Трюк "ε/2"
❌ > [!tip] Ключ — "развести окрестности"
✅ > [!tip] Делим на старшую степень
✅ > [!tip] Трюк ε/2
✅ > [!tip] Развести окрестности
```

**Но не обрубай заголовок до криптичности — ясность важнее краткости.** Тире-эллипсис, заменяющее глагол или связку, делает заголовок непонятным: из него уже не считать мысль с одного взгляда. Пиши полную фразу:

```markdown
❌ > [!warning] На концах интервала $q=1$ — признак молчит
✅ > [!warning] На концах интервала $|x|=R$ признак не работает

❌ > [!success] Сумма и масштаб — радиус не меньше минимального
✅ > [!success] При сложении и умножении на число радиус не меньше минимального из двух
```

Режется именно **эллипсис**, проглатывающий смысл. Тире-связка ("$\alpha$ — любое вещественное", "$f$ — сумма своего ряда Тейлора") читается ясно — её не трогаем. Метод доказательства в титуле — фраза без тире, а не ярлык с хвостом:

```markdown
❌ > > [!success]- Доказательство — через теорему Коши
❌ > > [!success]- Доказательство — монотонность + теорема Вейерштрасса
✅ > > [!success]- Доказательство через теорему Коши
✅ > > [!success]- Доказательство через монотонность и теорему Вейерштрасса
```

## Сворачиваемые callout

Синтаксис `+`/`-` за типом — `obsidian-markdown` (`references/CALLOUTS.md` → "Foldable Callouts"). Здесь — когда какой уместен в этом волте:

### Когда `+`

- Развёрнутый разобранный пример, который держим открытым
- Длинная справка, которую читатель должен видеть сразу

### Когда `-`

- **Доказательство / вывод — всегда `-`** (свёрнуто по умолчанию): заголовок-результат виден, выкладка прячется под кат
- Пометка "Без доказательства" — `references/theorem-proof-patterns.md` → "Теорема без доказательства"
- Второстепенное уточнение, побочное замечание
- Длинное следствие, которое отвлекает от основного потока
- В дневнике — `[!question]-` для разбора "что именно произошло" под спойлером, когда основные рассуждения выше
- Расширенные ссылки/источники

> [!tip] Свёрнутость — по роли, а не по типу
> Один и тот же тип не должен скакать между голым / `+` / `-`. Держи единообразно: **определение, формулировка, итог-хайлайт → голый** (без `+`/`-`); **доказательство/вывод → `-`**; длинное второстепенное → `-`. То же и для других типов, не только `success`

## Вложенные callout

Активный приём. Внутри одного блока — другой через `> >`. Обычно хватает двух-трёх уровней; глубже — редкость вроде эскалации в дневнике (`presets/diary.md` → "Эскалация callout"):

```markdown
> [!summary] Главное утверждение
> Формулировка
>
> > [!note] Уточнение по терминологии
> > Деталь определения
> >
> > > [!tip] И ещё глубже
> > > Подсказка
```

Перед вложенным callout стоит **пустая строка на уровне родителя**: одиночный `>` перед `> >`-блоком, `> >` перед `> > >`-блоком. Это стиль волта, а не требование рендера: Obsidian откроет вложенный callout и сразу за текстом родителя. Разделитель держит исходник читаемым, а волт единообразным, поэтому его ставят всегда. Пропуск показывает `tools/lint.py` (`nested-callout-no-blank`, уровень "посмотри")

```markdown
✅ стиль волта           ⚠️ рендерится, но не стиль волта
> [!note]               > [!note]
> text                  > text
>                       > > [!success]
> > [!success]          > > ...
> > ...
```

Соседние callout одного уровня разделяет та же строка уровнем выше — у верхних пустая без `>`, у `> >`-блоков одиночный `>`; строка своего уровня, даже голая `>`, блок не закрывает, и Obsidian рендерит следующий `[!type]` текстом внутри предыдущего (`callout-no-blank`)

## Шпаргалка — какой callout под задачу

### Учебная заметка

- Определение / формулировка → `[!note]` (НЕ `[!definition]` — нестандартный тип, рендерится дефолтно; для определений всегда `note`)
- Теорема (формулировка) → `[!summary]` с `boxed`
- Теорема (доказанная, результат) → `[!success]`
- **Доказательство / вывод → `[!success]-`** (свёрнуто по умолчанию, НЕ `[!example]`), вложенный через `> >` внутрь callout-а утверждения, которое доказывает (с пустой строкой-разделителем `>` перед ним)
- Теорема дана без вывода → пометка "Без доказательства" (`references/theorem-proof-patterns.md`)
- Следствие, мостик, удобный лайфхак, важное замечание → `[!tip]`
- Альтернативные теоремы, неочевидные ключевые утверждения → `[!important]`
- Соглашение об обозначениях, типичная ошибка, исключение → `[!warning]`
- Разобранный пример / иллюстрация → `[!example]` (именно пример-иллюстрация, не доказательство и не задача)
- Упражнение / задача ("найти", "доказать") → `[!question]+`, решение вложено через `> > [!success] Решение`; голой постановку не оставляем — решаем и расписываем шаги. Свёрнутость решения — по важности задачи, это исключение из "Свёрнутость — по роли, а не по типу": простое и рутинное `-`, важное `+`
- Вопрос-ответ, заметки к размышлениям → `[!faq]`; замечание, дополнительный контекст → `[!info]`
- Цитата лектора → `[!quote]`
