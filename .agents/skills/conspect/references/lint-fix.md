# Справка — `lint.py --fix`

Обычный прогон `lint.py` только подсказывает и файлов не меняет. С флагом `--fix` он сам исправляет находки, правка которых механическая и смысла текста не касается; всё остальное по-прежнему правится руками

## Что исправляет

Какие проверки `--fix` умеет исправлять, показывает сам инструмент: в `--list-checks` они помечены `[--fix]`. Список живёт в словаре `FIXERS` в `tools/lint.py` и здесь не повторяется, чтобы не разойтись с ним

## Что сохраняется

- Хвостовые пробелы последней строки: в markdown два пробела в конце строки — это перенос
- Окончания строк: файл читается и пишется байт в байт, и CRLF-файл получает недостающий `\r\n`, а не `\n`
- Пустой файл остаётся пустым
- Повторный запуск ничего не меняет

## Охват

`--fix` правит ровно то, что попало в охват прогона: пути из аргументов и фильтры `--only` / `--skip`. Дневник, как и при обычном прогоне, не трогается, пока `~/myWiki/03. Записки/01. Дневник` не назван явно — а попасть в другой волт можно только с `--vault`, поэтому дневник правится лишь так: `--vault ~/myWiki "03. Записки/01. Дневник"`

Не исправляется и то, чего инструмент не разбирает вовсе, даже если путь назван явно: заметки без пресета (`Статьи`, `Книги`, `Scripts`, `Templates`, `01. Data`, `04. Книжная полка`, папки вложений — см. `PRESET_TABLE` в `lint.py`), словари FSRS Vocabulary и всё служебное из `SKIP_PARTS` (`.obsidian`, `.agents`, `.trash` и прочее)

```bash
L=~/Projects/conspect/.agents/skills/conspect/tools/lint.py
python3 $L --fix                                            # весь волт без дневника
python3 $L --vault ~/myWiki "03. Записки/01. Дневник" --fix  # дневник
python3 $L --fix --only eof-newline                         # только одна проверка
```

## Как проверить

Волт под git, поэтому вся правка видна в `git diff`. Повторный прогон с тем же охватом не должен находить исправленных кодов
