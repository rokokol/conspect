# Пресет — Zettelkasten-заметка

Применяй для файлов в `~/myWiki/02. Zettelkasten/`. Атомарные мысли, идеи, шпаргалки, рабочие заметки

> [!important] Что такое атомарность 🧬
> Одна заметка — одна мысль / один объект / одна идея. Если хочется добавить вторую — заведи отдельную заметку и **залинкуй**
>
> Заметка должна быть **полезна сама по себе**, без контекста. Если читатель открыл её через год — она должна быть понятна

## Что сюда не входит

Из core rule в дневнике `2026-05-11 Monday.md` — что **не** идёт в Zettelkasten:
- Ежедневные мысли о настроении и событиях дня → в дневник
- Мысли, относящиеся к конкретному человеку/проекту/событию → в соответствующее ядро (`presets/hub.md`)
- Конспект курса/лекции → в конспекты (`presets/lecture.md`)

В Zettel остаётся:
1. Самостоятельные (независимые от личности и текущего контекста) философские мысли и озарения
2. Шпаргалки (как `Доступные чекбоксы и callouts`)
3. Размышления, которые нельзя отнести к ядрам или конспектам
4. Рабочие заметки с разбором задачи (как `Метод Шварца и идея Федотова`)
5. Списки правок по проектам (как `НИР`)

## Метаданные

Минимум — `created`, теги — когда есть сквозное свойство (`SKILL.md` → "### Теги"):

```yaml
---
tags:
  - <тематический тег>     # читлист / стих / личное / прога / ...
created: 2026-05-22
aliases:
  - <короткое имя>          # опционально
---
```

Никаких `prev`/`next` — Zettel связан не цепочкой, а графом ссылок

## Структура

Жёсткой нет. Скелет по типу:

### Самостоятельная философская мысль / стих

```markdown
# <Тема / название>
<Контекст: откуда взялась мысль, в какое настроение>

<Развёрнутая мысль — поток или структурированный текст>

> [!quote] <Цитата, если есть>
> *<Автор>*
```

### Шпаргалка / справка

```markdown
# <Что это>

## <Раздел>
<Перечень с примерами>

## <Раздел>
...
```

(`Доступные чекбоксы и callouts.md`)

### Рабочая заметка / разбор задачи

```markdown
# <Тема>
## Идея
<Постановка>

## Работа
### <Подраздел>
<Выводы с формулами, кодом, рисунками>

> [!note] <Промежуточный вывод>
> ...

---

<Свободный итог / открытые вопросы>
```

(`Метод Шварца и идея Федотова.md`)

### Список правок по проекту

```markdown
---
created: <дата>
---
# <Проект — что нужно сделать>
## Новые правки
- <пункт>
- <пункт>

## Правки
- <ранее зафиксированные>

## Что нужно сделать
1. <чек>
```

(`НИР.md`)

## Тон

Свобода. От первого лица. Можно с эмоциями, эмодзи, html-эффектами, матом в редких эмоциональных пиках. Но мысль должна быть **доводимая до конца** — Zettel не место для оборванных идей

## Обязательные ссылки наружу

**Не** отдельная секция в заметке — линкуй инлайн по ходу текста, там, где термин встретился

> [!tip] Главное правило Zettel — каждая заметка ведёт наружу
> Если в заметке нет ни одной wiki-ссылки — она либо первичная (стих, шпаргалка), либо плохая ⚠️
>
> Линкуй на источниковые заметки терминов, на ядра упомянутых людей, на смежные мысли в Zettel, на конспекты теорем

## Блок-якоря

Блок-якорь `^id` — основной инструмент ссылок в Zettel: так ссылаются на конкретную мысль внутри заметки, а не на всю заметку. Как ставить и чего якорями не делать — `references/wikilinks.md` → "Блок-якоря"

## Inbox

`~/myWiki/02. Zettelkasten/01. Inbox/` — буферная зона. Сюда падают `Untitled.md` и черновики, из которых потом мысль либо доводится и переезжает в основную папку Zettel, либо в дневник как мимолётное, либо удаляется. Не оставляй Inbox разрастаться: по правилу из дневника `2026-05-11 Monday.md` Inbox это **источник** для сортировки, не свалка

## Чек-лист

- [ ] Заметка раскрывает **одну** мысль/объект
- [ ] Понятна без контекста разговора, в котором появилась
- [ ] Есть минимум 1-2 wiki-ссылки наружу (или это первичный материал — стих/шпаргалка)
- [ ] H1 = тема заметки
- [ ] `created` стоит, теги — только сквозные свойства
- [ ] Точки в концах абзацев убраны
