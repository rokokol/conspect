# Iconic — иконки файлов и папок

Плагин [Iconic](https://github.com/gfxholo/iconic) рисует иконки рядом с файлами/папками в файловом дереве, вкладках, заголовках, подсказках. Вся раскладка иконок хранится в одном JSON, а меняет её `tools/iconic.py` через запущенный Obsidian

> [!tip] Какую иконку *выбрать* — `references/typical-icons.md`
> Этот файл — про **механику** (формат `data.json`, наборы, цвета, рецепты правки). За *выбором* конкретной иконки (словарь "учёный → эмодзи-человечек" для именных теорем, предметные эмодзи-метафоры распределений, lucide по темам) иди в [`references/typical-icons.md`](references/typical-icons.md)

## Где лежит и чем менять

Раскладка лежит в `.obsidian/plugins/iconic/data.json`. Пока Obsidian открыт, источник истины — настройки плагина в памяти: каждое сохранение плагина пишет их в файл целиком. Поэтому файл при открытом Obsidian напрямую не правим — запись в него гоняется с плагином:

- Obsidian замечает внешнюю запись в `data.json` и перечитывает файл в память. Изменение из UI, которое плагин ещё не сохранил, при этом молча пропадает: иконка, поставленная через API плагина, исчезла и из памяти, и с диска, когда через 50 мс внешний скрипт записал файл
- сохранение плагина, начатое до внешней записи, может положить поверх неё старое состояние

Читать `data.json` можно свободно, менять — только `tools/iconic.py`. Он меняет настройки в памяти плагина тем же путём, что и UI (`updateIconSetting`, затем `saveSettings`), через `obsidian-cli eval`, дожидается записи и сверяет `data.json` на диске с ответом приложения. Подкоманды, формат спеки и коды выхода — в `python3 .agents/skills/iconic/tools/iconic.py --help`. Что из этого нужно знать заранее:

- Путь — точный ключ плагина: заметка с расширением, папка без слэша на конце, `/` для корня волта. Иконку или цвет на несуществующий путь скрипт не ставит, а снять висячий ключ даёт
- Каждая правка печатает `undo` — спеку, которая возвращает прежние записи через `apply`. Перед пачкой сохрани её в файл, тогда откат — одна команда
- Сначала скрипт проверяет все пути пачки и только потом пишет, поэтому отказ не оставляет пачку записанной наполовину. Большую спеку он шлёт частями, каждая часть — одно сохранение плагина
- Транспорт CLI иногда бьёт многобайтовые символы в длинной команде (кириллица и эмодзи превращаются в U+FFFD, а код всё равно выполняется). Скрипт режет команды до 30 КБ, приложение отказывается выполнять запрос с U+FFFD, и скрипт шлёт его заново. Поэтому свой `eval` с длинной кириллицей или эмодзи в `obsidian-cli` для правки иконок не пиши
- Плагин держит до 5 бэкапов `data.json.backupN` (поле `maxBackups`) и делает новый при сохранении, если прошлому больше 3 часов; самый старый при этом удаляется. Бэкапы в git не идут: они в `.gitignore` волта

### Obsidian не запущен

CLI говорит только с запущенным приложением, и без него скрипт выходит с кодом 3. Лучше всего запустить Obsidian и повторить. Если он должен остаться закрытым, `--offline` правит `data.json` напрямую по тем же правилам слияния и в том же порядке ключей, что и плагин. Это безопасно, потому что настройки в памяти никто не держит, а при запуске плагин прочитает файл. Компромисс:

- Скрипт отличает "Obsidian закрыт" только по ответу CLI. Если Obsidian открыт, а CLI до него не достаёт (например, CLI выключен в настройках), `--offline` снова гоняется с плагином. Поэтому `--offline` — только когда точно известно, что Obsidian закрыт
- Существование пути проверяется по диску, а не по индексу Obsidian, и бэкап плагина не делается
- Syncthing везёт `data.json` на второй хост, и там открытый Obsidian перечитывает его так же, как при любой внешней записи

## Структура data.json

```json
{
  "fileIcons": {
    "<путь от корня волта>": { "icon": "...", "color": "...", "unsynced": [...] }
  },
  "appIcons": {}, "tabIcons": {}, ...
}
```

- **Ключ** — путь от корня волта: для заметки с расширением (`01. Математический анализ/content/01. Множества и числа/Множества и числа.md`), для папки без (`01. Математический анализ/00. Вложения`). Кириллица как есть
- **`icon`** (обязательно) — идентификатор иконки (см. ниже). Может отсутствовать, если задан только `color` (тогда красится дефолтная иконка)
- **`color`** (опционально) — имя цвета или RGB
- **`unsynced`** (опционально) — список device-id, на которых иконка не синкается; не трогаем, плагин ведёт сам

Ключ — это путь, и переименование или перенос через Obsidian плагин отслеживает сам: после `obsidian-cli rename` файла и `app.fileManager.renameFile` папки `tools/iconic.py get` показал ключи на новых путях, у папки — вместе с ключами файлов внутри неё, а старые пути пусты. Перенос мимо Obsidian, `mv` в шелле, приложение видит как удаление и создание: плагин удаляет ключ из памяти, новому пути иконку не даёт, и иконка теряется. Поэтому файлы и папки с иконками переносятся только через Obsidian. Ключи, указывающие в несуществующий путь, показывает `tools/lint.py` скилла `conspect` (`iconic-dangling`)

## Типы иконок (`icon`)

1. **Lucide** — `lucide-<name>`, основной набор (иконки с [lucide.dev](https://lucide.dev)). Большинство заметок. Примеры из волта: `lucide-sigma`, `lucide-function-square`, `lucide-mountain`, `lucide-route`, `lucide-diff`, `lucide-ruler`, `lucide-boxes`, `lucide-spline-pointer`, `lucide-rotate-3d`, `lucide-waypoints`
2. **Эмоджи** — сам символ, включая ZWJ-последовательности: `👨‍🎨`, `🧔‍♂️`, `🇬🇧`, `♾️`, `🕸️`, `📐`. Вставляются как есть в значение
3. **Доп. наборы** (зарегистрированные иконки, не lucide и не эмоджи) — короткие имена без префикса `lucide-`. В волте встречаются: `math-function`, `math-integral-x`, `math-x-divide-y-2` (математические), `code-dots`, `arrowtab`, `arrowenter`, `dice`, `distribute-space-vertical`, `stretch-horizontal`, `moveColumnRight`, `excalidraw-icon`. Использовать, когда математический символ точнее lucide (интеграл, дробь)

> [!tip] Откуда брать валидные имена
> Безопаснее всего — **взять иконку из уже используемых в волте** (`grep '"icon"' data.json`). Так гарантированно валидное имя и эстетика пользователя. Базовые lucide-имена (`lucide-layers`, `lucide-waves`, `lucide-grid-3x3`, `lucide-eye-off`) тоже надёжны. Несуществующее имя плагин просто не отрисует — ошибки не будет, но иконки не появится, поэтому проверяй визуально в Obsidian при сомнении

## Цвета и цветные эмоджи

`color` принимает **именованные** цвета (как у пользователя): `yellow`, `red`, `green`, `pink`, `gray`, `blue` (палитра Obsidian; настройка `colorPicker1: "list"`). Также поддерживается **RGB** (`colorPicker2: "rgb"`) — формат `"rgb(R, G, B)"` или hex

**Цветной эмоджи** = эмоджи в `icon` + `color` рядом (цвет тонирует фон/акцент). Реальные применения пользователя — ориентир по вкусу:

| Icon | Color | Где |
|---|---|---|
| `📐` | `yellow` | Тригонометрические формулы |
| `🛏️` | `red` | дневник, день отдыха |
| `🇬🇧` | `green` | дневник, день английского |
| `📚` | `pink` | дневник, день учёбы |
| `👨‍🎤` | `yellow` | Формула Ньютона–Лейбница |
| `♾️` | `gray` | несобственный интеграл |
| `🔄` | `yellow` | Теория поля |
| `🪩` | `blue` | формула Остроградского–Гаусса |
| `🕸️` | `yellow` | случайный граф |
| `👌` | `gray` | классическая вероятность |

## Конвенции волта

- **Папки `00. Вложения`** (центральные и локальные по темам) — иконка `lucide-boxes`, коробки. Ставится всем папкам вложений для единообразия
- **Папки курсов** — тематические: матан `math-function`, тервер `lucide-dices`, `content` → `lucide-folder-tree`
- **Заметки** — по смыслу темы, иконка-метафора: ряды → `lucide-sigma`, интеграл → `math-integral-x`, экстремум → `lucide-mountain`, кривая → `lucide-route`, мера → `lucide-ruler`, сравнение → `lucide-diff`, 3D/дифференцируемость → `lucide-rotate-3d`, цепное правило → `lucide-waypoints`. Эмоджи — для характерных заметок (люди, шутки, ключевые формулы), часто с цветом

## Рецепты

Команды ниже запускаются из корня волта; `ICONIC` — путь к скрипту, `<tmp>` — временный каталог вне волта (scratchpad сессии):

```bash
ICONIC=.agents/skills/iconic/tools/iconic.py
```

**Найти файлы курса без иконки** (set-разница диска и ключей, только чтение):

```python
import json, os
fi = json.load(open(".obsidian/plugins/iconic/data.json", encoding="utf-8"))["fileIcons"]
course = "01. Математический анализ"
miss = [os.path.relpath(os.path.join(dp,f),".")
        for dp,_,fs in os.walk(course) for f in fs
        if f.endswith(".md") and os.path.relpath(os.path.join(dp,f),".") not in fi]
print(len(miss)); [print(m) for m in sorted(miss)]
```

**Поставить, сменить, снять** — одна иконка или одна и та же на много путей:

```bash
python3 $ICONIC set "<путь>.md" --icon lucide-sigma            # просто иконка, цвет не трогает
python3 $ICONIC set "<путь>.md" --icon "📐" --color yellow      # цветной эмоджи
python3 $ICONIC unset "<путь>.md" --color                       # снять только цвет
python3 $ICONIC unset "<путь>.md"                               # убрать запись целиком
python3 $ICONIC get "<путь>.md"                                 # что стоит сейчас
```

**Пачка с разными иконками** — собрать спеку `{путь: {"icon": ..., "color": ...} | null}` и применить одной командой. Пример: значок коробки всем `00. Вложения` курса:

```python
import json, os
course = "01. Математический анализ"
spec = {os.path.relpath(os.path.join(dp, d), "."): {"icon": "lucide-boxes"}
        for dp, dirs, _ in os.walk(course) for d in dirs if d == "00. Вложения"}
json.dump(spec, open("<tmp>/spec.json", "w", encoding="utf-8"), ensure_ascii=False)
```

```bash
python3 $ICONIC apply <tmp>/spec.json > <tmp>/result.json   # в result.json — after и undo
```

**Вернуть потерянные иконки** — внешняя запись `data.json` при открытом Obsidian молча роняет ключи. После большой правки иконок соберите ключи из бэкапов плагина и git-истории файла и верните те, чей файл цел, а ключа нет:

```python
import json, os, subprocess
cfg = ".obsidian/plugins/iconic/data.json"
now = json.load(open(cfg, encoding="utf-8"))["fileIcons"]
hist = {}
revs = subprocess.run(["git","log","--format=%H","--since=1.week",cfg], capture_output=True, text=True).stdout.split()
for r in reversed(revs):
    hist.update(json.loads(subprocess.run(["git","show",f"{r}:{cfg}"], capture_output=True, text=True).stdout)["fileIcons"])
for b in sorted(f for f in os.listdir(os.path.dirname(cfg)) if f.startswith("data.json.backup")):
    for k,v in json.load(open(os.path.join(os.path.dirname(cfg),b), encoding="utf-8"))["fileIcons"].items():
        hist.setdefault(k,v)
lost = {k: {f: v[f] for f in ("icon","color") if f in v}
        for k,v in hist.items() if k not in now and os.path.exists(k)}
json.dump(lost, open("<tmp>/lost.json", "w", encoding="utf-8"), ensure_ascii=False, indent=2)
```

Сначала покажите `lost` пользователю: удалённую нарочно иконку это тоже вернёт. Потом `python3 $ICONIC apply <tmp>/lost.json`

> [!note] zsh-грабли при сборе имён через bash
> В zsh `for f in $var` **не** разбивает строку на слова. Перебирай через `while IFS= read -r f` или массивы — иначе вся пачка имён склеится в одну итерацию
