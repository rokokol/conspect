# Набор машинных команд IA-32 и Intel 64

## Группы команд

Классификация слайда (стр. 160) повторяет главу 5 "Instruction Set Summary" первого тома Intel [[Формат машинной команды IA-32|SDM]][^groups]:

- **Команды общего назначения**
  - передачи данных
  - двоичной арифметики
  - двоично-десятичной (BCD, Binary-Coded Decimal) арифметики
  - логические
  - побитового сдвига и вращения (циклического сдвига)
  - работы с битами и байтами
  - передачи управления
  - работы со строками
  - управления флагами
  - дополнительные
- **Системные команды**
- **Команды [[Регистры процессора#Регистры блока с плавающей точкой|x87 FPU]]**
- **Команды управления состоянием x87 FPU и [[Классификация Флинна|SIMD]]** — FXSAVE и FXRSTOR, сохранение и восстановление регистров FPU, [[Арифметико-логическое устройство|MMX]] и [[Арифметико-логическое устройство|SSE]]
- **Команды [[Регистры процессора#Регистры MMX и SSE|MMX]]**
- **Команды SSE, SSE2, SSE3** — и далее SSSE3, SSE4, **AVX** (Advanced Vector Extensions), AVX-512, которых на слайде нет

Мнемоники всех арифметических команд блока с плавающей точкой начинаются с буквы F — floating point[^f-lecture]

[^groups]: [Intel SDM, Vol. 1, глава 5](https://cdrdv2.intel.com/v1/dl/getContent/671436), редакция 253665-092US; состав группы "x87 FPU and SIMD State Management" — §5.3. Номера разделов SDM ниже — по редакции 325383-092US (июнь 2026)

[^f-lecture]: Лектор, 02.12.2024

## Какая команда реализует A = A + B

Запись `A = A + B` в программе не определяет машинную команду однозначно. Компилятор выбирает её по совокупности факторов, и пока переменные не описаны, выбрать нечего[^factors]:

1. **Тип данных** — целые, вещественные или "смешанные": целое плюс вещественное
2. **Формат данных** — для целых байт, слово, двойное слово; для вещественных [[Системы счисления и форматы данных#Вещественные числа|одинарная, двойная или расширенная точность]] (f32, f64, f80). Разная длина операнда — разный алгоритм сложения
3. **Источник операндов** — регистр, память, непосредственный операнд или их сочетание
4. **Способ выполнения** — скалярная обработка, одна пара чисел за команду, или векторная: одна команда над целым упакованным вектором[^vector]

Три семейства, на которых слайды показывают разнообразие кодировок, — ADD для целых, FADD/FADDP/FIADD для x87 FPU и ADDPS для упакованных векторов

[^factors]: Разбор лектора, 02.12.2024

[^vector]: Лектор (запись 02.12.2024) говорит, что для векторов и строк нужно "поставить префикс и организовать циклическое выполнение действий над всем набором данных". Так работают строковые команды с [[Формат машинной команды IA-32#Блокировка и повторение|префиксом повторения]], которые повторяют скалярную операцию для каждого элемента. SIMD-команда вроде ADDPS устроена иначе — она складывает все элементы вектора за одно выполнение, без префикса повторения и без цикла ([Intel SDM, Vol. 2A, "ADDPS": "Adds four, eight or sixteen packed single precision floating-point values from the first source operand with the second source operand"](https://cdrdv2.intel.com/v1/dl/getContent/671110))

Обозначения справочника SDM:

| Обозначение | Смысл |
| --- | --- |
| `ib`, `iw`, `id` | Непосредственный операнд 1, 2 или 4 байта после ModR/M, [[Формат машинной команды IA-32\|SIB]] и смещения |
| `/0`…`/7` | Байт ModR/M, в поле Reg которого стоит эта цифра — продолжение кода операции |
| `/r` | Байт ModR/M с регистром в поле Reg и регистром или памятью в R/M |
| `r/m8`, `r/m32`… | Регистр или операнд в памяти указанного размера — поля Mod и R/M |
| `r8*` | Байтовый регистр в команде с REX: вместо AH, CH, DH, BH доступны SPL, BPL, SIL, DIL |
| `Valid` / `N.E.` | Команда допустима / не кодируется (not encodable) в данном режиме |

Столбец Op/En (operand encoding) говорит, из какого поля команды берётся каждый операнд. Результат всегда записывается на место первого: если первый операнд в памяти, то и результат в память, если в регистре — в регистр

| Op/En | Операнд 1 | Операнд 2 |
| --- | --- | --- |
| RM | ModRM:reg (r, w) | ModRM:r/m (r) |
| MR | ModRM:r/m (r, w) | ModRM:reg (r) |
| MI | ModRM:r/m (r, w) | imm8/16/32 |
| I | AL/AX/EAX/RAX | imm8/16/32 |

(r, w) — операнд читается и записывается, (r) — только читается. Третьего и четвёртого операнда у ADD нет

Один и тот же код `05` складывает AX или EAX — различает их не код операции, а текущий размер операнда: атрибут сегмента кода и префикс 66H[^05-lecture]. Два операнда в памяти ADD не принимает ни в одной строке

[^add-table]: Слайд воспроизводит более раннюю редакцию SDM. В редакции 325383-092US строк "REX + 80 /0 ib", "REX + 00 /r" и "REX + 02 /r" уже нет — вместо них сноска к r/m8 и r8: "With a REX prefix in 64-bit mode, attempts to access AH, BH, CH, or DH will instead access SPL, DIL, BPL, or SIL, respectively" ([Intel SDM, Vol. 2A, "ADD—Add"](https://cdrdv2.intel.com/v1/dl/getContent/671110)). В строке "REX + 80 /0 ib" слайд описывает операнд как "sign-extended imm8" — для байтового приёмника расширять нечего, в таблице описание дано по смыслу. Операнды с "r/m8\*" на слайде и в старой редакции сопровождались той же оговоркой про AH, CH, DH, BH

### Битовые форматы ADD

Нижняя таблица на стр. 163 — та же команда в битовой записи приложения B SDM, где видны поля [[Формат машинной команды IA-32#Поля внутри кода операции|w, d и s]][^add-b]

| Операция | Кодировка |
| --- | --- |
| register1 to register2 | 0000 000w : 11 reg1 reg2 |
| register2 to register1 | 0000 001w : 11 reg1 reg2 |
| memory to register | 0000 001w : mod reg r/m |
| register to memory | 0000 000w : mod reg r/m |
| immediate to register | 1000 00sw : 11 000 reg : immediate data |
| immediate to AL, AX, or EAX | 0000 010w : immediate data |
| immediate to memory | 1000 00sw : mod 000 r/m : immediate data |

- Бит **d** (бит 1): 0 — приёмник в R/M (коды 00, 01), 1 — приёмник в Reg (коды 02, 03). Отсюда две кодировки одной `add eax, ebx`: `01 D8` и `03 C3`
- Бит **w** (бит 0): 0 — байт (00, 02, 04, 80), 1 — слово полного размера (01, 03, 05, 81, 83)
- Бит **s** (бит 1 в 1000 00sw): 1 — 8-битный непосредственный операнд расширяется знаком (83). Сочетание s = 1, w = 0 даёт код 82 — в 32-битном режиме objdump декодирует `82 C0 01` как `add al, 1`, а в 64-битном как недопустимый `(bad)`

Лектор разбирает таблицу по строкам: код 04 — сложение содержимого AL с байтом непосредственного операнда; `MI` — операнд из памяти с непосредственным операндом; `RM` и `MR` — регистр с памятью в двух порядках, от которого зависит, куда записан результат[^add-lecture]

[^add-b]: [Intel SDM, Vol. 2D, Table B-13 "General Purpose Instruction Formats and Encodings for Non-64-Bit Modes"](https://cdrdv2.intel.com/v1/dl/getContent/671110). В 64-битной Table B-15 той же редакции строки ADD для 64-битных операндов содержат ошибки, похоже скопированные из соседней ADC: "qwordregister1 to qwordregister2 0100 1R0B 0000 0000", хотя `add rbx, rcx` — это `48 01 CB`, а не 00; "immediate32 to qwordregister … 11 010 qwordreg" и "immediate32 to memory64 … mod 010 r/m" с полем Reg = 010, то есть `/2` — это ADC, а не ADD `/0`. Верные коды — в таблице ADD выше и в справочнике команд SDM

[^add-lecture]: Лектор, 02.12.2024

## FADD, FADDP, FIADD

Сложение на [[Регистры процессора#Регистры блока с плавающей точкой|стеке регистров x87 FPU]] (стр. 164). ST(0) — вершина стека, ST(i) — i-й регистр от вершины

| Код | Команда | 64-Bit Mode | Compat/Leg Mode | Описание | Байты примера |
| --- | --- | --- | --- | --- | --- |
| D8 /0 | FADD m32fp | Valid | Valid | Прибавить m32fp к ST(0), результат в ST(0) | `fadd dword [eax]` — D8 00 |
| DC /0 | FADD m64fp | Valid | Valid | Прибавить m64fp к ST(0), результат в ST(0) | `fadd qword [eax]` — DC 00 |
| D8 C0+i | FADD ST(0), ST(i) | Valid | Valid | Сложить ST(0) и ST(i), результат в ST(0) | `fadd st0, st3` — D8 C3 |
| DC C0+i | FADD ST(i), ST(0) | Valid | Valid | Сложить ST(i) и ST(0), результат в ST(i) | `fadd st3, st0` — DC C3 |
| DE C0+i | FADDP ST(i), ST(0) | Valid | Valid | Сложить ST(0) и ST(i), результат в ST(i), вытолкнуть стек | `faddp st3, st0` — DE C3 |
| DE C1 | FADDP | Valid | Valid | Сложить ST(0) и ST(1), результат в ST(1), вытолкнуть стек | `faddp` — DE C1 |
| DA /0 | FIADD m32int | Valid | Valid | Прибавить m32int к ST(0), результат в ST(0) | `fiadd dword [eax]` — DA 00 |
| DE /0 | FIADD m16int | Valid | Valid | Прибавить m16int к ST(0), результат в ST(0) | `fiadd word [eax]` — DE 00 |

- **FADD** с операндом в памяти складывает вершину стека с числом одинарной (`D8`) или двойной (`DC`) точности, результат остаётся на вершине. Какая из команд выбрана, различают и первый байт кода, и три нуля поля Reg байта ModR/M — `/0`
- **FADDP** после записи результата выталкивает стек: помечает ST(0) пустым и увеличивает поле `TOP` на 1
- **FIADD** складывает с целым из памяти — 16- или 32-битным, предварительно переводя его в расширенный формат

Битовая запись приложения B[^fadd-b]:

| Операция | Кодировка |
| --- | --- |
| FADD: ST(0) := ST(0) + 32-bit memory | 11011 000 : mod 000 r/m |
| FADD: ST(0) := ST(0) + 64-bit memory | 11011 100 : mod 000 r/m |
| FADD: ST(d) := ST(0) + ST(i) | 11011 d00 : 11 000 ST(i) |
| FADDP: ST(i) := ST(0) + ST(i) | 11011 110 : 11 000 ST(i) |

Здесь бит d стоит на месте бита 2 первого байта: d = 0 — результат в ST(0) (`D8`), d = 1 — в ST(i) (`DC`). Бит 2 он же выбирает размер операнда из памяти: 32 бита (`D8`) или 64 (`DC`)

[^fadd-b]: [Intel SDM, Vol. 2D, Table B-39 "Floating-Point Instruction Formats and Encodings"](https://cdrdv2.intel.com/v1/dl/getContent/671110) и описание "FADD/FADDP/FIADD—Add" в Vol. 2A. На слайде (стр. 164) и в самой Table B-39 строка FADDP записана как "ST(0) := ST(0) + ST(i)". Результат FADDP сохраняется в ST(i), а не в ST(0), — так сказано в основной таблице той же страницы: "Add ST(0) to ST(i), store result in ST(i), and pop the register stack". Иначе выталкивание стека сразу уничтожало бы результат

## ADDPS

**ADDPS** (Add Packed Single-Precision Floating-Point Values) складывает попарно упакованные вещественные числа одинарной точности — по 4 в XMM, 8 в YMM, 16 в ZMM — за одно выполнение команды (стр. 165)

| Код и команда | Op/En | 64/32 bit Mode Support | CPUID Feature Flag | Описание |
| --- | --- | --- | --- | --- |
| `NP 0F 58 /r` — `ADDPS xmm1, xmm2/m128` | A | V/V | SSE | Сложить xmm2/m128 с xmm1, результат в xmm1 |
| `VEX.128.0F.WIG 58 /r` — `VADDPS xmm1, xmm2, xmm3/m128` | B | V/V | AVX | Сложить xmm3/m128 с xmm2, результат в xmm1 |
| `VEX.256.0F.WIG 58 /r` — `VADDPS ymm1, ymm2, ymm3/m256` | B | V/V | AVX | Сложить ymm3/m256 с ymm2, результат в ymm1 |
| `EVEX.128.0F.W0 58 /r` — `VADDPS xmm1 {k1}{z}, xmm2, xmm3/m128/m32bcst` | C | V/V | AVX512VL и AVX512F | Сложить xmm3/m128/m32bcst с xmm2, результат в xmm1 по маске записи k1 |
| `EVEX.256.0F.W0 58 /r` — `VADDPS ymm1 {k1}{z}, ymm2, ymm3/m256/m32bcst` | C | V/V | AVX512VL и AVX512F | Сложить ymm3/m256/m32bcst с ymm2, результат в ymm1 по маске записи k1 |
| `EVEX.512.0F.W0 58 /r` — `VADDPS zmm1 {k1}{z}, zmm2, zmm3/m512/m32bcst {er}` | C | V/V | AVX512F | Сложить zmm3/m512/m32bcst с zmm2, результат в zmm1 по маске записи k1 |

Обозначения[^addps]:

- **`NP`** — перед кодом не должно быть префиксов 66H, F2H, F3H: с 66H те же `0F 58` — уже ADDPD
- **VEX.128.0F.WIG** — префикс [[Формат машинной команды IA-32#VEX и EVEX|VEX]] с длиной вектора 128 бит, неявным escape-кодом 0FH и игнорируемым битом W
- **{k1}{z}** — регистр маски записи k1; без {z} элементы, не прошедшие маску, сохраняют старые значения, с {z} — обнуляются. **m32bcst** — вектор, заполненный одним 32-битным значением из памяти. **{er}** — встроенное управление округлением, только для формы регистр–регистр
- **Tuple Type Full** — по нему определяется множитель N сжатого смещения [[Формат машинной команды IA-32|EVEX]] `disp8*N`
- В форме SSE приёмник совпадает с первым источником (A: reg — и чтение, и запись), в формах VEX и EVEX источников два, и первый из них задаёт поле vvvv префикса — результат не затирает ни один из них

| Команда | Байты |
| --- | --- |
| `addps xmm1, xmm2` | 0F 58 CA |
| `addps xmm1, [eax]` | 0F 58 08 |
| `addpd xmm1, xmm2` | 66 0F 58 CA |
| `addps xmm9, xmm10`, 64-битный режим | 45 0F 58 CA |
| `vaddps xmm1, xmm2, xmm3` | C5 E8 58 CB |
| `vaddps ymm1, ymm2, ymm3` | C5 EC 58 CB |
| `vaddps zmm1, zmm2, zmm3` | 62 F1 6C 48 58 CB |

Битовая запись приложения B для SSE-формы:

| Операция | Кодировка |
| --- | --- |
| xmmreg2 to xmmreg1 | 0000 1111 : 0101 1000 : 11 xmmreg1 xmmreg2 |
| mem to xmmreg | 0000 1111 : 0101 1000 : mod xmmreg r/m |

Код операции у всех форм один — 58: у `addps xmm1, xmm2` escape-байт 0FH записан явно, у `vaddps` он неявный, а второй источник и длина вектора упакованы в сам префикс VEX или EVEX
