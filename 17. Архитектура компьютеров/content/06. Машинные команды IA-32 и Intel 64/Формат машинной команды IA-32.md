# Формат машинной команды IA-32 и Intel 64

## Шесть полей команды

Общий формат команды процессоров [[Режимы работы процессоров Intel|IA-32 и Intel®64]] состоит из шести полей. Обязательно только поле кода операции, остальные присутствуют или отсутствуют в зависимости от него

| Поле | Размер | Назначение |
| --- | --- | --- |
| Префиксы (Instruction Prefixes) | 0–4 байта, по одному байту из каждой из четырёх групп | Меняют действие команды: блокировка, повторение, сегмент, размер операнда и адреса |
| Код операции (Opcode) | 1, 2 или 3 байта | Номер команды в системе команд процессора |
| ModR/M | 1 байт, если нужен | Регистр или способ адресации операнда |
| SIB | 1 байт, если нужен | Масштаб, индекс и база адреса в памяти |
| Displacement | 1, 2 или 4 байта либо нет | Смещение в исполнительном адресе |
| Immediate | 1, 2 или 4 байта либо нет | Непосредственный операнд |

![[Раскладка ModRM и SIB.png]]

> [!important] Максимальная длина команды — 15 байт
> Команда переменной длины, и её фактическую длину процессор узнаёт только декодированием: разобрал префиксы — понял, где код операции; разобрал код операции — понял, нужен ли ModR/M; разобрал ModR/M — понял, есть ли SIB и какой длины смещение; и так далее, как клубок, который разматывают шаг за шагом. Префиксы, раздувающие команду сверх 15 байт, вызывают исключение \#GP[^len15]
>
> Узнанная длина нужна и [[Цикл обработки машинной команды#Развёрнутый цикл обработки команды|циклу обработки команды]]: у команды, не передающей управление, адрес следующей получается как текущее содержимое счётчика команд плюс длина только что извлечённой. У команды перехода или вызова подпрограммы адрес задан в самой команде, и именно он загружается в счётчик[^len-lecture]

[^len15]: [Intel SDM, Vol. 2A, §2.3.11](https://cdrdv2.intel.com/v1/dl/getContent/671110): "The maximum length of an Intel 64 and IA-32 instruction remains 15 bytes"; условие \#GP — [Intel SDM, Vol. 3A, "Event 13—General Protection Exception (\#GP)"](https://cdrdv2.intel.com/v1/dl/getContent/671447): "Exceeding the instruction length limit of 15 bytes (this only can occur when redundant prefixes are placed before an instruction)". Предел ввёл Intel386, у 8086 его не было (там же, глава о совместимости с IA-32). Номера разделов и таблиц SDM в этой заметке — по редакции 325383-092US и 325384-092US (июнь 2026)

[^len-lecture]: Лектор, 02.12.2024

## Префиксы

До четырёх префиксов, по одному из каждой группы; группы между собой стоят в любом порядке[^prefixes-sdm]

| Группа | Код | Префикс | Где применяется |
| --- | --- | --- | --- |
| 1 — блокировка и повторение | F0H | LOCK | Монопольный доступ к разделяемой памяти на время команды |
| 1 | F2H | REPNE/REPNZ | Строковые команды и команды ввода-вывода; с 0FH — обязательный префикс |
| 1 | F3H | REP/REPE/REPZ | Строковые команды и команды ввода-вывода; с 0FH — обязательный префикс |
| 2 — замена сегмента | 26H | ES | Операнд в памяти берётся из сегмента ES |
| 2 | 2EH | CS | Сегмент CS |
| 2 | 36H | SS | Сегмент SS |
| 2 | 3EH | DS | Сегмент DS |
| 2 | 64H | FS | Сегмент FS |
| 2 | 65H | GS | Сегмент GS |
| 2 — указание ветвления | 2EH | Переход не ожидается | Только с условными переходами Jcc |
| 2 | 3EH | Переход ожидается | Только с условными переходами Jcc |
| 3 — размер операнда | 66H | Замена размера операнда | Переключает 16 ↔ 32 бита; с 0FH — обязательный префикс части [[Арифметико-логическое устройство\|SSE]]-команд |
| 4 — размер адреса | 67H | Замена размера адреса | Переключает разрядность исполнительного адреса[^67h] |

[^prefixes-sdm]: [Intel SDM, Vol. 2A, §2.1.1 "Instruction Prefixes"](https://cdrdv2.intel.com/v1/dl/getContent/671110): "For each instruction, it is only useful to include up to one prefix code from each of the four groups (Groups 1, 2, 3, 4). Groups 1 through 4 may be placed in any order relative to each other"

[^67h]: На слайде (стр. 150) префиксу замены размера адреса приписан код 66H — это код префикса размера **операнда** из группы 3, у размера адреса код 67H ([Intel SDM, Vol. 2A, §2.1.1](https://cdrdv2.intel.com/v1/dl/getContent/671110): "Group 4 — 67H—Address-size override prefix")

### Блокировка и повторение

**LOCK** на время выполнения команды переводит в активное состояние одноимённый сигнал LOCK#: в многопроцессорной системе это гарантирует команде монопольное использование разделяемой памяти, пока она не завершится. Допустим он не с любой командой — например, [[Набор машинных команд IA-32|ADD]] с префиксом LOCK, у которой приёмник не в памяти, вызывает \#UD[^lock]

Префиксы **повторения** заставляют команду выполниться для каждого элемента строки — это строковые команды MOVS, CMPS, SCAS, LODS, STOS и команды ввода-вывода INS, OUTS. С другими командами их использование зарезервировано. Рядом с escape-кодом 0FH байты F2H и F3H меняют роль и становятся **обязательным префиксом** (mandatory prefix) — частью кода операции SSE-команд: `F3 0F E6` — это CVTDQ2PD, и F3H здесь не повтор

[^lock]: Лектор (запись 02.12.2024) описывает LOCK как блокировку самого процессора: "никаких действий тут быть не может, он блокируется, пока не будет выполнена команда". Блокируется не процессор, а доступ других процессоров к разделяемой памяти: "The LOCK prefix (F0H) forces an operation that ensures exclusive use of shared memory in a multiprocessor environment" ([Intel SDM, Vol. 2A, §2.1.1](https://cdrdv2.intel.com/v1/dl/getContent/671110)); условие \#UD для ADD — там же, раздел "ADD—Add"

### Замена сегмента и указание ветвления

**Префикс замены сегмента** указывает, из какого [[Регистры процессора#Сегментные регистры|сегментного регистра]] брать базу для операнда в памяти вместо сегмента по умолчанию. С командами передачи управления его использование зарезервировано[^seg-branch]

Коды 2EH и 3EH перед условным переходом Jcc читаются иначе — как **указание ветвления** (branch hint): программа, а значит и компилятор, заранее сообщает процессору наиболее вероятный исход перехода. Это подсказка блоку [[Предсказание переходов|предсказания переходов]], полученная ещё на этапе трансляции программы, а не в момент срабатывания перехода[^hints]

[^seg-branch]: Слайд (стр. 149) и лектор (запись 02.12.2024) утверждают обратное — что префиксы замены сегмента "могут быть использованы с любыми командами управления программой". По SDM такое использование зарезервировано для каждого из шести кодов: "2EH—CS segment override (use with any branch instruction is reserved)" и так далее ([Intel SDM, Vol. 2A, §2.1.1](https://cdrdv2.intel.com/v1/dl/getContent/671110)). Те же байты 2EH и 3EH перед Jcc — уже не замена сегмента, а указание ветвления

[^hints]: Рассказ лектора, 02.12.2024. SDM оговаривает, что реакция на подсказку зависит от микроархитектуры конкретного процессора: "Microarchitectural behavior varies" ([Intel SDM, Vol. 2A, §2.1.1, сноска к "Branch hints"](https://cdrdv2.intel.com/v1/dl/getContent/671110))

### Размер операнда и размер адреса

**66H** переключает разрядность операнда между 16 и 32 битами: какая из них по умолчанию, задаёт режим, а префикс выбирает другую. В 32-битном коде `mov ax, bx` кодируется как `66 89 D8`, а без префикса те же `89 D8` означают `mov eax, ebx`

Вместе с 0FH префикс 66H становится обязательным для части команд SSE2–SSE4: `0F 58 CA` — это `addps xmm1, xmm2`, а `66 0F 58 CA` — уже `addpd xmm1, xmm2`. Такие команды — [[Классификация Флинна|SIMD]]: одна команда обрабатывает сразу несколько элементов данных[^sse-coproc]

**67H** так же переключает разрядность **исполнительного адреса**: в 32-битном режиме `67 66 8B 47 02` — это `mov ax, [bx+2]` с 16-битной адресацией. В 64-битном режиме префикс 67H урезает вычисленный адрес до 32 бит[^67h-lecture]

[^sse-coproc]: Лектор называет SSE сопроцессором — это расширение системы команд, разбор в [[Арифметико-логическое устройство]]

[^67h-lecture]: Лектор (запись 02.12.2024) говорит, что этим префиксом указывается режим работы — 32- или 64-разрядный. Режим префикс не меняет, он меняет только разрядность адреса одной команды: 16 ↔ 32 бита вне 64-битного режима, а в 64-битном — "The effect of the address-size prefix is to truncate and zero-extend the computed effective address to 32 bits" ([Intel SDM, Vol. 2A, §2.1.1 и §2.2.1.6](https://cdrdv2.intel.com/v1/dl/getContent/671110))

### VEX и EVEX

Слайды на REX заканчиваются, но команды [[Набор машинных команд IA-32|AVX]] и AVX-512 кодируются префиксами нового типа

**VEX** — двухбайтный (первый байт C5H) или трёхбайтный (C4H) префикс, в котором упакованы биты REX (R, X, B — в инвертированном виде), W, неявный escape-код (0F, 0F 38 или 0F 3A), неявный обязательный префикс (поле pp: нет, 66H, F3H, F2H), длина вектора L (128 или 256 бит) и поле vvvv — номер ещё одного регистра-источника, тоже инвертированный

Префиксы 66H, F2H, F3H или REX перед VEX запрещены — такая команда вызывает \#UD[^vex]

Коды C4H и C5H выбраны не случайно: вне 64-битного режима это команды LES и LDS, операнд которых — дальний указатель в памяти (m16:32), а в 64-битном режиме они недопустимы

Вне 64-битного режима два старших бита второго байта VEX всегда единицы: биты R и X хранятся инвертированными, а регистров с номером больше 7 там нет. Прочитанный как ModR/M, такой байт даёт Mod = 11, то есть регистр вместо памяти, — для LES и LDS это невозможно, и процессор узнаёт префикс

> [!example]- VEX по битам — `vaddps xmm1, xmm2, xmm3` = `C5 E8 58 CB`
> | Байт | Биты | Смысл |
> | --- | --- | --- |
> | C5 | 1100 0101 | Двухбайтный VEX |
> | E8 | 1 1101 0 00 | R инвертирован — REX.R = 0; vvvv инвертировано: 1101 → 0010 — XMM2; L = 0 — 128 бит; pp = 00 — без неявного префикса |
> | 58 | 0101 1000 | Код операции [[Набор машинных команд IA-32\|ADDPS]] с неявным 0FH |
> | CB | 11 001 011 | Mod = 11 — регистр; Reg = 001 — XMM1 (приёмник); R/M = 011 — XMM3 |

**EVEX** — четырёхбайтный префикс AVX-512: байт 62H и три байта полезной нагрузки. Он кодирует 32 векторных регистра XMM/YMM/ZMM, регистр маски k, длину вектора до 512 бит, сжатое 8-битное смещение и широковещательную подстановку операнда из памяти. Первые два байта EVEX взяты из неиспользуемой формы команды BOUND, которая существует только вне 64-битного режима. Пример — `vaddps zmm1, zmm2, zmm3` = `62 F1 6C 48 58 CB`[^evex]

[^vex]: [Intel SDM, Vol. 2A, §2.3.2–2.3.5 и Figure 2-9 "VEX bit fields"](https://cdrdv2.intel.com/v1/dl/getContent/671110); про LES и LDS — §2.3.5.2: "In protected and compatibility modes the bit must be set to '1' otherwise the instruction is LES or LDS"

[^evex]: [Intel SDM, Vol. 2A, §2.7 и §2.7.1](https://cdrdv2.intel.com/v1/dl/getContent/671110): "EVEX is a 4-Byte prefix (the first byte must be 62H)… The EVEX prefix is a 4-byte prefix, with the first two bytes derived from unused encoding form of the 32-bit-mode-only BOUND instruction"

## Код операции

**Код операции** (**КОП**) — уникальная комбинация бит, по которой процессор отличает одну команду от другой, своего рода номер команды в системе команд[^opcode-unique]. Основной код операции занимает 1, 2 или 3 байта:

- **1 байт** — `03` (ADD r32, r/m32), `F4` (HLT)
- **2 байта** — escape-код **0FH** и второй байт: `0F 58` (ADDPS)
- **3 байта** — 0FH, затем 38H или 3AH, затем третий байт: `66 0F 38 01` — PHADDW, где 66H обязательный префикс

Иногда код операции дополняется тремя битами поля Reg/Opcode байта ModR/M. В справочнике **SDM** (Intel 64 and IA-32 Architectures Software Developer's Manual) это записывается как `/digit`: `80 /0` — ADD, `80 /7` — CMP, у обеих первый байт 80H, а различает их поле Reg

[^opcode-unique]: Лектор (запись 02.12.2024) говорит, что в процессоре "не может быть двух абсолютно одинаковых команд", вызываемых по разным кодам. У x86 это не так: из-за бита d одна и та же `add eax, ebx` кодируется и как `01 D8` (ADD r/m32, r32), и как `03 C3` (ADD r32, r/m32) — objdump декодирует обе последовательности в одну команду. Однозначно обратное — в заданном режиме каждой кодовой последовательности соответствует одна команда

### Поля внутри кода операции

Внутри однобайтного кода встречаются служебные битовые поля. Все они видны на семействе ADD: `0000 00dw` и `1000 00sw`[^fields]

| Поле | Бит | 0 | 1 |
| --- | --- | --- | --- |
| **w** | 0 | Операнд — байт | Операнд полного размера — 16 или 32 бита, в 64-битном режиме с REX.W — 64 |
| **d** | 1 | Источник — поле Reg, приёмник — ModR/M | Источник — ModR/M, приёмник — поле Reg |
| **s** | 1, при непосредственном операнде | Непосредственный операнд полного размера | 8-битный непосредственный операнд расширяется знаком до размера приёмника |
| **reg** | 2–0 | Номер регистра прямо в коде операции | — |

- `00` = 0000 0000: d = 0, w = 0 — ADD r/m8, r8; `03` = 0000 0011: d = 1, w = 1 — ADD r32, r/m32
- `81` = 1000 0001: s = 0, w = 1 — непосредственный операнд imm32; `83` = 1000 0011: s = 1, w = 1 — imm8, расширяемый знаком
- `B8`+r — MOV r32, imm32, `50`+r — PUSH r: номер регистра в младших трёх битах кода

[^fields]: [Intel SDM, Vol. 2D, Appendix B.1.4, Tables B-1, B-6, B-7, B-11](https://cdrdv2.intel.com/v1/dl/getContent/671110). Для команд x87 бит d стоит на месте бита 2 первого байта кода — [[Набор машинных команд IA-32#FADD, FADDP, FIADD|пример FADD]]

## Байт ModR/M

**ModR/M** (Mode, Register/Memory) присутствует в большинстве команд, у которых есть операнд в памяти или регистр вне кода операции

| Биты | Поле | Содержимое |
| --- | --- | --- |
| 7–6 | **Mod** | Способ адресации: 11 — регистр, 00/01/10 — память без смещения, с 8-битным, с 16- или 32-битным смещением |
| 5–3 | **Reg/Opcode** | Номер регистра-операнда или три дополнительных бита кода операции — решает код операции |
| 2–0 | **R/M** | Номер регистра или, вместе с Mod, способ формирования адреса в памяти |

Mod и R/M вместе дают 32 значения: 8 регистров (Mod = 11) и 24 способа адресации памяти. Полные таблицы и особые случаи — в [[Способы адресации#Байт ModR/M в 32-разрядной адресации|способах адресации]]

## Байт SIB

**SIB** (Scale-Index-Base) следует за ModR/M, когда Mod ≠ 11 и R/M = 100, и доопределяет адрес в 32- и 64-разрядной адресации

| Биты | Поле | Содержимое |
| --- | --- | --- |
| 7–6 | **Scale** | Масштаб индекса: 00, 01, 10, 11 — множитель 1, 2, 4, 8 |
| 5–3 | **Index** | Номер индексного регистра; 100 — индекса нет |
| 2–0 | **Base** | Номер базового регистра; 101 при Mod = 00 — базы нет, следует disp32 |

$$
\boxed{\text{адрес} = \text{Base} + \text{Index}\cdot 2^{\text{Scale}} + \text{Displacement}}
$$

Таблица значений SIB и особые случаи — в [[Способы адресации#Байт SIB|способах адресации]]

## Смещение и непосредственный операнд

**Displacement** — константа, которая прибавляется к исполнительному адресу операнда в памяти: и без базы (прямая адресация), и к базе, и к результату, вычисленному по SIB. Размер задаёт Mod: в 16-разрядной адресации 8 или 16 бит, в 32- и 64-разрядной — 8 или 32 бита. 8-битное смещение расширяется знаком, так что `disp8` охватывает только $-128\ldots127$[^disp]

**Immediate** — непосредственный операнд, константа из текста программы, записанная прямо в тело команды. Для её получения не нужно обращаться ни к регистру, ни к памяти — значение уже извлечено вместе с командой. Непосредственный операнд всегда стоит после смещения и занимает 1, 2 или 4 байта

В 64-битном режиме 32-битный непосредственный операнд расширяется знаком до 64 бит, а полные 8 байт бывают только у `MOV r64, imm64`: `48 B8 88 77 66 55 44 33 22 11` — `mov rax, 1122334455667788h`[^imm]

Оба поля записываются [[Системы счисления и форматы данных#Порядок байт в памяти|младшим байтом вперёд]]: смещение 100h в команде выглядит как `00 01 00 00`

[^disp]: На слайде (стр. 152) смещение описано как "смещение операнда при прямой адресации". Прямая адресация — только частный случай: смещение участвует в любом способе адресации со смещением, в том числе базовом и индексном ([Intel SDM, Vol. 2A, §2.1.4, §2.2.1.3](https://cdrdv2.intel.com/v1/dl/getContent/671110)). Позже в той же записи лектор так и говорит: "эта константа определяет смещение относительно базы"

[^imm]: [Intel SDM, Vol. 2A, §2.2.1.5 "Immediates"](https://cdrdv2.intel.com/v1/dl/getContent/671110). Второе исключение — `MOV` с 64-битным абсолютным адресом (moffset), §2.2.1.4

## REX-префикс Intel®64

В IA-32 регистров общего назначения восемь, и на их номер хватает трёх бит в полях Reg, R/M, Index, Base. В 64-битном режиме Intel®64 регистров вдвое больше — 16, номеру нужно четыре бита. Недостающий старший бит каждого поля приносит **REX-префикс**. Он задаёт расширенные регистры общего назначения и SSE, 64-битный размер операнда и расширенные регистры управления

| Устаревшие префиксы | REX-префикс | Код операции | ModR/M | SIB | Displacement | Immediate |
| --- | --- | --- | --- | --- | --- | --- |
| Группы 1–4, необязательны | Необязателен | 1, 2 или 3 байта | 1 байт, если нужен | 1 байт, если нужен | 1, 2 или 4 байта либо нет | 1, 2 или 4 байта либо нет |

Раскладка байта — `0100WRXB`:

| Биты | Поле | Значение |
| --- | --- | --- |
| 7–4 | — | 0100 — признак REX-префикса |
| 3 | **W** | 0 — размер операнда задаётся атрибутом сегмента кода (CS.D); 1 — операнд 64-битный |
| 2 | **R** | Старший бит поля Reg байта ModR/M |
| 1 | **X** | Старший бит поля Index байта SIB |
| 0 | **B** | Старший бит поля R/M байта ModR/M, поля Base байта SIB или поля регистра в коде операции |

Правила, которых нет на слайдах[^rex-rules]:

- REX стоит **непосредственно перед кодом операции**, после всех устаревших префиксов, в том числе обязательного: `F3 REX 0F E6`. REX в другом месте игнорируется
- Нужен REX только для регистров R8–R15, XMM8–XMM15, байтовых SPL, BPL, SIL, DIL или 64-битного операнда. Команды, по умолчанию 64-битные в этом режиме — ближние переходы и работа со стеком через RSP, — обходятся без REX.W: `push r8` = `41 50`
- С любым REX байтовые регистры AH, CH, DH, BH закодировать нельзя — те же номера означают SPL, BPL, SIL, DIL: `00 C4` — `add ah, al`, а `40 00 C4` — `add spl, al`
- При REX.W = 1 префикс 66H в небайтовых операциях игнорируется
- Байты 40H–4FH в IA-32 и режиме совместимости — однобайтные INC и DEC. В 64-битном режиме это REX-префиксы, а инкремент кодируется через ModR/M: `inc eax` в 32-битном коде — `40`, в 64-битном — `FF C0`

Четыре схемы применения REX (стр. 158–159, в SDM — Figures 2-4…2-7):

| Схема | REX | Биты команды | Как собираются 4-битные номера |
| --- | --- | --- | --- |
| Память без SIB, Mod ≠ 11 | 0100WR0B | ModR/M: mod, reg, r/m | Регистр = R:reg, база = B:r/m; X не используется |
| Регистр–регистр, Mod = 11 | 0100WR0B | ModR/M: 11, reg, r/m | Первый регистр = R:reg, второй = B:r/m; X не используется |
| Память с SIB, Mod ≠ 11, R/M = 100 | 0100WRXB | ModR/M: mod, reg, 100; SIB: ss, index, base | Регистр = R:reg, индекс = X:index, база = B:base |
| Регистр в коде операции | 0100W00B | Код операции с полем reg | Регистр = B:reg; X и R не используются |

Особые значения полей REX расширяет не везде одинаково: R/M = 100 (признак SIB) и R/M = 101 при Mod = 00 распознаются по трём младшим битам без учёта B, а поле Index — по всем четырём, поэтому R12 можно использовать как индекс, в отличие от RSP. Все эти случаи сведены в таблицы [[Способы адресации#64-разрядный режим|64-разрядного режима адресации]]

[^rex-rules]: [Intel SDM, Vol. 2A, §2.2.1, §2.2.1.2, §2.2.1.7 и Table 2-5 "Special Cases of REX Encodings"](https://cdrdv2.intel.com/v1/dl/getContent/671110)

## Кодирование команды по байтам

Оба примера собраны вручную по таблицам SDM и затем проверены ассемблером: байты ниже — вывод `objdump -d` для кода, собранного **NASM** (Netwide Assembler)[^toolchain]

> [!example]+ Все шесть полей — `lock add dword [fs:ebx+esi*4+100h], 12345678h`
> Режим 32-битный, команда занимает 13 байт: `64 F0 81 84 B3 00 01 00 00 78 56 34 12`
>
> | Поле | Байты | Биты | Смысл |
> | --- | --- | --- | --- |
> | Префикс, группа 2 | 64 | 0110 0100 | Замена сегмента на FS |
> | Префикс, группа 1 | F0 | 1111 0000 | LOCK |
> | Код операции | 81 | 1000 00**01** | `81 /0 id` — ADD r/m32, imm32: s = 0, w = 1, операнд полного размера |
> | ModR/M | 84 | **10** 000 100 | Mod = 10 — смещение 32 бита; Reg = 000 — `/0`, т.е. именно ADD; R/M = 100 — дальше SIB |
> | SIB | B3 | **10** 110 011 | Scale = 10 — множитель 4; Index = 110 — ESI; Base = 011 — EBX |
> | Displacement | 00 01 00 00 | — | 00000100h, младшим байтом вперёд. В `disp8` число 100h не помещается — отсюда Mod = 10 |
> | Immediate | 78 56 34 12 | — | 12345678h |
>
> Префиксы NASM поставил в порядке 64, F0 — порядок групп между собой произвольный

> [!example]+ REX на всех полях — `add r9, [rax+r12*8+100h]`
> Режим 64-битный, 8 байт: `4E 03 8C E0 00 01 00 00`
>
> | Поле | Байты | Биты | Смысл |
> | --- | --- | --- | --- |
> | REX | 4E | 0100 **1** **1** **1** **0** | W = 1 — операнд 64 бита; R = 1; X = 1; B = 0 |
> | Код операции | 03 | 0000 0011 | `REX.W + 03 /r` — ADD r64, r/m64 |
> | ModR/M | 8C | **10** 001 100 | Mod = 10 — смещение 32 бита; Reg = 001, с R — 1001 = R9; R/M = 100 — дальше SIB |
> | SIB | E0 | **11** 100 000 | Scale = 11 — множитель 8; Index = 100, с X — 1100 = R12; Base = 000, с B — 0000 = RAX |
> | Displacement | 00 01 00 00 | — | 00000100h |
>
> Без REX.X поле Index = 100 означало бы "индекса нет", а с X = 1 оно становится полноценным номером 12

[^toolchain]: NASM 3.02, `nasm -f bin`, дизассемблирование — `objdump -D -b binary -m i386` или `-m i386:x86-64` из [[GNU]] Binutils 2.46

## Число операндов

Команды без операндов, с одним и с двумя операндами устроены по-разному

### Команды без операндов

Такие команды ничего не вычисляют, а настраивают процессор или вызывают нужное срабатывание в вычислительном процессе. Два примера лектора: **`CLI`** (`FA`) сбрасывает [[Регистры процессора#Регистр флагов EFLAGS|флаг IF]] и тем запрещает маскируемые прерывания, **`HLT`** (`F4`) останавливает выполнение команд и переводит процессор в состояние `HALT`

> [!warning] CLI и затем HLT — не вечная блокировка
> Лектор приводит эту пару как гарантированную мёртвую блокировку: прерывания от внешних устройств запрещены, процессор остановлен, и вывести его можно только перезапуском компьютера[^cli-hlt-lecture]. Это верно лишь для маскируемых прерываний
>
> `CLI` не влияет на исключения и на **NMI** (Non-Maskable Interrupt, немаскируемое прерывание), а из состояния `HALT` процессор выводят разрешённое прерывание, включая NMI и [[Режимы работы процессоров Intel#Режим системного управления|SMI]], отладочное исключение и сигналы BINIT#, INIT#, RESET#. После обработчика NMI выполнение продолжается с команды, следующей за `HLT`[^cli-hlt]
>
> Кроме того, обе команды привилегированные. В защищённом режиме `HLT` вне [[Режимы работы процессоров Intel#Кольца защиты|кольца 0]] вызывает \#GP, а `CLI` при IOPL меньше текущего уровня привилегий вызывает \#GP или, в режимах виртуальных прерываний **PVI** (Protected-Mode Virtual Interrupts) и **VME** (Virtual-8086 Mode Extensions), сбрасывает только виртуальный флаг VIF. Прикладная программа такой парой процессор не остановит

[^cli-hlt-lecture]: Лектор, 02.12.2024

[^cli-hlt]: `CLI`: "Clearing the IF flag causes the processor to ignore maskable external interrupts. The IF flag and the CLI and STI instruction have no effect on the generation of exceptions and NMI interrupts"; `HLT`: "An enabled interrupt (including NMI and SMI), a debug exception, the BINIT# signal, the INIT# signal, or the RESET# signal will resume execution. If an interrupt (including NMI) is used to resume execution after a HLT instruction, the saved instruction pointer (CS:EIP) points to the instruction following the HLT instruction… When the processor is running in protected or virtual-8086 mode, the privilege level of a program or procedure must be 0 to execute the HLT instruction" ([Intel SDM, Vol. 2A, разделы "CLI—Clear Interrupt Flag" и "HLT—Halt"](https://cdrdv2.intel.com/v1/dl/getContent/671110)). Условие \#GP для `CLI` — Table 3-7 там же

### Команды с одним операндом

Операнд единственный, а действие с ним предопределено кодом операции. Пример — инкремент и декремент: второе слагаемое, единица, нигде не хранится, в поле Immediate его нет, процессор подставляет его сам

### Команды с двумя операндами

Самый распространённый вид: для каждого операнда нужно явно указать, где он находится

- **RR** (register-to-register, регистр — регистр): оба операнда в регистрах, достаточно номеров регистров в ModR/M с Mod = 11
- **RM** (register — memory, регистр — память)[^rm]: один операнд в регистре, другой в памяти; чтобы до него добраться, нужно декодировать [[Способы адресации|способ адресации]] — базу, индекс, масштаб и смещение

Два операнда в памяти одна команда ADD не принимает — один из операндов всегда регистр или непосредственный операнд ([[Набор машинных команд IA-32#ADD|таблица ADD]])

[^rm]: Порядок букв — порядок операндов, как в столбце Op/En у Intel SDM: в `RM` первый операнд, он же приёмник, — регистр из поля reg, второй — поле r/m. Обратное направление, с приёмником в памяти, называется `MR` ([[Набор машинных команд IA-32#Таблица кодов операции|таблица Op/En]])
