# Intel P6 и Motorola MPC604

> [!tip] Современный процессор — "процессор в процессоре"
> Набор специализированных сопроцессоров (операционных автоматов), каждый со своей узкой специализацией — оба процессора ниже устроены по одному и тому же принципу. Структурно почти все современные процессоры очень похожи друг на друга; принципиальные различия — не в наборе блоков, а в том, как каждый блок реализован: алгоритмы, технологии, конкретная аппаратная реализация под доступный техпроцесс

## Структура Intel P6

![[Архитектура компьютеров Мосин.pdf#page=134&rect=347,27,717,353]]

| Блок | Функция |
| --- | --- |
| Блок внешнего интерфейса (**BIU**, Bus Interface Unit) | Протокол обмена процессора с системной шиной |
| Кэш-память команд L1 / данных L1 (по 16 Кбайт) | Раздельные — размещение наиболее часто используемых команд и данных; явное проявление [[Принципы фон Неймана#Принстонская и гарвардская архитектуры\|гарвардской архитектуры]] внутри процессора при принстонской архитектуре внешней [[Характеристики ЗУ и типы ПЗУ\|ОЗУ]] |
| Блок предсказания ветвлений ([[Предсказание переходов\|BTB]]) | Формирует адрес следующей выбираемой команды при условном переходе |
| Блок выборки-декодирования (DC1, DC2, DC3) | Выбирает из кэша 32 байта командного кода; простые команды (1 микрооперация) декодируют DC1 и DC2, сложные многооперационные — DC3 |
| Блок распределения регистров (**RAT**, Register Alias Table) | Выделяет один из 40 физических регистров замещения под логический регистр декодированной команды, требующей регистр с фиксированной или плавающей точкой[^rat-40] |
| Блок регистров замещения (**RRF**, Retirement Register File) | Сами 40 физических регистров-псевдонимов — программно недоступны напрямую, только через RAT |
| Блок изменения последовательности команд (**ROB**, Re-Order Buffer) | Переупорядочивает независимые декодированные команды для параллельной подачи на разные сопроцессоры, если нет конфликта по данным или по управлению |
| Блок распределения (**RS**, Reservation Station) | Диспетчер: направляет микрокоманды в исполнительные устройства, обеспечивает одновременное выполнение трёх команд |
| IU1, IU2 | Обработка целых чисел (**БФТ** — блоки с фиксированной точкой) |
| [[Регистры процессора\|FPU]] | Операции с плавающей точкой (**БПТ** — блок с плавающей точкой) |
| [[Арифметико-логическое устройство\|MMX]] | Одновременная обработка нескольких упакованных значений |
| [[Арифметико-логическое устройство\|SSE]] | Операции над потоком чисел с плавающей точкой |
| Блок интерфейса с памятью (**MIU**, Memory Interface Unit) | Вычисляет адреса операндов из памяти, формирует запросы к кэш-памяти данных |
| Буферный блок обращения к памяти (**MOB**, Memory Order Buffer) | Спекулятивная выборка операнда из кэша 2-го уровня или внешней памяти при чтении, промежуточное хранение 32 байт при записи |
| Блок трансляции адреса (**TLB**, Translation Lookaside Buffer) — раздельно для команд и данных | Преобразование адреса |
| Кэш-память 2-го уровня (L2) | Общая для команд и данных |

[^rat-40]: Лектор, 26.11.2024, слайд стр. 135 — "для логических регистров с [[Арифметико-логическое устройство|ФТ]] или [[Арифметико-логическое устройство|ПТ]] выделяет один из 40 физических регистров из блока регистров замещения"; блок распределения (RAT) и сами физические регистры замещения (RRF) — два разных блока на схеме, а не один

Все девять исполнительных блоков (IU1, IU2, FPU, MMX, SSE, MIU и далее) подключены к общим шинам данных 2×32 — это и есть конкретная реализация [[Жёсткая и магистральная структура АЛУ#Магистральная структура|магистральной структуры]] на уровне целого процессора, а не одного [[Арифметико-логическое устройство|АЛУ]]

## Структура Motorola MPC604

![[Архитектура компьютеров Мосин.pdf#page=138&rect=292,78,708,315]]

| Блок | Функция |
| --- | --- |
| BPU | Блок обработки ветвлений |
| Устройство управления | Выборка команды → декодирование → распределение команд → выполнение команд |
| SIU1, SIU2 | Простые одноцикловые целочисленные операции |
| MIU2 | Сложные многоцикловые целочисленные операции |
| FPU | Операции с числами в формате с плавающей точкой |
| LSU | Выборка данных из памяти и загрузка в регистры данных [[Регистры процессора\|GPR]] и FPR (Floating-Point Registers) |
| GPR 32×32 / буфер GPR 12×32 | Регистры общего назначения и буфер их переименования |
| FPR 32×64 / буфер FPR 8×64 | Регистры с плавающей точкой и буфер их переименования |
| Кэш команд (**IC**, Instruction Cache, 16 Кбайт) / **IMMU** (Instruction Memory Management Unit) | Кэш-память и MMU (Memory Management Unit) для команд |
| Кэш данных (**DC**, Data Cache, 16 Кбайт) / **DMMU** (Data Memory Management Unit) | Кэш-память и MMU для данных |
| Блок завершения | Буфер результатов, обратная запись |
| BUI | Интерфейс с системной шиной (аналог BIU у P6) |

Структурно MPC604 почти повторяет P6: то же разделение на простые/сложные целочисленные устройства, тот же принцип раздельных кэшей команд и данных со своими MMU. Единственное содержательное отличие — у MPC604 нет блока MMX: для целевых приложений (рабочие станции, серверы) он не требовался

### "Motorola в наш век?"

Удивление уместно — в потребительском сознании Motorola ассоциируется с мобильными телефонами, а не с процессорами для рабочих станций. У Motorola тем не менее был целый спектр процессоров для мобильного сектора. Современный телефон — по сути многопроцессорная вычислительная система: отдельный сопроцессор (микроконтроллер) на подключение к сети, отдельный — на обработку мультимедиа

## Почему лидируют именно Intel и AMD

Постройка фабрики под современный техпроцесс — высокорискованная инвестиция: до промышленного пуска неизвестно, повторится ли лабораторный результат выращивания гетероструктур в промышленном масштабе, а риск брака велик. Стоимость самой фабрики — порядка нескольких миллиардов долларов[^fab-cost]; подробнее о том, как стоимость и сроки постройки фабрики тормозят [[Закон Мура|закон Мура]] — там же

[^fab-cost]: Лектор называет стоимость завода под 7-нанометровый техпроцесс в одном и том же рассуждении сначала "порядка 5 миллиардов долларов", а через несколько секунд — "7 миллиардов долларов" (26.11.2024) — по всей видимости, это оговорка, а не две разные оценки (возможно, лектор спутал стоимость с числом "7" от "7-нанометровая"). Независимые оценки последних лет дают на порядок бо́льшие цифры для фабрики такого класса: 15 млрд долларов за одну фабрику Intel в Аризоне, 25 млрд долларов — за фабрику Samsung в Тейлоре (Техас), общий диапазон для передовых фабрик — 10–20 млрд долларов и выше ([How to Build a $20 Billion Semiconductor Fab](https://www.construction-physics.com/p/how-to-build-a-20-billion-semiconductor), Construction Physics) — обе цифры лектора занижают реальный порядок затрат

### Российский пример: Байкал и Эльбрус

Лектор приводит российский пример: компания в Зеленограде (автораспознавание речи — ASR, Automatic Speech Recognition — записало её как "MSC", искажённое **МЦСТ** — Московский центр SPARC-технологий) производит процессоры Байкал и Эльбрус, архитектура которых максимально ориентирована на архитектуру Intel, но с полностью собственными внутренней организацией, логикой работы и элементной базой

Техпроцесс менее продвинут, чем 7–9 нм, зато такие процессоры применимы не только в бытовых условиях, но и в космосе — с повышенным радиационным фоном

> [!warning] Байкал и Эльбрус делают две разные компании на двух разных архитектурах
> Акционерное общество (АО) **МЦСТ** разрабатывает процессоры **Эльбрус** на собственной архитектуре Эльбрус и линейку **МЦСТ-R** (R2000) на SPARC (Scalable Processor Architecture) V9. Система команд Эльбрус не совпадает с x86: программы x86 запускаются через двоичную трансляцию на лету (Lintel — целые [[Операционная система|ОС]], RTC — приложения), которой архитектура помогает аппаратно[^elbrus-arch]
>
> Процессоры **Байкал** разрабатывает отдельная компания **Байкал Электроникс**, на лицензированных ядрах **MIPS** (Microprocessor without Interlocked Pipelined Stages), [[CISC и RISC|ARM]] и (позже) **RISC-V**[^baikal-arch] — с системой команд x86 эти ядра не совместимы вообще, в отличие от Эльбруса они не занимаются двоичной трансляцией x86
>
> Верно то, что роднит обе линейки: обе разрабатываются в России и обе на момент лекции печатались на сторонних зарубежных фабриках, а не на площадях, сравнимых по масштабу с Intel/AMD

[^elbrus-arch]: [Система двоичной трансляции](https://www.mcst.ru/BinComp), АО МЦСТ — трансляция x86 в Эльбрус, Lintel и RTC, аппаратная поддержка трансляции; [Микропроцессоры и СБИС](https://www.mcst.ru/chips), АО МЦСТ — каталог: Эльбрус-2С3, -8С, -8СВ на архитектуре Эльбрус и R2000 на SPARC V9

[^baikal-arch]: [О компании](http://www.baikalelectronics.ru/about/), Байкал Электроникс — официальное описание: самостоятельный дизайн-центр (fabless), архитектуры MIPS, Arm и RISC-V, три линейки (Baikal-T, Baikal-M, Baikal-S); о МЦСТ или Эльбрусе страница не упоминает
