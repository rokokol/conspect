# Регистры процессора

Регистры процессора представляют память самого верхнего уровня — быстрее и дороже любого уровня [[Иерархия памяти|иерархии памяти]] ниже

## Классификация регистровой памяти

| Группа | Назначение |
| --- | --- |
| **Программно доступные** | Минимизируют число обращений к медленной оперативной памяти, хранят промежуточные результаты вычислений |
| **Управления и состояния** | Используются для управления функционированием процессора — в программах [[Операционная система\|ОС]] |

## Программно доступные регистры

| Тип | Роль |
| --- | --- |
| **РОН** (General Purpose Register, **GPR**) | Универсальные — программист использует по своему усмотрению |
| **Регистры данных** | Только хранение операндов и результатов; не участвуют в вычислении исполнительного адреса |
| **Регистры адреса** | Формирование адресов: указатель сегмента (базовый адрес сегмента памяти), индексные регистры (адресация с индексацией), указатель стека (текущая вершина стека) |
| **Регистр кодов условий** (флаги) | Особый случай — программисту доступны только на чтение отдельные биты, не регистр целиком |

### Проблемы проектирования программно доступных регистров

| Проблема | Компромисс |
| --- | --- |
| **Функциональное назначение** (универсальные / специализированные) | Специализированный регистр (например индексный) рискует простаивать, если программа не использует именно этот вид адресации — впустую потрачены площадь кристалла и энергия |
| **Количество** (8, 16, 32...) | Чем больше регистров, тем реже нужна память — но тем сложнее и медленнее логика их выбора и адресации; рост производительности от числа регистров не монотонен |
| **Разрядность** | Форматы слово / двойное слово / учетверённое слово |
| **Сохранение при вызове подпрограмм** | При вызове подпрограммы всё содержимое регистровой памяти сохраняется в стек — снимок точки возврата. Чем шире и многочисленнее регистры, тем больше места требуется в стеке, а стек живёт в [[Характеристики ЗУ и типы ПЗУ\|ОЗУ]] и не может расти безгранично: при нехватке места ограничивается глубина рекурсии[^stack-depth] |

[^stack-depth]: Лектор, 25.11.2024. Понимание этой внутренней организации регистров позволяет писать код, который компилятор транслирует в более эффективные машинные команды — компилятор сам подбирает регистры и команды под целевую архитектуру (лектор, 26.11.2024)

## Регистры управления и состояния

| Обозначение | Английское | Название |
| --- | --- | --- |
| СчК | PC — program counter | Счётчик команд |
| РгК | IR — instruction register | Регистр команд |
| РгАОП | MAR — memory address register | Регистр адреса операнда в памяти |
| РгДОП | MBR — memory buffer register | Регистр данных операнда в памяти |
| ССП | PSW — program status word | Слово состояния программы |

В [[Цикл обработки машинной команды#Потоки данных|потоке данных цикла обработки команды]] те же регистры фигурируют под сокращёнными именами схемы (СчАК, РгАдр, РгД) — это те же СчК, РгАОП и РгДОП, лектор использует более короткие варианты названий именно в этой диаграмме

## IA-32: основные функциональные регистры

Четыре группы: [[Регистры процессора#Регистры общего назначения|РОН]] (8 штук), указатель команд **EIP**, регистр флагов **EFLAGS**, шесть [[Регистры процессора#Сегментные регистры|сегментных регистров]]

### Регистры общего назначения

Один физический 32-разрядный регистр логически даёт до нескольких представлений — выбор зависит от полей самой [[Формат машинной команды IA-32|машинной команды]]:

| 32 бита | 16 бит | Старший байт | Младший байт |
| --- | --- | --- | --- |
| EAX | AX | AH | AL |
| EBX | BX | BH | BL |
| ECX | CX | CH | CL |
| EDX | DX | DH | DL |
| EBP | BP | — | — |
| ESI | SI | — | — |
| EDI | DI | — | — |
| ESP | SP | — | — |

16-битные имена (AX, BX, ...) унаследованы от 8086; байтовый доступ (AH/AL и т.д.) есть только у EAX/EBX/ECX/EDX — у EBP/ESI/EDI/ESP отдельных байтовых регистров нет

### Регистр флагов EFLAGS

32 разряда, у каждого — своя функция; часть разрядов зарезервирована. По роли флаги делятся на **статусные** (S, признак результата последней операции), **управляющий** (C, задаёт режим самого процессора) и **системные** (X, служебные, для ОС)[^eflags-sdm]:

| Бит | Флаг | Роль | Название |
| --- | --- | --- | --- |
| 0 | CF | S | Carry Flag — перенос |
| 2 | PF | S | Parity Flag — чётность |
| 4 | AF | S | Auxiliary Carry Flag — вспомогательный перенос |
| 6 | ZF | S | Zero Flag — ноль |
| 7 | SF | S | Sign Flag — знак |
| 8 | TF | X | Trap Flag — пошаговый режим |
| 9 | IF | X | Interrupt Enable Flag — разрешение прерываний |
| 10 | DF | C | Direction Flag — направление строковых операций |
| 11 | OF | S | Overflow Flag — переполнение |
| 12–13 | IOPL | X | I/O Privilege Level — уровень привилегий ввода-вывода |
| 14 | NT | X | Nested Task — вложенная задача |
| 16 | RF | X | Resume Flag — возобновление после отладочного прерывания |
| 17 | VM | X | Virtual-8086 Mode — [[Режимы работы процессоров Intel#Виртуальный режим i8086\|виртуальный режим i8086]] |
| 18 | AC | X | Alignment Check — контроль выравнивания |
| 19 | VIF | X | Virtual Interrupt Flag — виртуальное разрешение прерываний |
| 20 | VIP | X | Virtual Interrupt Pending — отложенное виртуальное прерывание |
| 21 | ID | X | ID Flag — поддержка команды `CPUID` |

Биты 1, 3, 5, 15, 22–31 зарезервированы (бит 1 всегда читается как 1, остальные — как 0)

[^eflags-sdm]: Разбивка S/C/X — по [Intel 64 and IA-32 Architectures Software Developer's Manual, Vol. 1](https://cdrdv2-public.intel.com/782149/253665-sdm-vol-1.pdf), §3.4.3 "EFLAGS Register"; совпадает с легендой на самом слайде (стр. 125)

### Сегментные регистры

| Регистр | Назначение |
| --- | --- |
| CS | Сегмент кода |
| SS | Сегмент стека |
| DS | Сегмент данных (основной) |
| ES, FS, GS | Дополнительные сегменты данных |

CS/DS/SS достались IA-32 исторически, от 8086; ES/FS/GS добавлены позже — сокращают затраты на формирование исполнительных адресов, когда данные программы одновременно лежат в разных сегментах: без лишнего регистра пришлось бы перезагружать DS каждый раз при переключении между ними

## Регистры блока с плавающей точкой

**FPU** (Floating-Point Unit), или x87, — блок операций с плавающей точкой. У 8086–80386 это был отдельный [[Арифметико-логическое устройство#^intel287|сопроцессор]], начиная с Intel486DX он встроен в кристалл процессора

> [!note] **ST0–ST7** — восемь физических 80-разрядных регистров R0–R7, логически организованных в циклический стек
> Вершина стека — не фиксированный физический регистр, а тот, на который указывает поле **Top** регистра состояния: $\mathrm{ST}(i) = R((\mathrm{Top}+i)\bmod 8)$. Например, при $\mathrm{Top}=011_2=3$ физический R3 адресуется как ST(0), R4 — как ST(1), R5 — как ST(2), и так далее по кругу

### Регистр тегов

16 разрядов, 8 полей по 2 разряда — по одному на каждый **физический** регистр R(i), а не на его текущий номер ST(i)[^tag-word]:

| Код | Состояние | Значение |
| --- | --- | --- |
| 00 | Valid | Регистр содержит действительное число |
| 01 | Zero | Регистр содержит ноль |
| 10 | Special | NaN, бесконечность, ненормализованное или неподдерживаемое число |
| 11 | Empty | Регистр не инициализирован |

Тег **Zero** избавляет от запуска дорогой операции деления или арифметики с плавающей точкой, когда делимое заведомо ноль — результат предсказуем без вычислений

Тег **Special** возникает, например, при сложении двух чисел с сильно различающимися порядками (условно миллиард и одна миллиардная): выравнивание порядков сдвигом мантиссы меньшего числа может увести всю мантиссу за пределы разрядной сетки — это не ошибка, а особый случай (потеря значимости), обрабатываемый программно или аппаратно в зависимости от требуемой точности

[^tag-word]: [Intel 64 and IA-32 Architectures Software Developer's Manual, Vol. 1](https://cdrdv2-public.intel.com/782149/253665-sdm-vol-1.pdf), §8.1.7 "x87 FPU Tag Word" — слайд называет регистр (стр. 126), но не раскрывает кодировку; лектор в записи даёт только смысл состояний Zero и Special (ниже), формальную привязку "1 тег на физический регистр, не на ST(i)" уточняет [[Формат машинной команды IA-32|SDM]]

### Регистр состояния

Слайд называет его **FPSR** (Floating-Point Status Register); в терминологии Intel SDM это **x87 FPU Status Word** (SW) — обозначение FPSR в самой архитектуре x86 не используется, оно относится к регистру состояния операций с плавающей точкой в [[CISC и RISC|ARM]][^fpsr-name]:

| Биты | Поле | Значение |
| --- | --- | --- |
| 0 | IE | Invalid Operation — недопустимая операция |
| 1 | DE | Denormalized Operand — ненормализованный операнд |
| 2 | ZE | Zero Divide — деление на ноль |
| 3 | OE | Overflow — переполнение |
| 4 | UE | Underflow — потеря значимости |
| 5 | PE | Precision — неточный результат |
| 6 | SF | Stack Fault — ошибка стека FPU |
| 7 | ES | Error Summary Status — суммарный признак ошибки |
| 8–10 | C0–C2 | Коды условий |
| 11–13 | TOP | Номер физического регистра — текущей вершины стека |
| 14 | C3 | Код условия |
| 15 | B | Busy — FPU занят |

[^fpsr-name]: [FSTSW/FNSTSW — Store x87 FPU Status Word](https://xem.github.io/minix86/manual/intel-x86-and-64-manual-vol1/o_7281d5ea06a5b67a-194.html), зеркало Intel SDM Vol. 1, Figure 8-4 — точная раскладка битов статусного слова

### Регистр управления

Слайд называет его **FPCR** (Floating-Point Control Register), в SDM — **x87 FPU Control Word** (CW): маска разрешения прерываний по особым случаям, метод округления и точность представления[^fpcr-sdm]:

| Биты | Поле | Значение |
| --- | --- | --- |
| 0 | IM | Invalid Operation Mask |
| 1 | DM | Denormal Operand Mask |
| 2 | ZM | Zero Divide Mask |
| 3 | OM | Overflow Mask |
| 4 | UM | Underflow Mask |
| 5 | PM | Precision Mask |
| 8–9 | PC | Precision Control |
| 10–11 | RC | Rounding Control |
| 12 | IC | Infinity Control — только для совместимости с сопроцессором [[Арифметико-логическое устройство#^intel287\|Intel 287]], для более новых FPU не значим |

**RC** (Rounding Control) — метод округления:

| RC | Метод округления |
| --- | --- |
| 00 | К ближайшему числу |
| 01 | К $-\infty$ |
| 10 | К $+\infty$ |
| 11 | К нулю |

**PC** — точность представления:

| PC | Точность |
| --- | --- |
| 00 | Одинарная (32 бита) |
| 01 | Не используется |
| 10 | Двойная (64 бита) |
| 11 | Расширенная (80 бит) |

[^fpcr-sdm]: [Intel 64 and IA-32 Architectures Software Developer's Manual, Vol. 1](https://cdrdv2-public.intel.com/782149/253665-sdm-vol-1.pdf), §8.1.5 "x87 FPU Control Word" — совпадает с содержимым слайда (стр. 129), разрядность форматов PC добавлена по SDM

## Регистры MMX и SSE

Слайды не приводят число и разрядность регистров этих расширений — только упоминание в составе исполнительных блоков [[Intel P6 и Motorola MPC604|Intel P6]]. История появления обеих технологий — в [[Арифметико-логическое устройство#Как граница смещалась у Intel|заметке об АЛУ]]

| Технология | Регистры | Разрядность | Особенность |
| --- | --- | --- | --- |
| [[Арифметико-логическое устройство\|MMX]] | MM0–MM7 (8 штук) | 64 бита | Физически совмещены (aliased) с [[Регистры процессора#Регистры блока с плавающей точкой\|регистрами R0–R7 стека FPU]] — стек FPU и MMX нельзя использовать одновременно[^mmx-sse-sdm] |
| [[Арифметико-логическое устройство\|SSE]] | XMM0–XMM7 (8 штук); XMM0–XMM15 (16 штук в 64-битном режиме) | 128 бит | Отдельный регистровый файл, не совмещён ни с x87, ни с MMX[^mmx-sse-sdm] |

[^mmx-sse-sdm]: [Intel 64 and IA-32 Architectures Software Developer's Manual, Vol. 1](https://cdrdv2-public.intel.com/782149/253665-sdm-vol-1.pdf), глава 9 "Programming with Intel MMX Technology" §9.2 "MMX Registers" и глава 10 "Programming with the Streaming SIMD Extensions (SSE)" §10.2 "SSE Programming Environment" — совмещение регистров MMX со стеком x87 сделано намеренно, чтобы операционным системам не требовалось сохранять дополнительный контекст при переключении задач
