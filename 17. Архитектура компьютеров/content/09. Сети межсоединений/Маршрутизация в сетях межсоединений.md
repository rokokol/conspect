# Маршрутизация в сетях межсоединений

> [!warning] Омоним с маршрутизацией пакетов между сетями
> [[Классификация протоколов маршрутизации|Маршрутизация IP-пакетов]] выбирает путь между сетями по таблицам маршрутизации ([[Протокол RIP|RIP]]/[[Протокол OSPF|OSPF]]/[[Протокол EIGRP|EIGRP]]). Здесь — маршрутизация сообщений между процессорами **внутри одной** вычислительной системы, по портам коммутаторов [[Сети межсоединений|сети межсоединений]]: общий термин, разные предметы

## Алгоритмы выбора маршрута

> [!note] **Маршрутизация от источника** (source routing) — источник заранее прописывает весь путь целиком, как список номеров портов, которые нужно использовать на каждом коммутаторе до пункта назначения

> [!note] **Распределённая маршрутизация** — каждый коммутатор сам решает, в какой выходной порт отправить пакет
> - **Статическая** — правило выбора порта одинаково для всех пакетов (например, "первый свободный порт")
> - **Адаптивная** — коммутатор учитывает текущее состояние трафика в сети

## Время передачи данных

> [!note] Составляющие времени передачи
> - $t_н$ — время начальной подготовки: подготовка сообщения к передаче и поиск маршрута в сети
> - $t_с$ — время передачи служебных данных между двумя соседними процессорами (то есть процессорами, между которыми есть физический канал)
> - $t_к$ — время передачи одного слова данных по одному каналу; зависит от полосы пропускания канала

## Способы коммуникации

Сообщение можно дробить на пути между процессорами, разделёнными $l$ каналами, по-разному

> [!summary] Метод передачи сообщений — весь путь ждёт полного приёма на каждом шаге
> $$\boxed{t_{пд}=t_н+(mt_к+t_с)l}$$
> Отправитель готовит всё сообщение размером $m$ байт целиком, определяет получателя и запускает пересылку. Каждый промежуточный процессор сначала полностью принимает сообщение и только затем передаёт его дальше — поэтому стоимость одного шага $(mt_к+t_с)$ повторяется $l$ раз, по числу шагов маршрута

> [!summary] Метод передачи пакетов — пересылка следующему узлу начинается сразу после приёма пакета
> $$\boxed{t_{пд}=t_н+mt_к+t_сl}$$
> Принимающий процессор пересылает данные дальше по маршруту сразу по приёму очередного пакета, не дожидаясь приёма всего сообщения. Передача данных $m t_к$ платится один раз, а не на каждом шаге: пока один участок канала передаёт хвост сообщения, соседний уже передаёт его начало дальше. Накапливается только служебная часть $t_с$ — по разу на каждый из $l$ переходов[^formula-check]

[^formula-check]: Обе формулы сверены с рендером слайдов (стр. 222–223), а не только с текстовым слоем: скобки вокруг $(mt_к+t_с)$ в формуле сообщений и их отсутствие в формуле пакетов на слайде не потеряны при извлечении текста

> [!note] Сравнение методов
> Метод передачи пакетов
> - быстрее — за счёт конвейеризации передачи между шагами маршрута
> - требует меньше памяти для буферизации пересылаемых данных
> - допускает одновременное использование разных каналов для разных пакетов одного сообщения
>
> Ценой служит более сложное аппаратное и программное обеспечение сети и возможный рост накладных расходов на подготовку и передачу служебных данных
