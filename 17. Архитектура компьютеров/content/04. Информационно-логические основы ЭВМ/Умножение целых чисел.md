# Умножение целых чисел

Умножение целых чисел в [[Электронно-вычислительная машина|ЭВМ]] реализуется через сложение и [[Арифметико-логическое устройство#Логический и арифметический сдвиг|сдвиг]] — операции, которые [[Арифметико-логическое устройство#Минимальный набор операций|АЛУ выполняет аппаратно]]

## От умножения столбиком к сдвигам

В десятичной системе многоразрядные числа умножают столбиком: множимое умножают на младший разряд множителя, затем на следующий и записывают это частичное произведение под предыдущим, выровняв по позиции разряда множителя, и так до последнего разряда. В конце частичные произведения складывают

В двоичной системе разряд множителя — только 0 или 1, и умножать на него не нужно:

- разряд равен 1 — частичное произведение есть само множимое, выровненное по позиции этого разряда
- разряд равен 0 — частичное произведение равно нулю, к сумме ничего не добавляется

```
        1100    A = 12, множимое
      × 1001    B = 9,  множитель
      ------
        1100    b0 = 1
       0000     b1 = 0
      0000      b2 = 0
     1100       b3 = 1
     -------
     1101100    = 108
```

Последовательный перебор разрядов множителя — это сдвиг: регистр множителя сдвигают и каждый раз анализируют выдвинутый разряд. Выравнивание частичного произведения по позиции — тоже сдвиг. Настоящего умножения внутри нет: только сдвиг, условный выбор "множимое или ноль" и сложение

Ничто не мешает и столбиком начинать со старших разрядов множителя — процедура та же, только частичные произведения выравниваются в другую сторону. Отсюда четыре варианта: начать с младших или со старших разрядов множителя и сдвигать либо множимое, либо сумму частичных произведений

## Четыре алгоритма

Множитель $B=b_{n-1}\ldots b_1b_0$, множимое $A$, произведение $П$[^formulas]:

| Алгоритм | Разряды множителя | Что сдвигается | Формула |
| --- | --- | --- | --- |
| 1 | С младших | Множимое влево | $П=Ab_02^0+Ab_12^1+\ldots+Ab_{n-1}2^{n-1}$ |
| 2 | С младших | Сумма частичных произведений вправо | $П=(\ldots((0+A2^nb_0)2^{-1}+A2^nb_1)2^{-1}+\ldots+A2^nb_{n-1})2^{-1}$ |
| 3 | Со старших | Множимое вправо | $П=2^n\{A2^{-1}b_{n-1}+A2^{-2}b_{n-2}+\ldots+A2^{-n+1}b_1+A2^{-n}b_0\}$ |
| 4 | Со старших | Сумма частичных произведений влево | $П=(\ldots((0+Ab_{n-1})2^1+Ab_{n-2})2^1+\ldots+Ab_1)2^1+Ab_0$ |

[^formulas]: На слайде (стр. 114) формулы записаны в разной нумерации разрядов. В формулах 1, 3, 4 множитель — $b_{n-1}\ldots b_0$, а в формуле 2 — $(\ldots((0+Ab_n)2^{-1}+Ab_{n-1})2^{-1}+\ldots+Ab_1)2^{-1}$, то есть разряды $b_n\ldots b_1$, как у дробного множителя $0.b_1b_2\ldots b_n$: для такой дроби формула точна, а для целого $B$ даёт $A\cdot B\cdot2^{-n}$. В таблице она приведена к общей целой нумерации, множитель $2^n$ означает, что множимое прибавляется к старшей половине регистра. Кроме того, в формуле 3 на слайде второе слагаемое — $A2^{-2}b_{n-1}$, верно $A2^{-2}b_{n-2}$. Целочисленные формы сдвига вправо и влево, $p^{(j+1)}=(p^{(j)}+x_ja2^k)2^{-1}$ и $p^{(j+1)}=2p^{(j)}+x_{k-j-1}a$, — B. Parhami, [Computer Arithmetic, слайды к гл. 9, "Examples of Basic Multiplication"](https://web.ece.ucsb.edu/~parhami/pres_folder/f31-book-arith-pres-pt3.pdf)

Число шагов любого алгоритма равно разрядности множителя $n$ — по одному анализу разряда и одному сдвигу на шаг. Все четыре дают один результат; различаются они тем, как операнды исходно расположены в разрядной сетке и куда сдвигаются

> [!warning] Операнды нужно расположить так, чтобы сдвиг не терял значащие разряды
> Регистр — физический объект фиксированной длины, и разряд, выдвинутый за его границу, теряется. На бумаге можно каждый раз приписать нолик или выделить ещё разряд, то есть искусственно расширить разрядную сетку, а в процессоре потеря хотя бы одной единицы делает результат неверным
>
> Поэтому при сдвиге суммы вправо (алгоритм 2) операнды размещают в **старших** разрядах регистра: сдвиги вправо освобождают младшие разряды, и их хватает под результат. Размести их в младших — при сдвиге вправо значащие разряды выпадут

## Пример по алгоритму 2

$A=12_{10}=1100_2$, $B=9_{10}=1001_2$, регистр 8 разрядов. На каждом шаге анализируется очередной разряд множителя (выделен), при $b_i=1$ множимое прибавляется к старшим четырём разрядам суммы, затем сумма сдвигается на разряд вправо

| Шаг | 7 | 6 | 5 | 4 | 3 | 2 | 1 | 0 | Действие |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 0 | 1 | 0 | 0 | **1** |  |  |  |  | $b_0=1$ |
|  | 1 | 1 | 0 | 0 |  |  |  |  | $0+Ab_0=П_1$ |
|  | 0 | 1 | 1 | 0 | 0 |  |  |  | $П_1\cdot2^{-1}$ |
| 1 | 1 | 0 | **0** | 1 |  |  |  |  | $b_1=0$ |
|  | 0 | 0 | 0 | 0 |  |  |  |  | $Ab_1$ |
|  | 0 | 1 | 1 | 0 | 0 |  |  |  | $П_1\cdot2^{-1}+Ab_1=П_2$ |
|  | 0 | 0 | 1 | 1 | 0 | 0 |  |  | $П_2\cdot2^{-1}$ |
| 2 | 1 | **0** | 0 | 1 |  |  |  |  | $b_2=0$ |
|  | 0 | 0 | 0 | 0 |  |  |  |  | $Ab_2$ |
|  | 0 | 0 | 1 | 1 | 0 | 0 |  |  | $П_2\cdot2^{-1}+Ab_2=П_3$ |
|  | 0 | 0 | 0 | 1 | 1 | 0 | 0 |  | $П_3\cdot2^{-1}$ |
| 3 | **1** | 0 | 0 | 1 |  |  |  |  | $b_3=1$ |
|  | 1 | 1 | 0 | 0 |  |  |  |  | $Ab_3$ |
|  | 1 | 1 | 0 | 1 | 1 | 0 | 0 |  | $П_3\cdot2^{-1}+Ab_3=П_4$ |
|  | **0** | **1** | **1** | **0** | **1** | **1** | **0** | **0** | $П_4\cdot2^{-1}$ |

$$
\boxed{C=01101100_2=108_{10}}
$$

Нулевой разряд множителя внутри процессора не требует никакого сложения: частичное произведение просто сдвигается ещё на разряд вправо. Сложение идёт только по старшей половине регистра, младшие разряды суммы уже окончательны; перенос из старшего разряда при сложении нужно сохранить в дополнительном триггере, он вдвигается в регистр при следующем сдвиге (в этом примере переносов нет)[^slide-bn]

[^slide-bn]: На слайде (стр. 115) анализируемый разряд на каждом шаге обозначен одинаково — $b_n$, — а по мере шагов обведён кружком всё левее в записи $1001$. В таблице выше он пронумерован по позиции во множителе

### Те же числа по алгоритмам 1, 3 и 4

Алгоритм 1 — множимое сдвигается влево, сумма накапливается на месте:

| Шаг | $b_i$ | Множимое $A\cdot2^i$ | Сумма $П$ |
| --- | --- | --- | --- |
| 0 | 1 | 00001100 | 00001100 |
| 1 | 0 | 00011000 | 00001100 |
| 2 | 0 | 00110000 | 00001100 |
| 3 | 1 | 01100000 | 01101100 |

Алгоритм 3 — множимое исходно стоит в старшей половине, $A\cdot2^n=11000000$, и перед каждым шагом сдвигается вправо:

| Шаг | $b_i$ | Множимое $A\cdot2^i$ | Сумма $П$ |
| --- | --- | --- | --- |
| 3 | 1 | 01100000 | 01100000 |
| 2 | 0 | 00110000 | 01100000 |
| 1 | 0 | 00011000 | 01100000 |
| 0 | 1 | 00001100 | 01101100 |

Алгоритм 4 — множимое на месте в младших разрядах, сумма сдвигается влево после каждого шага, кроме последнего:

| Шаг | $b_i$ | $П+Ab_i$ | После сдвига влево |
| --- | --- | --- | --- |
| 3 | 1 | 00001100 | 00011000 |
| 2 | 0 | 00011000 | 00110000 |
| 1 | 0 | 00110000 | 01100000 |
| 0 | 1 | 01101100 | — |

Во всех трёх $П=01101100_2=108_{10}$

## Знак произведения

Алгоритмы выше вычисляют значащую часть — произведение модулей. Знак формируется отдельно одним [[Логические вентили|вентилем]] исключающего ИЛИ:

$$
\boxed{\text{Зн.}П=\text{Зн.}A\oplus\text{Зн.}B}
$$

Например, для $A=-12$, $B=9$ в [[Прямой, обратный и дополнительный код|прямом коде]]: $\text{Зн.}П=1\oplus0=1$, модуль — $01101100$ из примера выше, $П=-108$
